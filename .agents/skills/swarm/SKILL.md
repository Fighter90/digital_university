# Запуск роя

Ты запускаешь рой агентов этого репозитория (digital_university). Механика — в
`scripts/swarm/` (оркестратор + линейный клерк + гейты, архитектура в
`scripts/swarm/README.md`). Твоя работа: preflight, запуск, сопровождение, отчёт.

## 1. Preflight (всё должно пройти)

```bash
git status --porcelain                 # пусто
git rev-parse --abbrev-ref HEAD        # main
opencode --version                     # воркер-CLI доступен
```

Если дерево грязное — сначала коммит или stash (рой сам прерывается на грязном
дереве). Если пользователь сказал «N задач» — это `--max N` (по умолчанию 1).

## 2. Запуск

```bash
node scripts/swarm/orchestrator.mjs --max <N> 2>&1 | tee /tmp/swarm-run-$(date +%H%M).log
```

Флаги: `--max N` (задач за прогон), `--rounds N` (раунды dev/ревью, 3),
`--dry-run` (только выбрать и показать), `--no-pr`, `--merge`, `--deploy`,
`--pin DIG-XX`. Запускай в фоне и транслируй лог пользователю.

## 3. Сопровождение (рой разговаривает через лог)

Вехи: `picked DIG-XX` → `round n: develop` → `gates green` → `verdict: ACCEPT` →
`security: PASS` → `story:` → `PR: …` → `=== DONE: DIG-XX ===`.
Хвосты агентов: `.task-board/log/cycle-*.log`.

## 4. При сбое — фикс-форвард

1. Прочитай последний `.task-board/log/*.log` и комментарии задачи в Linear.
2. Классифицируй: **баг оркестратора** → почини красным-первым (дополни
   `tests/swarm-orchestrator.test.mjs`), закоммить, запусти заново.
   **Проблема задачи** (двусмысленно, слишком крупно) → сообщи пользователю,
   задачу не закрывай — Закрыть может только человек.
3. Известные мины: push без upstream молча но-опит — пушь ветку явно;
   не запускай рой не из `main`; `-B` стирает работу ветки — рефлог-спасение
   встроено, но не рассчитывай на него.

## 5. Отчёт

В конце — сводка на языке пользователя: какие задачи взяты, что отправлено
(PR, гейты, вердикты), что осталось человеку. Linear — источник истины.
После завершения не запускай новый прогон без явной просьбы.
