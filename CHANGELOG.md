# Changelog

Все значимые изменения проекта документируются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## Unreleased

### Изменения

- **Добавлена изоляция данных (DIG-12)**: страницы и API читают данные
  только через слой `src/server/data/*`, где фильтр по владельцу вшит в
  контекст сессии; чужая заявка и несуществующая отвечают одинаковым 404,
  попытки чужого доступа пишутся в журнал аудита, сотрудник видит студентов
  только своего факультета, заявки в URL адресуются не-последовательными
  номерами (`SR-2026-A1B2C`). Прямой импорт Prisma вне `src/server/`
  запрещён правилом ESLint (тесты закрепляют). Появились экраны «Мои заявки»
  и детальная заявка с историей, API заявки, единая страница 404 и
  вымышленные демо-аккаунты жюри (Анна, Илья, Мария).
  - Раунд 2 (по замечаниям ревью): починены упавшие тест-гейты —
    `turbopack.root` закреплён за каталогом проекта (посторонний lockfile в
    домашнем каталоге ломал определение корня workspace и рендерил сборку
    с ENOENT на edge-чанках), e2e переведены на production-сервер
    (`next build && next start`): в dev-режиме Turbopack отдаёт not-found
    страницу со статусом 200 (гонка dev-сервера), а продовый контракт —
    честный 404; 16/16 e2e зелёные на детерминированном сервере.
  - Раунд 3 (по замечаниям ревью): снова упал гейт build — ENOENT
    `.next/server/pages-manifest.json` на «Collecting page data». Устранено
    архитектурно: `next dev` пишет в отдельный `.next-dev` (`distDir`
    развязан по NODE_ENV в `next.config.ts`), поэтому dev и build физически
    не перезаписывают манифесты друг друга; `npm run build` теперь
    герметичный — чистит `.next` перед сборкой, сохраняя сгенерированные
    route-types (на них ссылается `next-env.d.ts`, удаление роняет
    typecheck ошибкой TS6053). Инварианты закреплены тестами
    `tests/build-hermetic.test.ts`.
- **Добавлен вход по логину и паролю** (DIG-11): серверные сессии на
  httpOnly-куках, хэширование паролей, защита от перебора по IP, route-guard
  через middleware и форма логина; покрыто unit-тестами и e2e-сценарием
  входа.
- **Инфраструктура** — рой ИИ-агентов OpenCode: оркестратор (детерминированный
  автомат), Linear-клерк на GraphQL, адаптивные тест-гейты, роли
  executor/reviewer/security/documenter, команды `/swarm`, `/next-task`,
  `/review`, `/security-gate`, юнит-тесты маркерных контрактов.

### Заметки

- Специально не делали: восстановление пароля по email и 2FA — это отдельная
  задача, в этот раз ограничились базовым входом и сессиями.
- Специально не делали (DIG-12): ICS-фид, PDF-справка и чат AI — поверхностей
  ещё нет; их задачи обязаны идти через слой `src/server/data/*` и единый
  404-хелпер (проверяется security-агентом в каждом PR).
- Специально не делали: параллельные воркеры в worktree (из DIG-5) — циклы
  последовательные, параллелизм отдельной задачей после стабилизации цикла.
