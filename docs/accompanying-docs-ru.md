## 2. CHANGELOG.md — как читать и вести

- Формат: обратная хронология; запись на каждую задачу после merge.
- Каждый блок: дата, номер задачи/PR, «Добавлено / Изменено / Исправлено», короткая пользовательская формулировка (не коммит-сообщения).
- Ведёт **documenter** роя автоматически (`CHLOG_FIXED` → блок); правки руками — допустимы, стиль сохранять.
- Пример записи:

```markdown
## 2026-11-17
- **Добавлено** экран «Справка» (/guide): гайд «Как пользоваться кабинетом»
  с оглавлением, поиском и инструкциями по всем разделам (DIG-70).
- **Исправлено** двойной сайдбар в Shell (артефакт слияния DIG-48).
```

## 3. docs/ai-log/ — журнал ИИ-роя

- Один файл на задачу (`docs/ai-log/dig-xx-*.md`): что делал executor, раунды ревью (пункты RETURN), вердикт security, финальный STORY-блок.
- Назначение: прозрачность ИИ-разработки для жюри; разбор «как принимались решения».
- Ведёт **documenter**; формат свободный, но три блока обязательны: «Что сделано», «Замечания ревью и как закрыты», «STORY» (1–3 предложения от лица пользователя).

## 4. OpenSpec (openspec/) — спеки

- `openspec/specs/<capability>/spec.md` — **текущая правда** системы после archive: требования с WHEN/THEN-сценариями.
- `openspec/changes/<change-id>/` — активные/завершённые change-папки: `proposal.md` (зачем/что/non-goals), `tasks.md` (чек-лист), `specs/**/spec.md` (дельта ADDED/MODIFIED/REMOVED).
- Жизненный цикл: создать change → реализовать → гейты/ревью/security → merge → `openspec archive <change>`.
- Валидация: `openspec validate` (обязательна перед merge).
- Список закрывшихся capability: request-machine (DIG-30/32), cabinet-shell (DIG-14/20), gradebook+insight (DIG-26/27/66), deanery-tickets (DIG-39), people (DIG-37), feedback (DIG-40), msp-catalog (DIG-68), events-screen (DIG-43), dpo-catalog (DIG-42), i18n (DIG-69), motion (DIG-71), help+guide (DIG-38/70) и др.

## 5. Linear — управление задачами

- Проект «Цифровой деканат — ЛК студента (хакатон)», команда Digital_university.
- Идентификаторы задач: DIG-6…DIG-72; каждая задача ↔ ветка `pochtasergeia/dig-XX-…` ↔ PR.
- Метка `swarm` — берётся роем; статусы: Todo (очередь) → In Progress (взято) → Done (влито и задеплоено).
- Комментарии задач — отчёты роя (что сделано, гейты, раунды ревью).
- После squash-merge ветка удаляется автоматически; SHA голов смерженных веток — `docs/BRANCHES-ARCHIVE.md`.

## 6. Глоссарий терминов

| Термин | Значение |
|---|---|
| **ЗД-2026-XXXXXX** | Номер канонической заявки студента (мастер заказов DIG-30/32) |
| **SR-2026-XXXXX** | Номер сервисной заявки (легаси-нумерация прототипа) |
| **TS-2026-XXXXX** | Номер обращения в деканат (DIG-39) |
| **Канон DIG-30** | Единый словарь статусов заявки (10 значений) и машина переходов |
| **SLA** | Контрольный срок ответа сотрудника на заявку (3 дня; просрочка подсвечивается) |
| **Owner-scope** | Принцип: запрос данных всегда фильтруется по владельцу сессии (IDOR-запрет) |
| **Единый 404** | Несуществующий и чужой объект отвечают одинаково (нет оракула существования) |
| **Fail-closed** | Отсутствие данных/секрета → безопасный отказ (например, роль = студент) |
| **Порт DataDb** | Интерфейс доступа к данным; страницы не ходят мимо него |
| **RAG** | Retrieval-Augmented Generation: ответ LLM строится по найденным фрагментам справки |
| **FAB** | Floating Action Button — плавающая кнопка AI-ассистента |
| **Гейты** | lint/typecheck/build/test — обязательный фильтр перед ревью |
| **Сальвадж** | Восстановление осиротевшей ветки: wip-коммиты → merge main → union-резолв → гейты |

## 7. Ограничения прототипа (non-goals)

- Реальные персональные данные, интеграции с вузом, оплата — запрещены концептом.
- Доменные данные — в памяти процесса: рестарт сбрасывает к сиду; Prisma-слой домена — будущая работа (DIG-10/50).
- E-mail/Telegram/push каналы уведомлений — имитация в прототипе.
- Голосовые функции зависят от поддержки браузера.
- AI-ассистент ограничен справкой кабинета (RAG) и демо-фолбэком.

## 8. Как поддерживать документацию дальше

1. После merge каждой фичи: дополнить `CHANGELOG.md` (documenter делает это автоматически) и, если менялся UI, — `docs/user-guide-*.md`.
2. После изменения инфраструктуры/секретов: `docs/admin-guide-*.md` + `docs/wiki/RUNBOOK.md`.
3. Новые архитектурные решения: `docs/wiki/ARCHITECTURE.md` + `docs/architecture.md`.
4. Правило единого источника: подробности — в docs/, README — только витрина и ссылки.
5. Документация обновляется тем же роевым конвейером (задача DIG-59 — прецедент).
