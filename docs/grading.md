# Правила оценивания прототипа (DIG-25)

> Все данные вымышленные. Документ фиксирует правила расчётов, на которых стоят
> экраны «Успеваемость» (DIG-26), «Зачётная книжка» (DIG-27), «Сессия» (DIG-28)
> и калькулятор «что нужно на экзамене». Формулы реализованы в
> `src/lib/performance-math.ts` (чистые функции), агрегаты —
> `src/server/data/performance.ts` (скоуп по ctx, защита от IDOR).

## Шкала и единицы

- Оценка элемента контроля — **процент от максимума элемента** (0–100):
  `score / maxScore × 100`. В сиде прототипа `maxScore = 100`, но формулы
  не зависят от этого (шкала экзамена может быть, например, 60-балльной —
  `needForTarget` возвращает балл в шкале элемента и процент отдельно).
- Итог дисциплины и «накопленные» величины — тоже проценты 0–100.
- GPA — проценты, взвешенные кредитами дисциплин.

## Накопленная оценка по дисциплине

План контроля дисциплины — все элементы семестра с весами (`weight`, доля
итога) и максимумами. Веса **нормируются на сумму весов плана** (если план
отсутствует — на сумму весов самих оценок, robustness для старых сидов).
При пересдачах элемента побеждает последняя оценка по дате.

- **Накопленная** = Σ(нормированный вес × доля максимума) по уже
  выставленным элементам × 100. Оценок нет → `null` (не определена).
- **Минимально гарантированная** = накопленная (все несданные элементы
  считаются нулями). Оценок нет → 0.
- **Максимально возможная** = накопленная + нормированный вес несданных
  элементов × 100 (все несданные — на максимум).
- Элементы с `maxScore ≤ 0` не могут быть оценены и **исключаются из
  плана** — они не уменьшают «максимально возможную».

## Правило округления

**Итог дисциплины = арифметическое округление накопленного процента до
целого** (половина округляется вверх, `Math.round`): 86.5 → 87, 69.4 → 69.
Промежуточные накопленные величины хранятся с точностью до 0.01 и наружу
идут без округления до целого — округляет только итог.

**Блокирующие элементы** («сдашь все лабы — допущен к экзамену») в
прототипе **отсутствуют**: все элементы плана накапливают вес. Если
появятся, правило допуска фиксируется здесь; расчётные функции менять не
потребуется (допуск — вопрос экрана «Сессия», а не формулы).

## `needForTarget(дисциплина, target)`

Какой балл нужен на экзамене, чтобы итог стал ≥ `target` (проценты):

```
round(acc + wNorm·x/maxScore·100) ≥ target
⇔ x ≥ (target − 0.5 − acc) · maxScore / (100·wNorm)   // монотонность округления
```

- `acc` — накопленная (сданные элементы), `wNorm` — нормированный вес
  экзамена, `x` — искомый балл (целое, 0…maxScore).
- **Остальные незакрытые элементы считаются нулями** — ответ
  «гарантированный», а не оптимистичный.
- Статусы результата: `OK` (нужен балл `neededScore`), `ALREADY_SECURED`
  (цель уже гарантирована — даже ноль на экзамене), `EXAM_ALREADY_GRADED`
  (экзамен сдан, цель выше — изменить ничего нельзя), `UNREACHABLE`
  (даже 100 на экзамене не хватает; `bestPossible` — максимум достижимого),
  `NO_EXAM_ELEMENT` (в плане нет экзамена).
- `target` вне [0; 100] обрабатывается математикой (≤ 0 → secured,
  > 100 → unreachable); NaN/∞ — `null` без записи в аудит.

## Семестры и GPA

- Границы семестров — вымышленный учебный календарь прототипа (как в
  `semesterBounds`, `src/lib/schedule-time.ts`): осень 1.09–25.01,
  весна 9.02–30.06, июль/август — будущая осень, январь — хвост осени.
  Часовой пояс — Europe/Moscow.
- Дисциплина относится к семестру **по дате последней оценки**.
- **GPA** — средневзвешенное кредитами: `Σ(значение × кредиты)/Σ(кредиты)`.
  Значение дисциплины: **итог** (округлённый) для завершённой дисциплины,
  **накопленная** — для идущего семестра (предварительный результат).
  Дисциплина без оценок в GPA не участвует.
- **Дельта** = GPA текущего семестра − GPA предыдущего; нет оценок в
  предыдущем семестре → `null`.
- Кредиты дисциплин — из справочника дисциплин группы; дисциплина без
  записи в справочнике считается «1 кредит» (равный вес, robustness).

## Кредиты

- **Набрано** = Σ кредитов завершённых дисциплин с итогом ≥ **60**
  (порог «удовлетворительно» прототипа, `CREDIT_PASS_PERCENT`).
- **Требуется** = 240 кредитов на программу 4 лет (`PROGRAM_TOTAL_CREDITS`).

## Рейтинг в группе и перцентиль

- Рейтинг — по **общему GPA** (за всё время) среди студентов группы,
  у которых есть хотя бы одна оценка. Студенты без оценок не ранжируются.
- **Равные GPA — одно место** (competition ranking): место =
  1 + число студентов со строго большим GPA.
- «Топ-X%» = `ceil(место / размер группы × 100)`, не меньше 1
  (пример: место 6 из 22 → «Вы входите в 28% лучших в группе»).
- Формулировка для человека: **«Вы входите в N% лучших в группе»**
  (вместо «перцентиль 32» без объяснения). Группа из одного студента —
  «Вы — единственный студент в группе».
- Оценки сокурсников читаются только как вход агрегата рейтинга; наружу
  уходят место/перцентиль владельца контекста, но не чужие строки.

## Долги (пересдачи)

Источник — сессии `RETAKE` группы студента. Статус долга:

- `CLOSED` — итог/накопленная дисциплины ≥ 60 (долг закрыт);
- `ASSIGNED` — дата пересдачи сегодня или позже;
- `OVERDUE` — дата прошла, долг не закрыт.

Порядок в ответе: активные (`OVERDUE`, `ASSIGNED`) по дате, затем
закрытые. Рядом — календарных дней до пересдачи (отрицательное — прошла).

## Доступ (IDOR)

Каждая функция слоя данных принимает `ctx` из живой сессии
(`requireDataCtx`) и скоупит выборки: персональные — по `ctx.studentId`,
справочники и сессии группы — по `ctx.groupName`. Дисциплина в
`needForTarget` обязана принадлежать группе из ctx: чужая и
несуществующая дают **единообразный null** (HTTP 404 снаружи), причина —
только в AuditLog (`OWNERSHIP_DENIED` / `ROLE_MISMATCH`).
