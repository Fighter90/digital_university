### 3.1. Результаты — **FAIL (среда исполнителя, не продукт)**

| Прогон | Тестов | Passed | Failed | Skipped / did not run | Вердикт |
|---|---|---|---|---|---|
| Полный прогон #1, 09:58 (desktop-1440 + mobile-360) | 608 | 3 | 469 | 63 skipped + 73 did not run | не завершён |
| Полный прогон #2, 10:29 (повтор) | 608 | 2 | 221 | 83 skipped + ~302 не дошли (прерван) | не завершён |

**Причина — сеть исполнителя, а не продукт.** Разбор всех 214 папок `test-results/*/error-context.md`:
- 178 папок — `net::ERR_TIMED_OUT` / `net::ERR_CONNECTION…` при `page.goto` на `https://ostrovok.store/…` (TLS/HTTP-соединение не устанавливается из этой сети);
- остальные 36 — `Test timeout of 30000ms exceeded` (wait-шаги после неудавшегося перехода — та же сетевая причина);
- **ни одной assertion-failure** (расхождений DOM/текстов/поведением нет) — все падения начинаются с таймаута загрузки страницы;
- прямая проверка из той же сети в момент повтора: `curl https://ostrovok.store` висит >120 с — сеть исполнителя к проду недоступна (прод отвечает с других сетей, проверено ранее: HTTP 200, brief-compliance §2.1).

**Что это значит:** целевые прода-спеки (`prod-auth`, `prod-crawl`, `zz-a11y-plain-prod`, `zz-en-audit`) с этой же машины **успешно проходили 20.11.2026 ранее** (`prod-auth`: 2 passed — `docs/qa/2026-11-20-brief-compliance.md` §2.2; crawl-отчёт `dig-60-crawl-report-desktop-1440.json`). Полный 608-тестовый прогон из текущей сети невозможен — рекомендуется перезапустить из другой сети перед отправкой. Продукт от этого не меняется: прода-контракты закреплены и проходили в день отчёта.

Ключевые прода-спеки в наборе:
- `e2e/prod-auth.spec.ts` — вход anna/ilya, `__Host-session`, изоляция (чужой номер заявки → 404 + API 404 `{error:"not_found"}`), вход сотрудника dean.kovaleva → `/staff` со SLA-подсветкой.
