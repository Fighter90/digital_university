- **Агенты:** executor → gates → reviewer → security → documenter (GLM-5.3, opencode run)
- **Раундов dev↔review:** 3 (раунд 1: гейты упали на build; раунд 2: исправлено;

- **Гейты:** lint/typecheck/test/build — green; e2e 16/16 — green (production-сервер, см. раунд 2)
- **Ревью:** раунд 2 вернул задачу по упавшим тест-гейтам — исправлено;
  раунд 3 вернул по повторному ENOENT build — исправлено в этом раунде
- **Security:** — (слой для IDOR-проверки готов: `src/server/data/*` + AuditLog)
- **PR:** ветка `pochtasergeia/dig-12-izolyaciya-dannikh-student-vidit-tolko`
- **Итог исполнителя:** архитектурный слой изоляции (DataCtx + порт + in-memory
  адаптер + аудит + единый 404), ESLint-запрет Prisma вне `src/server/`,
  экраны заявок и API, 34 unit-теста изоляции + 7 тестов ESLint-правила +
  e2e IDOR (Анна/Илья) — 125 unit + 16 e2e зелёные.
- **Раунд 2 — как чинили гейты:** (1) посторонний `package-lock.json` в
  домашнем каталоге сбивал определение корня workspace — Next.js строил
  чанки с префиксом `Projects_digital_university_…`, и сборка падала с
  ENOENT на edge-чанках; фикс — `turbopack.root = __dirname` в
  `next.config.ts`, предупреждение исчезло, имена чанков стабильны.
  (2) e2e IDOR-тест ждал HTTP 404 от dev-сервера, а `next dev` (Turbopack)
  отдаёт not-found страницу со статусом 200 — гонка dev-режима (между
  запусками то 404, то 200); продовый `next start` отвечает честным 404.
  Фикс — webServer e2e теперь `pnpm build && pnpm start`: suite проверяет
  продовый контракт, 16/16 зелёные детерминированно.
- **Раунд 3 — как чинили повторный ENOENT build:** гейт упал с
  ENOENT `.next/server/pages-manifest.json` на «Collecting page data».
  Причина — общий distDir: `next dev --turbopack` пишет манифесты в тот же
  `.next` и может стереть их под живой production-сборкой (воспроизводится
  как гонка «dev рядом с build», а не чистой последовательностью).
  Фикс двухуровневый: (1) `distDir` развязан через `resolveDistDir(NODE_ENV)`
  в `next.config.ts` — dev живёт в `.next-dev`, build в `.next`; (2)
  `npm run build` стартует с чистого `.next` (сохраняя `types/`: на
  route-types ссылается `next-env.d.ts`, их удаление даёт TS6053 в
  следующем typecheck — проверено на отдельном кейсе). Инварианты
  закреплены `tests/build-hermetic.test.ts` (red-first: 5/6 падали до
  реализации). Проверена живая последовательность dev → typecheck → build.
- **История:** Сделали так, чтобы «чужое» физически не открывалось: единственная
  дорога к данным проходит через функции, которым владелец известен из сессии, а
  не из адресной строки. Чужой номер заявки и несуществующий выглядят для
  посетителя одинаково (404), но попытка остаётся в журнале аудита — так честно и
  для жюри, и для security.
