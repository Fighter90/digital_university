## Исправленные дефекты

### D1. КРИТИЧНО (DIG-106): анонимный переключатель «Русский/English» на лендинге уводил на /login

- **Где:** `src/server/actions/locale.ts` (setLocale), вызывается LocaleSwitch
  из шапки ПУБЛИЧНОГО лендинга (DIG-90).
- **Симптом:** аноним нажимает «English» → server action owner-scoped
  (`requireDataCtx('/settings')`, паттерн DIG-69) → redirect
  `/login?next=%2Fsettings`; язык не меняется. Воспроизведено e2e (контент
  после клика — h1 «Вход в кабинет»).
- **Почему дефект:** лендинг по спеке `landing-screen` открывается без
  авторизации; локаль — cookie-предпочтение самого браузера (whitelist ru/en,
  httpOnly, lax), данные action не читает и не пишет — owner-scope здесь не
  защищает ничего, кроме… невозможности сменить язык.
- **Фикс (минимальный):** убрать `requireDataCtx` из `setLocale`; whitelist
  и запись только своей cookie сохранены (IDOR невозможен по построению).
- **Тесты (red-first):** `tests/landing-locale-anonymous.test.ts` — до фикса
  3/3 красные (guard кидал NEXT_REDIRECT), после — зелёные; e2e «клик English
  меняет контент…» зелёный, включая персистентность после перезагрузки.
- **Спека:** change-папка `openspec/changes/dig-106-107-regress-landing/`
  (delta `landing-screen`: требование «Переключатель языка на лендинге» —
  аноним RU/EN, персистентность, битое значение отбрасывается).

### D2. ТЕСТ (DIG-106): e2e `landing.spec.ts` ждал карточку «Справки с QR»

- **Где:** `e2e/landing.spec.ts` (тест «пять карточек преимуществ»).
- **Симптом:** 2/2 проекции падали — карточка называется «Справки с

- **Фикс:** ожидание приведено к текущей копирайт-строке. Прогон файла:
  11 passed / 0 failed (обе проекции).
- **Попутно отмечено:** спека `landing-screen` содержала тот же дрейф
  («Справки с QR») и не описывала секции DIG-90 — дельта в change-папке
  приводит требования к текущей правде.

## Наблюдения (по спеке — НЕ дефекты, зафиксировано как контракт)

### N1. `/?plain` query-параметр НЕ является переключателем plain-версии

- **Поведение:** `https://ostrovok.store/?plain` и локальная сборка
  рендерят обычную версию (класс `a11y-plain` на `<html>` отсутствует);
  GET с query ничего не включает.
- **Контракт (спека DIG-100, `openspec/specs/a11y/spec.md`):** включение —
  только ссылкой над шапкой и в футере (форма → server action
  `toggleA11yVersion` → cookie `du-a11y-version=plain|off`, работает без JS).
  Тумблера в Настройках для plain НЕТ — это соответствует спеке (в Настройках
  только large-text/no-effects, DIG-86).
- **e2e-фиксация:** тест «/?plain не является переключателем…» проверяет оба
  факта: query не включает plain, cookie включает. Прогон зелёный.

### N2. plain-ссылка owner-scoped: аноним на лендинге уходит на /login

- **Поведение:** `toggleA11yVersion` требует сессию (`requireDataCtx`) —
  анонимный посетитель лендинга, нажав «Версия для слабовидящих», попадает
  на `/login?next=/`.
- **Статус:** это ЯВНО описано спекой DIG-100 («анонимный посетитель выпадает
  на /login») — регрессией не считается, правило не нарушено.
- **Риск/рекомендация:** для слабовидящего анонима публичная доступная версия
  недостижима до входа. Рекомендую отдельной задачей повторить ход D1
  (локаль/plain — cookie-предпочтения без данных; IDOR невозможен) и
  разрешить `toggleA11yVersion` анонимно. В этой задаче НЕ делалось — правка
  спеки DIG-100 вне скоупа регресса.

### N3. Оптимистичный тумблер Настроек (замечание к тестам, не к продукту)

- Toggle «Крупный текст» чекается на клиенте ДО ответа server action —
  e2e-проверку сохранения корректно делать по статусу «Сохранено…» и классу
  `<html>` после перезагрузки. В регресс-спеке сделано именно так; продукт
  работает: оба тумблера применяются (классы `a11y-large-text` /
  `a11y-no-effects` на `<html>`, ≥125% базовый шрифт, параллакс стопится)
  и переживают перезагрузку; выключение убирает классы.
