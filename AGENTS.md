# Цифровой деканат — правила для ИИ-агентов

> Этот файл обязателен для любого агента, работающего в репозитории
> (OpenCode-рой, любые CLI, IDE-ассистенты). Нарушение любых пунктов из
> «Жёстких запретов» — автоматический RETURN на ревью.

## Что это за проект

Конкурсный прототип **«Цифровой деканат будущего»** — личный кабинет студента:
всё в одном месте (расписание, успеваемость, заявки, уведомления, обращения),
мобильный (360 px), красивый и безопасный. Это **концепт для конкурса**, не
официальный сервис вуза. Дедлайн подачи: 22 ноября 2026, 23:59 МСК; прототип
должен работать до 28 ноября.

## Стек

- **Next.js 15 (App Router) + TypeScript**, React Server Components по умолчанию.
- **Prisma + PostgreSQL** — данные (docker-compose на сервере).
- **NextAuth (credentials)** или собственные сессии — вход по логину/паролю,
  пароли только через `bcrypt`/`argon2`.
- **Tailwind CSS + дизайн-токены** (см. `openspec/specs/design-system/`).
- Тесты: **Vitest** (unit) + **Playwright** (e2e, mobile-вьюпорт 360×800).
- Стиль кода: ESLint + Prettier из стандартного шаблона Next.js.

## Структура (после инициализации)

```
src/app/(auth)/login        — вход
src/app/(app)/…             — экраны кабинета (layout = Shell)
src/components/…            — UI-компоненты
src/lib/…                   — auth, db, трассировка доступа
src/server/actions/…        — server actions (мутации)
prisma/schema.prisma        — схема БД
prisma/seed.ts              — вымышленные данные
tests/                      — unit и e2e
```

## Экраны — по Figma

Каждая экранная задача Linear (метка `screen`) соответствует фрейму в файле
Figma «Цифровой деканат — экраны ЛК студента»
(<https://www.figma.com/design/dP2lFEahhw1gBbMRKX7BD2>). Соответствие
«экран ↔ задача» — в `docs/figma-screens.md`. Правила:

- Шрифт **Inter** (как в макетах), десктоп 1440 px, мобильный 390 px, минимум 360 px.
- Шапка и боковое меню — общий компонент `Shell` (аналог компонента «Shell · Кабинет»).
- Вёрстку сверять с описанием фрейма в задаче Linear; если задан `FIGMA_TOKEN`,
  можно тянуть данные нод через Figma REST API.
- Дизайн-токены (цвета, радиусы, тени) — из задачи DIG-13, не изобретать свои.

## Жёсткие запреты (автоматический RETURN)

1. **Никаких реальных персональных данных** — только вымышленные ФИО, группы,
   зачётки, преподаватели. Не подключаться к реальным системам вуза.
2. **Никаких секретов в коде**: ключи, пароли, токены — только в `.env`
   (в git не попадает, есть `.env.example`).
3. **Бренд вуза запрещён**: логотип и фирменные материалы использовать нельзя;
   допустим только собственный вымышленный логотип.
4. На каждой странице должна быть заметна плашка **«Концепт для конкурса»**.
5. **IDOR запрещён**: ни один запрос не должен возвращать чужие данные.
   Каждая server action и API-роут обязана проверять `session.user.id`
   (или роль сотрудника) и фильтровать по владельцу.
6. Не ослаблять заголовки безопасности, CSP, rate-limit входа.
7. Не редактировать `scripts/swarm/` из задач-экранов (это инфраструктура роя).

## Definition of Done (для каждой задачи)

- [ ] `npm run lint` — без ошибок; `npm run typecheck` — зелёный.
- [ ] `npm test` — зелёный; поведение покрыто тестами (red-first).
- [ ] e2e основного сценария экрана (Playwright, mobile 360×800) зелёный.
- [ ] Страница работает на 360 px и на 1440 px.
- [ ] Пустые состояния, загрузка (skeleton) и ошибки обработаны.
- [ ] Данные вымышленные; на странице есть плашка «Концепт для конкурса».
- [ ] Если экран = задача с меткой `screen` — вёрстка соответствует Figma.
- [ ] Коммит(ы) на ветке задачи, conventional commits с `DIG-XX`.

## Рой (scripts/swarm/)

Оркестратор сам берёт задачи Linear с меткой `swarm` из Todo, создаёт ветку,
вызывает агентов (executor → gates → reviewer → security → documenter) и
открывает PR. Агенту-исполнителю не нужно ничего знать про жизненный цикл
Linear — статусы меняет только оркестратор. Запуск:

```bash
node scripts/swarm/orchestrator.mjs --max 1        # одна задача
node scripts/swarm/orchestrator.mjs --max 3        # очередь из трёх
node scripts/swarm/orchestrator.mjs --dry-run      # только выбрать и показать
node scripts/swarm/orchestrator.mjs --merge --deploy  # авто-merge + деплой
```

Команды для интерактивной работы: `/swarm`, `/next-task`, `/review`,
`/security-gate`, `/opsx:propose`, `/opsx:apply`, `/opsx:archive`.

## SDD / OpenSpec

Проект ведётся по спек-драйвен процессу (см. `docs/sdd/SDD-GUIDE.md`):
каждая содержательная задача — change-папка в `openspec/changes/`
(proposal → tasks → delta-specs), после готовности — `openspec archive`.
Исполнитель обязан создать change-папку, если её нет, и отмечать задачи в
`tasks.md` по ходу работы.
