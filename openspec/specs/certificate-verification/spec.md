# certificate-verification Specification

## Purpose
Проверка подлинности документов: коды проверки, публичная страница /verify, QR в PDF, отзыв справок сотрудником, текстовый слой PDF.
## Requirements
### Requirement: Код проверки справки

Каждый цифровой документ с проверкой подлинности (справка по заявке CERTIFICATE, мгновенная «Справка об обучении» CERT_ENROLLMENT, «Выписка оценок» GRADES_EXTRACT) несёт уникальный код проверки — 32 символа base32 в группах по 4, и этот код СУЩЕСТВУЕТ в реестре справок: страница `/verify/<код>` обязан (MUST)а открыть карточку документа.

#### Scenario: Владелец скачивает PDF мгновенного документа
- **WHEN** владелец скачивает PDF мгновенной справки или выписки (по заявке «ЗД-…» или мимо заявки — `/api/grades/transcript`)
- **THEN** документ печатает код проверки из записи реестра и сканируемый QR со ссылкой `${origin}/verify/<код>`; запись создаётся при первом скачивании (код из криптографического ГСЧ, 160 бит) и переиспользуется при повторных (QR остаётся действительным).

#### Scenario: Выписка скачивается мимо заявки
- **WHEN** выписка скачивается мимо заявки
- **THEN** реестр ключуется стабильным синтетическим ключом на пару (студент, тип документа) — один код на студента и тип документа.

#### Scenario: Срок действия мгновенного документа истекает
- **WHEN** срок действия мгновенного документа истекает (30 дней, как напечатано на PDF справки)
- **THEN** страница проверки отвечает «Документ не найден» (единый ответ с неверным/чужим кодом, без «оракула» существования).

### Requirement: Публичная страница проверки `/verify/<код>`

Требование «Публичная страница проверки `/verify/<код>`» — обязательное (MUST): Страница доступна без входа в кабинет и показывает РОВНО:
тип документа, дату выдачи, ФИО держателя в маскированном виде
(«Смирнова А. В.») и статус.

#### Scenario: Код существует
- **WHEN** код существует, справка не отозвана и не истекла
- **THEN** страница показывает зелёный статус «Документ действителен», тип документа, дату выдачи и маскированное ФИО; полное имя, оценки, контакты и прочие данные НЕ отображаются нигде на странице.

#### Scenario: Справка отозвана сотрудником
- **WHEN** справка отозвана сотрудником
- **THEN** страница показывает красный статус «Отозван» (тип, дата и маскированное ФИО остаются видимыми).

#### Scenario: Код не найден
- **WHEN** код не найден, истёк, имеет неверный формат или справка вышла из реестра
- **THEN** страница показывает нейтральный статус «Документ не найден» без каких-либо полей документа; неверный формат НЕ отличим от отсутствия кода (нет ответа «неверный формат»).

#### Scenario: Страница отрисована
- **WHEN** страница отрисована
- **THEN** на ней есть плашка «Концепт для конкурса» и подсказка «Как проверить документ»; работает на 360 px и 1440 px.

### Requirement: Rate limit перебора кодов

Требование «Rate limit перебора кодов» — обязательное (MUST): Подбор кодов на публичной странице ограничен.

#### Scenario: Превышен лимит обращений с одного IP
- **WHEN** с одного IP за окно `VERIFY_RATE_WINDOW_MS` поступает более `VERIFY_RATE_MAX_ATTEMPTS` обращений к странице проверки
- **THEN** дальнейшие обращения получают состояние «Слишком много попыток» (нейтральный текст без статуса документа) до окончания окна.

### Requirement: PDF-шаблон справки

Требование «Блок «Проверка подлинности» в PDF мгновенных документов» — обязательное (MUST): PDF мгновенной справки и выписки содержит блок проверки со
сканируемым QR; обещание «QR-код появится» и пунктирная рамка-заглушка
запрещены.

#### Scenario: PDF собирается при равных входах
- **WHEN** PDF собирается при равных входах
- **THEN** вывод байт-в-байт детерминирован; QR нарисован модулями-квадратами (энкодер `src/lib/pdf/qr.ts`, сервер, без внешних API и клиентских библиотек), число модульных квадратов в контенте равно числу тёмных модулей матрицы (проверяется парсером).

#### Scenario: QR сканируют декодером
- **WHEN** QR «сканируют» декодером (BCH + Рида–Соломона + byte-mode)
- **THEN** из матрицы восстанавливается ровно verify-URL, напечатанный в том же блоке текстом («Проверить по ссылке или QR-коду: …»).

#### Scenario: Блок проверки попадает к низу страницы
- **WHEN** блок проверки попадает к низу страницы (плотная выписка)
- **THEN** блок целиком переносится на новую страницу: QR не пересекает нижнее поле; строки блока переносятся по ширине, чтобы не заходить под квадрат QR (96 pt ≈ 34 мм).

### Requirement: Отзыв справки сотрудником

Требование «Отзыв справки сотрудником» — обязательное (MUST):

#### Scenario: Сотрудник
- **WHEN** сотрудник (STAFF) отзывает код справки студента СВОЕГО факультета через `POST /api/staff/certificates/revoke`
- **THEN** статус на странице проверки меняется на «Отозван» сразу — при следующем открытии страницы (без кэша).

#### Scenario: Отзыв пытается выполнить студент или сотрудник
- **WHEN** отзыв пытается выполнить студент или сотрудник ЧУЖОГО факультета, либо код не существует
- **THEN** ответ — единый 404, попытка пишется в аудит (ROLE_MISMATCH / OWNERSHIP_DENIED / NOT_FOUND соответственно); повторный отзыв того же кода — идемпотентен (дата отзыва не меняется).

### Requirement: Текстовый слой PDF-документов

Требование «Текстовый слой PDF-документов» — обязательное (MUST): PDF справки, выписки и справки об обучении несут невидимый текстовый слой:
каждая видимая строка дублируется текстом стандартного шрифта Helvetica
(WinAnsi, без вложенных файлов) в режиме отрисовки 3 Tr, документ помечен
/Lang (ru-RU).

#### Scenario: Получатель открывает PDF скринридером
- **WHEN** получатель открывает PDF скринридером
- **THEN** читается текст документа (кириллица — транслитерацией латиницей).

#### Scenario: Получатель копирует текст из PDF
- **WHEN** получатель копирует текст из PDF
- **THEN** код проверки, ссылка проверки, номер документа и даты копируются посимвольно точно (ASCII — без транслитерации).

#### Scenario: PDF собирается при равных входах
- **WHEN** PDF собирается при равных входах
- **THEN** вывод остаётся байт-в-байт детерминированным.

### Requirement: Скоуп выдачи кода мгновенного документа

Требование «Скоуп выдачи кода мгновенного документа» — обязательное (MUST):

#### Scenario: Контекст не студент или `studentId` входа
- **WHEN** контекст не студент или `studentId` входа не совпадает с контекстом
- **THEN** `getOrCreateDocumentVerification` отвечает null и пишет отказ в аудит (`ROLE_MISMATCH` / `OWNERSHIP_DENIED` через `denyAccess`); чужой номер заявки отвечает тем же единым 404 роута (IDOR исключён).
