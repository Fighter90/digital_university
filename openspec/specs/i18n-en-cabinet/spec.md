# i18n-en-cabinet Specification

## Purpose
EN-версия кабинета: паритет словарей RU/EN, ноль кириллицы в EN-рендере, локализация демо-контента и статусов; RU — канон.
## Requirements
### Requirement: EN-рендер разделов кабинета без кириллицы

Требование «EN-рендер разделов кабинета без кириллицы» — обязательное (MUST): На локали `en` видимый рендер перечисленных маршрутов не содержит кириллицы
(кроме демо-ФИО студентов/преподавателей, разрешённых задачей):
`/grades` (+`/grades/gradebook`, `/grades/session`, карточка дисциплины,
AI-динамика), `/deanery`, `/feedback`, `/finance`, `/events`, `/msp`, `/dpo`,
`/people`, `/news`, `/profile`, `/settings`, `/tasks`, `/notifications`,
`/services`, `/more`, `/staff` (+`/staff/requests`, `/staff/appeals`,
`/staff/announcements`).

#### Scenario: Компонент маршрута рендерится на EN без кириллицы

- WHEN компонент маршрута (например `TasksView`, `TicketComposer`,
  `FeedbackComposer`, `DocumentsBrowser`, `AnnouncementForm`) рендерится с
  `locale='en'`
- THEN в HTML-выводе нет символов `[А-Яа-яЁё]`

#### Scenario: Демо-контент локализуется по id записи

- WHEN для каждой демо-записи каталога (events `ev-*`, dpo `dpo-*`, msp
  `msp-*`, новости, seed-уведомления `ntf-*`, сид-дедлайны `dl-*`, сид-задачи
  `task-*`) запрашивается EN-контент
- THEN EN-титул/описание существуют и не содержат кириллицы

#### Scenario: Runtime-уведомление локализуется чтением

- WHEN строка уведомления, созданная известным шаблоном прототипа (подача
  заявки, переход статуса, пересдача, ответ в обращении, отправка на email,
  заказ через ассистента, перенос пары), читается на `en`
- THEN `title`/`body` отдаются на английском без кириллицы

### Requirement: RU-версия байт-в-байт не меняется

Требование «RU-версия байт-в-байт не меняется» — обязательное (MUST):
рендер с `locale='ru'` (дефолт) обязан остаться байт-в-байт прежним.

#### Scenario: RU-рендер не меняется

- **WHEN** рендер с `locale='ru'` (дефолт) сравнивается с прежним
- **THEN** строки идентичны прежним захардкоженным; все существующие RU-тесты
  остаются зелёными

### Requirement: Паритет словарей

Требование «Паритет словарей» — обязательное (MUST): словари `en.ts` и
`ru.ts` обязаны иметь идентичные наборы ключей.

#### Scenario: ключи словарей совпадают

- **WHEN** `en.ts` сравнивается с `ru.ts`
- **THEN** наборы ключей идентичны и ни одно EN-значение не содержит кириллицы

### Requirement: Локализация демо-контента кабинета по locale=en (DIG-93)

Требование «Локализация демо-контента кабинета по locale=en (DIG-93)» — обязательное (MUST): При `locale=en` видимый рендер кабинета не содержит кириллических символов
`[А-Яа-яЁё]`: ни в каркасе, ни в демо-контенте сида.

#### Scenario: Инициалы топбара латиницей

- WHEN пользователь с RU-ФИО («Анна Смирнова») открывает любую страницу
  кабинета с cookie `du-locale=en`
- THEN кнопка-аватар показывает латинские инициалы «AS» (из EN-имени
  маппинга; фолбэк — инициалы из префикса email/логина), а меню аватара —
  транслит имени и EN-подпись группы
- AND при `du-locale=ru` инициалы и имена — прежние («АС», «Анна Смирнова»)

#### Scenario: Демо-контент агрегатов на EN

- WHEN билдеры view-моделей (dashboard, session, gradebook, grade-insight,
  event-details) получают `locale='en'` и канонические RU-строки сида
- THEN в возвращаемых view нет кириллицы: дисциплины, преподаватели, заметки
  пар, семестры, статусы и причины сессии, имена работ инсайта — EN
- AND при `locale='ru'` (дефолт) возвращаются байт-в-байт прежние строки

#### Scenario: Задачи на EN

- WHEN `getTasks` вызывается с `locale='en'`
- THEN глаголы и источники задач всех шести источников — EN: дедлайны по id
  сида, элементы контроля, дисциплины, темы обращений, ручные задачи;
  канонический номер «ЗД-…» в origin показывается транслитом «ZD-…»
- AND глагол, уже собранный словарём с RU-титулом внутри («Submit: Тест 1
  «Кинематика»»), также приводится к EN

#### Scenario: Заявки и обращения на EN

- WHEN список заявок/обращений рендерится при locale=en
- THEN названия заявок — EN (имя типа + адресат: «Enrollment certificate ·
  for the military office»), причины доработки — EN, превью последнего
  сообщения обращения — EN по id сида, `<option>` композера — EN-подписи
  при канонических value (номер/код)
- AND при locale=ru названия/причины/превью — байт-в-байт прежние

#### Scenario: Меню разделов без RU-фолбэка

- WHEN боковое меню или «Ещё» рендерятся при locale=en
- THEN подписи /finance, /msp, /events — EN («Finance», «Startups»,
  «Events»); при locale=ru — прежние «Финансы», «МСП», «Мероприятия»

#### Scenario: AI-гид на EN

- WHEN Shell рендерит AiGuide/AiFab при locale=en
- THEN пилюля «AI guide», панель, шаги экскурсии и сценарии-подсказки — EN
  (те же id контента), микрофон голосового ввода — EN-подписи и en-US
  распознавание
- AND при locale=ru — прежние RU-строки
