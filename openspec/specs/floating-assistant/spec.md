# floating-assistant Specification

## Purpose
Плавающая AI-кнопка (FAB) с попап-чатом: OpenRouter + RAG по справке и FAQ, история в памяти сессии.
## Requirements
### Requirement: Плавающая кнопка AI-ассистента

Плавающая круглая кнопка AI (FAB) ОБЯЗАНА (MUST) быть доступна студенту в
правом нижнем углу всех страниц кабинета, кроме экрана `/ai-assistant`;
на мобильном 360 px поднята над таб-баром, на десктопе 1440 px не перекрывает
контент и соседние плавающие элементы (пилюля AI-гида). Цвет и иконка —
из дизайн-токенов (coral, Sparkles).

#### Scenario: FAB виден над таб-баром на мобильном

- WHEN студент на 360 px открывает любую страницу кабинета, кроме /ai-assistant
- THEN плавающая AI-кнопка видима и расположена выше таб-бара, без перекрытия

#### Scenario: FAB скрыт на экране ассистента

- WHEN студент открывает /ai-assistant
- THEN плавающая AI-кнопка не отображается (вход не дублируется)

#### Scenario: FAB на десктопе не перекрыт гидом

- WHEN на 1440 px пилюля или панель AI-гида раскрыты
- THEN они не перекрывают плавающую AI-кнопку

### Requirement: Попап-чат ассистента

Клик по FAB ОБЯЗАН (MUST) открывать всплывающий чат: на десктопе — карточка
380–420 px у кнопки с хвостиком, на мобильном — bottom-sheet на весь экран
с ручкой. Заголовок «AI-ассистент», кнопка закрытия, поле ввода с отправкой
по Enter и кнопкой; история текущей сессии MUST жить в памяти компонента
(не в БД).

#### Scenario: Вопрос отправляется по Enter

- WHEN студент вводит вопрос в попапе и нажимает Enter
- THEN вопрос добавляется в историю и ассистент отвечает

#### Scenario: Закрытие и повторное открытие

- WHEN студент закрывает попап крестиком и открывает снова
- THEN история текущей сессии (в памяти вкладки) сохраняется, экран не падает

### Requirement: Серверный ответ через OpenRouter

Server action `askFloatingAssistant` ОБЯЗАН (MUST) вызывать OpenRouter
chat-completions серверно: ключ только из `process.env.OPENROUTER_API_KEY`,
модель — бесплатная/дешёвая (переопределяется env), таймаут 20 секунд,
повторов нет. Ключ никогда не должен попадать в клиентский бандл и в
репозиторий.

#### Scenario: Ключ только на сервере

- WHEN выполняется сборка и grep по репозиторию
- THEN ни одного значения ключа в коде нет (grep репозитория по реальному префиксу ключей OpenRouter пуст),
  в `.env.example` — только имя переменной

#### Scenario: Таймаут и без повторов

- WHEN OpenRouter не отвечает в течение 20 секунд или вернул ошибку
- THEN повторного запроса нет, срабатывает fallback-ответ

### Requirement: RAG по справке кабинета

Индекс чанков ОБЯЗАН (MUST) включать секции «Справки» (/guide) и
вопросы/ответы «FAQ» (/help). Retrieval — лексический скоринг без внешних
embedding API: нормализация (регистр, ё→е), русский стемминг + английские
ключи, частота слов запроса по чанку, буст совпадения в заголовке; в промпт
идут топ-3 чанка. Системный промпт требует отвечать только по справке; при
отсутствии данных — честно сказать и предложить открыть справку или создать
обращение. Ответ ОБЯЗАН (MUST) рендериться как текст без markdown-сырца.

#### Scenario: Retrieval находит нужный раздел по русскому вопросу

- WHEN студент спрашивает «Как оформить справку об обучении?»
- THEN retrieval возвращает чанк справки про справки/заявки в топе

#### Scenario: Ответ только по справке

- WHEN вопрос касается использования кабинета
- THEN ответ строится по найденным чанкам справки и рендерится как текст

### Requirement: Fallback демо-режима

Если ключа нет или OpenRouter недоступен/ошибся, ассистент ОБЯЗАН (MUST)
отвечать в демо-режиме: возвращает релевантный чанк справки как «подсказку
из справки» с явной пометкой демо-режима; если чанков не нашлось — честное
сообщение с предложением открыть справку или создать обращение. Прототип
не должен падать и зависать.

#### Scenario: Нет ключа — детерминированный демо-ответ

- WHEN `OPENROUTER_API_KEY` пуст и студент задал вопрос
- THEN ассистент показывает подсказку из найденного чанка справки с пометкой
  демо-режима (без сетевых вызовов)

#### Scenario: Ошибка API — fallback без падения экрана

- WHEN вызов OpenRouter упал (сеть, 5xx, таймаут)
- THEN студент получает fallback-ответ с пометкой, экран остаётся рабочим

### Requirement: Безопасность попапа

Action MUST требовать requireDataCtx (аноним — на /login). Rate-limit:
не более 10 вопросов в минуту на сессию (скользящее окно). Вход MUST
обрезаться до 1000 символов. В серверный лог MUST попадать только факт
вызова, длина входа и режим ответа — не сам вопрос.

#### Scenario: Лимит вопросов на сессию

- WHEN студент (или его сессия) отправляет 11-й вопрос в течение минуты
- THEN action отвечает ошибкой «слишком много вопросов», вызов модели не происходит

#### Scenario: Обрезка длинного входа

- WHEN вопрос длиннее 1000 символов
- THEN в модель/ретривал уходит не более 1000 символов

#### Scenario: Лог без содержимого вопроса

- WHEN обрабатывается любой вопрос
- THEN в логах нет текста вопроса — только факт вызова и длина
