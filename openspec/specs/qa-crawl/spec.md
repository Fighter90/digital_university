# qa-crawl Specification

## Purpose
QA-обход сайта: полный обход ссылок и кнопок без авторизации на 404 и падения рендера — регрессионный гард навигации.
## Requirements
### Requirement: Полный обход ссылок и кнопок сайта

Требование «Полный обход ссылок и кнопок сайта» — обязательное (MUST): Сайт (прод-стенд) обязан проходить автоматический обход: каждая страница из
навигации (сайдбар, таб-бар, «Ещё», вкладки настроек) и каждая внутренняя
ссылка на посещённых страницах отвечают успешным HTTP-статусом (200 после
следования ожидаемым редиректам), страница рендерит `<main>` с контентом и
плашкой «Концепт для конкурса», консоль браузера свободна от ошибок и
ответов ≥ 400 (кроме намеренно проверяемых страниц 404).

#### Scenario: Аноним видит рабочий вход

- **WHEN** открывается лендинг `/`, CTA «Войти», `/login` («Забыли пароль?»),
  `/forgot-password` («Назад ко входу»), а также запрашивается защищённый
  `/dashboard` без сессии
- **THEN** все страницы отвечают 200 с `<main>` и плашкой концепта, каждая
  внутренняя ссылка — 200, а `/dashboard` отдаёт ожидаемый редирект на
  `/login?next=%2Fdashboard`

#### Scenario: Вошедший студент обходит весь кабинет

- **WHEN** студент (демо-креды) кликает по всем 8 пунктам сайдбара,
  5 вкладкам таб-бара и 5 пунктам «Ещё» (mobile-360), 5 вкладкам настроек,
  разделам успеваемости (сводка, ведомость, дисциплина, сессия, выписка),
  заявкам (список → деталь → справка → `/verify`), видам расписания и
  карточкам каталога сервисов
- **THEN** каждый переход отвечает 200, «Детали пары» открываются из клика
  по паре, выписка и справка отдаются PDF-ом, консоль без ошибок, ни один
  ответ сети не ≥ 400; клик по вкладке настроек обязан сменить URL ровно на
  свой `?tab=<id>` и отрисовать контент этой вкладки, клик по виду расписания —
  дождаться своего `?view=<вид>&…` (строгие проверки URL после клика,
  ревью DIG-60 раунд 3); строка отчёта клика пишется с фактическим итоговым
  URL перехода.

#### Scenario: Ошибки не дают белого экрана

- **WHEN** вошедший пользователь открывает неизвестный адрес или чужой
  номер заявки
- **THEN** сервер отвечает честным 404, и клиент рендерит страницу
  not-found с навигацией (не пустой белый экран)
