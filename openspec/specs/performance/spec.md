# performance Specification

## Purpose
Серверная производительность и стабильность: скоуп данных владельца, агрегаты оценок, рейтинг группы, гарды гидрации и сборки.
## Requirements
### Requirement: Гард гидрации (таймзона в клиентских компонентах)

Требование «Гард гидрации (таймзона в клиентских компонентах)» — обязательное (MUST):

#### Scenario: Клиентский компонент форматирует дату во время
- **WHEN** клиентский компонент форматирует дату во время рендера
- **THEN** форматирование задаёт явный timeZone (Europe/Moscow); вызовы Intl.DateTimeFormat без timeZone и toLocale*String в 'use client'-файлах запрещены и ловятся юнит-сканером (корень React #418 не возвращается).

### Requirement: Гард консистентности сборки (чанки)

Требование «Гард консистентности сборки (чанки)» — обязательное (MUST):

#### Scenario: Сборка не отдаёт пререндер несуществующих чанков
- **WHEN** выполнен `next build` **THEN** каждый файл, на который ссылается app-build-manifest.json и пререндер-HTML (`/_next/static/…`), существует в `.next` — сборка не может отдать предзагрузку несуществующего чанкам (источник 404 BUG-13).

### Requirement: Накопленная оценка дисциплины

Слой данных ДОЛЖЕН (MUST) возвращать по каждой дисциплине текущего студента
накопленную оценку (Σ(нормированный вес × доля максимума) по выставленным
элементам), минимально гарантированную (несданные элементы — нули) и
максимально возможную (несданные — на максимум) в процентах 0–100. Веса
нормируются на сумму весов плана контроля дисциплины; при пересдаче
элемента учитывается последняя оценка по дате; элементы с maxScore ≤ 0
исключаются из плана. Оценок нет → накопленная `null`, границы 0 и 100.

#### Scenario: частично сданная дисциплина

- **WHEN** студент сдал проект на 85 из 100 (вес 0.3), тест и экзамен
  впереди (веса 0.2 и 0.5)
- **THEN** накопленная = 25.5, минимально гарантированная = 25.5,
  максимально возможная = 95.5.

#### Scenario: дисциплина без оценок

- **WHEN** по дисциплине оценок нет
- **THEN** накопленная `null`, минимально гарантированная 0, максимально
  возможная 100, семестр не определён.

#### Scenario: завершённая дисциплина

- **WHEN** все элементы плана оценены
- **THEN** итог = арифметическое округление накопленного процента до
  целого (86.5 → 87), минимальная = максимальная = накопленная, кредит
  зачтён при итог ≥ 60.

### Requirement: GPA за семестр и за всё время

Слой данных ДОЛЖЕН (MUST) считать GPA средневзвешенно кредитами дисциплин:
значение завершённой дисциплины — округлённый итог, идущей — накопленная.
Семестр дисциплины — по московскому учебному календарю (дата последней
оценки). Дополнительно ДОЛЖНЫ быть возвращены GPA за всё время, GPA и
метка текущего семестра, GPA и метка предыдущего семестра и дельта
(текущий − предыдущий; не с чем сравнивать → `null`).

#### Scenario: дельта к прошлому семестру

- **WHEN** у студента есть оценки в текущем и предыдущем семестрах
- **THEN** `semesterDelta` = GPA текущего − GPA предыдущего (до 0.01),
  рядом метки обоих семестров.

#### Scenario: первый семестр

- **WHEN** оценок в предыдущем семестре нет
- **THEN** `previousSemesterLabel` и `semesterDelta` — `null`.

### Requirement: Кредиты

Слой данных ДОЛЖЕН (MUST) возвращать «набрано» (Σ кредитов завершённых дисциплин
с итогом ≥ 60) и «требуется» (240 на программу).

#### Scenario: прогресс кредитов

- **WHEN** студент завершил дисциплины на 5 и 4 кредита с итогами ≥ 60
- **THEN** `credits = { earned: 9, required: 240 }`.

### Requirement: Рейтинг в группе и перцентиль

Слой данных ДОЛЖЕН (MUST) возвращать место студента по общему GPA среди
студентов его группы с оценками, размер группы, «топ-X%» =
ceil(место/размер×100) и готовую формулировку «Вы входите в N% лучших в
группе». Равные GPA — одно место (competition ranking). Группа из одного
студента — «Вы — единственный студент в группе». Студент без оценок —
рейтинга нет (`null`). Оценки сокурсников используются только внутри
агрегата: чужие строки наружу не выходят.

#### Scenario: человеческая формулировка

- **WHEN** студент второй из пяти по общему GPA
- **THEN** `rating = { rank: 2, groupSize: 5, bestPercent: 40, label:
  'Вы входите в 40% лучших в группе' }`.

#### Scenario: равные GPA

- **WHEN** два студента имеют одинаковый общий GPA
- **THEN** оба на месте 1; следующий — на месте 3.

### Requirement: Долги (пересдачи)

Слой данных ДОЛЖЕН (MUST) возвращать по RETAKE-сессиям группы: дисциплину, дату
пересдачи, дней до неё и статус — `CLOSED` (итог/накопленная ≥ 60),
`ASSIGNED` (дата сегодня или позже), `OVERDUE` (дата прошла, долг не
закрыт). Активные раньше закрытых, внутри — по дате.

#### Scenario: три статуса долга

- **WHEN** в группе есть прошедшая пересдача по несданной дисциплине,
  будущая пересдача и прошедшая пересдача по дисциплине с итогом ≥ 60
- **THEN** статусы соответственно OVERDUE, ASSIGNED, CLOSED; закрытая
  последняя.

### Requirement: needForTarget — калькулятор цели

`needForTarget(db, ctx, disciplineCode, target)` ДОЛЖЕН (MUST) вернуть
минимальный балл на экзамене (в шкале элемента и в процентах), при котором
итог с арифметическим округлением станет ≥ target, считая остальные
незакрытые элементы нулями. Статусы: `OK`, `ALREADY_SECURED`,
`EXAM_ALREADY_GRADED`, `UNREACHABLE` (с `bestPossible`), `NO_EXAM_ELEMENT`.

#### Scenario: граница округления

- **WHEN** накопленная 25.5, вес экзамена 0.5 (max 100), target 70
- **THEN** `OK`, `neededScore = 88` (при 87 итог 25.5 + 0.5·87 = 69.0 → 69 <
  70, при 88 итог 69.5 округляется вверх в 70), `guaranteedFinal = 70`.

#### Scenario: дробная цель

- **WHEN** накопленная 25.5, вес экзамена 0.5 (max 100), target 70.5
- **THEN** `OK`, `neededScore = 90` (итог округлённый — целое, «итог ≥ 70.5»
  равносильно «итог ≥ 71»; при 90 итог 70.5 округляется вверх в 71),
  `guaranteedFinal = 71`.

#### Scenario: нет оценок

- **WHEN** по дисциплине оценок нет, вес экзамена 0.6, target 60
- **THEN** `OK`, `neededScore = 100`.

#### Scenario: экзамен уже сдан

- **WHEN** экзаменационный элемент оценён и итог ≥ target
- **THEN** `ALREADY_SECURED`; иначе — `EXAM_ALREADY_GRADED` с итогом и
  баллом экзамена.

#### Scenario: цель недостижима

- **WHEN** даже 100 на экзамене не дают target
- **THEN** `UNREACHABLE` с `bestPossible` — максимумом достижимого.

### Requirement: Скоуп данных текущего студента (IDOR)

Требование «Скоуп данных текущего студента (IDOR)» — обязательное (MUST): Все функции ДОЛЖНЫ получать ctx из живой сессии и скоупить персональные
выборки по `ctx.studentId`, справочники и сессии — по `ctx.groupName`.
Сотрудник (studentId отсутствует) — пустой агрегат / `null` + запись в
аудите `ROLE_MISMATCH`. Дисциплина в needForTarget вне группы ctx —
единообразный `null` с причиной `OWNERSHIP_DENIED` в аудите; некорректный
target (NaN/∞) — `null` без записи в аудит.

#### Scenario: сотрудник

- **WHEN** сотрудник вызывает getPerformance или needForTarget
- **THEN** пустой агрегат / `null`, в AuditLog — `ROLE_MISMATCH`.

#### Scenario: чужая дисциплина

- **WHEN** студент запрашивает дисциплину другой группы
- **THEN** ответ `null` — такой же, как для несуществующей; причина
  (`OWNERSHIP_DENIED`) только в AuditLog.

#### Scenario: чужие оценки не покидают агрегат рейтинга

- **WHEN** студент получает свой агрегат
- **THEN** в ответе нет ни ФИО, ни оценок сокурсников — только его место
  и перцентиль.

### Requirement: Сводка «как у меня дела»

Экран `/grades` ДОЛЖЕН (MUST) показывать кольцо среднего балла выбранного
семестра (итог ?? накопленная, вес — кредиты), дельту к предыдущему
семестру со знаком и короткой подписью предыдущего семестра (не с чем
сравнивать → дельта не показывается), GPA за всё время, прогресс кредитов
«набрано из 240» (полоса + aria-валу) и место в группе «N из M» с
формулировкой «Вы входите в X% лучших в группе» и тултипом «Как считается».

#### Scenario: идущий семестр с дельтой

- **WHEN** осень 2026/27: GPA семестра 27,14, весной 2025/26 GPA 81,22
- **THEN** кольцо «27,1», дельта «−54,1 к Весна 25/26», кредиты «9 из 240»,
  рейтинг «2 из 5» с «Вы входите в 40% лучших в группе».

#### Scenario: завершённый семестр

- **WHEN** выбрана весна 2025/26 (итоги 87 и 74)
- **THEN** кольцо «81,2», дельты нет (предыдущий семестр пуст), на
  карточках «Экзамен сдан», словесные уровни «Отлично» / «Хорошо».

### Requirement: Выбор семестра

Экран ДОЛЖЕН (MUST) показывать пилюли семестров: семестры с оценками плюс
текущий (даже пустой), по убыванию, с короткими подписями («Осень 26/27»).
Активная пилюля помечена aria-current. Параметр `?semester=YYYY-FALL|
YYYY-SPRING` выбирает семестр; мусор откатывается к дефолту. Дефолт —
текущий семестр, а если в нём нет оценок — ближайший семестр с оценками.
Безоценочные дисциплины остаются в срезе текущего семестра.

#### Scenario: дефолт при пустом текущем семестре

- **WHEN** в текущем семестре оценок ещё нет, последняя оценка — весна
- **THEN** открыт семестр с последними оценками, кольцо показывает его GPA.

#### Scenario: пустой выбранный семестр

- **WHEN** в выбранном семестре нет ни одной оценки
- **THEN** вместо карточек — «Оценок пока нет» с подсказкой о первой
  контрольной («Первая контрольная — зачёт по … 14 ноября»); светофор
  нейтрален (idle).

### Requirement: Карточки дисциплин

Карточка дисциплины ДОЛЖНА (MUST) показывать название, преподавателя (из
справочника группы), кредиты («4 кр.»), крупную оценку («87» итог /
«48,9» накопленная / «—» без оценок), «из возможных 88,9» для идущей,
словесный уровень рядом с цветом («Отлично», «Хорошо», «Порог уже
набран», «Порог ещё не гарантирован», «Не дотянуть до порога», «Ниже
порога», «Оценок ещё нет») и бейдж допуска к экзамену: «Экзамен сдан» /
«Допуск к экзамену есть» (неоценён только экзамен) / «Допуска к экзамену
нет» (есть и другие несданные) / без бейджа (в плане нет экзамена). Клик
ведёт в зачётную книжку `/grades/gradebook?discipline=CODE`.

#### Scenario: допуска нет

- **WHEN** сдан 1 из 3 элементов, среди несданных — не только экзамен
- **THEN** бейдж «Допуска к экзамену нет» (warning).

#### Scenario: дисциплина без экзамена в плане

- **WHEN** план дисциплины без экзаменационного элемента
- **THEN** бейджа допуска нет ни в каком виде.

### Requirement: Светофор состояния

Экран ДОЛЖЕН (MUST) показывать светофор с приоритетом: активные долги («Есть
долги», «Активных долгов: N. Ближайшая пересдача — …», действие к
#debts) > риски («Есть риски», N дисциплин с недостижимым порогом,
действие к сессии) > всё хорошо («Всё хорошо», действие к сессии) >
«Оценок пока нет» (без действия). Тон светофора имеет и статус бейджа
(debts=error, risk=warning, ok=success, idle=neutral).

#### Scenario: долги важнее рисков

- **WHEN** есть и просроченный долг, и дисциплина в зоне риска
- **THEN** тон debts, фраза с ближайшей пересдачей, действие ведёт к блоку долгов.

### Requirement: Долги

Блок «Долги» (#debts) ДОЛЖЕН (MUST) перечислять незакрытые пересдачи со статусом
(«Назначена» info / «Просрочена» error), фразой даты («Пересдача назначена
на 19 ноября (осталось 7 дней)» / «Пересдача была 8 ноября — долг не
закрыт») и ссылкой «Записаться на пересдачу» → /deanery.

#### Scenario: активные долги

- **WHEN** есть просроченная и назначенная пересдачи
- **THEN** обе строки с фразами дат; закрытые долги в блоке не показываются.

### Requirement: Доступ и состояние экрана

Требование «Доступ и состояние экрана» — обязательное (MUST): Данные ДОЛЖНЫ читаться только на сервере из `getPerformance(dataDb, ctx)`
и `listExams(dataDb, ctx)` с ctx из живой сессии; `?semester=` влияет
только на срез уже своих данных. Сотруднику (studentId = null) — заглушка
«Экран доступен студентам» без обращения к данным. Ошибка агрегата —
ErrorState «Успеваемость не загрузилась» с «Повторить» (role=alert).
Пока агрегат грузится — скелетон (loading.tsx → GradesSkeleton, aria-busy).
Страница живёт в main-регионе Shell и не заводит собственный <main>.

#### Scenario: сотрудник

- **WHEN** ctx.role = STAFF
- **THEN** заглушка «Экран доступен студентам», студенческих данных нет.

#### Scenario: ошибка данных

- **WHEN** getPerformance отклоняется
- **THEN** role=alert, «Успеваемость не загрузилась», кнопка «Повторить».

### Requirement: Рейтинг группы по среднему баллу

Фасад `getGroupRating(db, ctx)` ДОЛЖЕН (MUST) возвращать таблицу студентов
группы из `ctx.groupName` (только из сессии; параметр из URL невозможен
по построению) со средним баллом каждого студента, рассчитанным ЕДИНОЙ
функцией агрегата успеваемости (`gpaOfStudent`, DIG-80). В строках
ДОЛЖНЫ быть только: studentId, ФИО, средний балл, место, флаг «строка
владельца» — оценки сокурсников по дисциплинам наружу не раскрываются.
Сотрудник (studentId = null) ДОЛЖЕН получать null с записью в AuditLog
(ROLE_MISMATCH).

#### Scenario: сортировка и места

- **WHEN** в группе оценки у трёх студентов: 95 / 85 / 70, у четвёртого
  оценок нет
- **THEN** порядок 95 → 85 → 70, места 1/2/3; студент без оценок — после
  ранжированных, по алфавиту, без места и среднего; размер таблицы равен
  размеру группы (совпадает с «N из M» сводки).

#### Scenario: равные средние — одно место

- **WHEN** два студента имеют одинаковый средний балл
- **THEN** оба показываются с одним и тем же местом (1 + число тех, чей
  средний строго выше), между собой — по алфавиту; место владельца на
  странице рейтинга совпадает с «место N из M» на сводке /grades.

#### Scenario: единый расчёт с агрегатом DIG-80

- **WHEN** у владельца ctx GPA за всё время X и место N по getPerformance
- **THEN** getGroupRating возвращает для него средний X и место N.

### Requirement: Страница «Рейтинг группы» (/grades/rating)

Экран ДОЛЖЕН (MUST) показывать таблицу «место №, ФИО, средний балл (всегда два
знака)» с тонким прогресс-баром среднего к шкале проекта (0–100) у
каждого оценённого студента. Строка владельца ДОЛЖНА быть подсвечена и
помечена меткой «вы» (словарь). Экран ДОЛЖЕН работать на 360 px и
1440 px в общем Shell с плашкой «Концепт для конкурса».

#### Scenario: строка владельца

- **WHEN** студент открывает /grades/rating
- **THEN** его строка подсвечена, рядом с ФИО — метка «вы» (RU) / «you»
  (EN).

#### Scenario: группа без оценок

- **WHEN** в группе ни у кого нет ни одной оценки
- **THEN** вместо таблицы — empty-state «В группе пока нет оценок» с
  подсказкой; таблица не рендерится.

#### Scenario: группа из одного студента

- **WHEN** в группе один студент с оценками
- **THEN** таблица из одной строки с местом 1 и меткой «вы».

#### Scenario: сотрудник

- **WHEN** сотрудник деканата открывает /grades/rating
- **THEN** заглушка «Доступно студентам» вместо студенческого рейтинга;
  вызов слоя данных возвращает null + запись в аудите.

### Requirement: Переход из сводки успеваемости

Блок «Рейтинг в группе» на /grades ДОЛЖЕН (MUST) содержать ссылку «Весь рейтинг
группы» на /grades/rating.

#### Scenario: ссылка из сводки

- **WHEN** студент с рейтингом открывает сводку /grades
- **THEN** в блоке рейтинга есть ссылка на /grades/rating.
