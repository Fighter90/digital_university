# seeding Specification

## Purpose
Сиды демо-данных: идемпотентный запуск, живое расписание относительно текущей недели, только вымышленные данные и хэши паролей.
## Requirements
### Requirement: Единые демо-доступы memory и БД-сида

Логины и пароли demo-набора DIG-12 (memory) ДОЛЖНЫ (MUST) совпадать с
сидом БД (prisma/seed-data.ts): `anna.smirnova`, `ilya.petrov`,
`dean.kovaleva`; пароли — публичные по дизайну прототипа
(`anna-demo-2026`, `ilya-demo-2026`, `dean-demo-2026`), отображаются
чипами экрана входа.

#### Scenario: вход по чипу работает на обоих хранилищах

- **WHEN** вход выполняется по демо-чипу экрана входа (memory-store или
  БД-сид)
- **THEN** пара логин/пароль совпадает на обоих хранилищах; пользователь
  попадает в кабинет под соответствующей ролью

### Requirement: Идемпотентный сид демо-данных

Требование «Идемпотентный сид демо-данных» — обязательное (MUST): Сид `pnpm db:seed` наполняет БД вымышленными данными; повторный запуск не
создаёт дубликатов (финальное состояние одинаково после любого числа запусков).

#### Scenario: Повторный запуск сида

- WHEN выполняют `pnpm db:seed` второй раз без изменения кода
- THEN счётчики всех таблиц совпадают с первым запуском, дублей нет.

### Requirement: Живое расписание относительно текущей недели

Требование «Живое расписание относительно текущей недели» — обязательное (MUST): Расписание генерируется на семестр (≈8 недель назад … ≈6 недель вперёд от
текущего понедельника). На текущей неделе ровно: 1 перенос аудитории,
1 перенос времени, 1 отмена. Сессия (зачёты, экзамены, 1 пересдача) — в
последние 2 недели семестра.

#### Scenario: Демо живое в любой день

- WHEN сид выполняют в произвольную дату (до 28.11 и после)
- THEN в диапазоне семестра содержится текущая дата, исключения приходятся
  на текущую неделю, сессия лежит внутри семестра.

### Requirement: Только вымышленные данные и безопасные пароли

Требование «Только вымышленные данные и безопасные пароли» — обязательное (MUST): Все email — на домене `example.edu`; ФИО преподавателей — из собственного
вымышленного списка; в сидах пароли только как bcrypt-хэши, открытые пароли —
только в README для жюри.

#### Scenario: Проверка ПДн и паролей

- WHEN читают prisma/*.ts и README
- THEN в сидах нет открытых паролей, все хэши соответствуют формату bcrypt,
  email только `@example.edu`, README содержит тестовые аккаунты.
