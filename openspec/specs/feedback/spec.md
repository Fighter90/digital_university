# feedback Specification

## Purpose
Экран «Предложение или жалоба руководству»: адресная обратная связь с категориями и статусами, отдельная от обращений в деканат.
## Requirements
### Requirement: Понятный канал обратной связи в навигации

Требование «Понятный канал обратной связи в навигации» — обязательное (MUST): Кабинет содержит раздел «Обратная связь» (`/feedback`), доступный студентам.
Название пункта меню однозначно объясняет назначение (предложения, жалобы,
благодарности руководству) — в боковом меню (десктоп) и в списке «Ещё»
(мобильный). Сотруднику раздел недоступен (пустое состояние «Доступно
студентам» + запись в AuditLog с причиной ROLE_MISMATCH при попытке
создания/чтения).

#### Scenario: Пункт меню объясняет назначение

- **WHEN** студент открывает боковое меню или список «Ещё»
- **THEN** видит пункт «Обратная связь», ведущий на `/feedback`
- **AND** рядом нет пунктов с непонятными названиями каналов обратной связи

### Requirement: Создание обращения

Требование «Создание обращения» — обязательное (MUST): Студент создаёт обращение: тип из фиксированного списка (Предложение, Жалоба,
Благодарность), адресат из фиксированного списка (Деканат, Учебный офис,
Руководство программы, Руководство вуза), текст (1–2000 символов), до 3
вложений (имена файлов, каждое ≤ 5 МБ, имя ≤ 80 символов) и переключатель
«Анонимно». Обращение получает публичный номер `FB-ГГГГ-XXXXX`, статус «На
рассмотрении» и срок ответа «до …» (3 рабочих дня, выходные пропускаются).

#### Scenario: Подписанное обращение видно в списке и в карточке

- **WHEN** студент отправляет форму без «Анонимно»
- **THEN** открывается карточка `/feedback/<номер>` со статусом «На
  рассмотрении», сроком ответа, текстом и вложениями
- **AND** обращение появилось в списке «Мои обращения» на `/feedback`

#### Scenario: Валидация формы

- **WHEN** студент отправляет форму с типом/адресатом вне белого списка,
  пустым текстом, текстом длиннее 2000 символов или более чем 3 вложениями
- **THEN** создание отклоняется с ошибкой формы, обращение не создаётся

### Requirement: Анонимное обращение не связано с пользователем

Требование «Анонимное обращение не связано с пользователем» — обязательное (MUST): Анонимное обращение (переключатель «Анонимно» включён) не хранит связь с
пользователем: в хранилище `studentId = null`, на клиенте и в ответах API
нет пользовательских полей. Оно не появляется в списке «Мои обращения», его
карточка `/feedback/<номер>` отвечает 404 всем — включая автора. После
отправки открывается страница подтверждения `/feedback/sent/<номер>`:
номер, статус, срок ответа и пояснение, что обращение не связано с
аккаунтом. Страница подтверждения показывает ТОЛЬКО минимальное
представление (тип, адресат, статус, даты, признак анонимности) — без
текста, вложений и любых пользовательских данных.

#### Scenario: Анонимное обращение без связи с пользователем

- **WHEN** студент отправляет форму с включённым «Анонимно»
- **THEN** открывается `/feedback/sent/<номер>` с номером, сроком и статусом
- **AND** сохранённая строка не содержит ни `studentId`, ни имени, ни группы
- **AND** обращение отсутствует в списке «Мои обращения» автора
- **AND** `/feedback/<номер>` отвечает 404 (в том числе автору), попытка —
  в AuditLog (OWNERSHIP_DENIED / NOT_FOUND)

#### Scenario: Подтверждение по номеру не раскрывает содержимое

- **WHEN** кто-либо открывает `/feedback/sent/<номер>` по известному номеру
- **THEN** видит только тип, адресат, статус, дату и срок — не текст и не
  вложения, никаких пользовательских данных

### Requirement: Список «Мои обращения» owner-scoped

Требование «Список «Мои обращения» owner-scoped» — обязательное (MUST): Список `/feedback` показывает владельцу сессии ТОЛЬКО его подписанные
обращения (тип, адресат, номер, статус, срок ответа), свежие сверху.
Чужой/несуществующий номер в карточке отвечает тем же 404, что и
несуществующий; различие живёт только в AuditLog (OWNERSHIP_DENIED /
NOT_FOUND) — ответ не является оракулом существования.

#### Scenario: Студент видит только свои обращения

- **WHEN** студент Анна открывает `/feedback`
- **THEN** в списке только обращения Анны, отсортированные свежими сверху
- **AND** ни одно обращение другого студента (и ни одно анонимное) в списке
  не присутствует

### Requirement: Публичная лента решённых предложений

Требование «Публичная лента решённых предложений» — обязательное (MUST): На `/feedback` есть блок «Что мы изменили по вашим предложениям» — публичная
лента решённых предложений: тип/адресат, суть предложения и что изменилось
(результат). Лента общая (без авторов и пользовательских данных), источники —
сиды (3 примера); новые записи может добавлять только слой данных.

#### Scenario: Лента видна всем студентам

- **WHEN** студент открывает `/feedback`
- **THEN** видит блок «Что мы изменили по вашим предложениям» с примерами
  решённых предложений (результат по каждому)
- **AND** в записях ленты нет имён, групп и ссылок на авторов
