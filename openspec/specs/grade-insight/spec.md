# grade-insight Specification

## Purpose
Пояснения оценок: «что изменилось», интерактивный график работ-влияний, скоупинг строго по владельцу.
## Requirements
### Requirement: Карточка «Что изменилось» на «Успеваемости»

Требование «Карточка «Что изменилось» на «Успеваемости»» — обязательное (MUST): Экран «Успеваемость» (`/grades`) показывает студенту карточку «Что
изменилось»: человеческое объяснение динамики среднего балла за последние
30 дней по данным идущего семестра (семестр последней оценки). Логика —
детерминированная, без LLM и внешних сервисов. Метрика карточки считается
по тем же формулам, что GPA-кольцо сводки (накопленная по плану контроля,
взвешенная кредитами), поэтому числа карточки и сводки совпадают. Карточка
не показывается студенту без оценок.

#### Scenario: Карточка рендерится и совпадает с успеваемостью

* WHEN студент с оценками за идущий семестр открывает `/grades`
* THEN карточка «Что изменилось» видна и содержит заголовок-объяснение
* AND текущий средний балл карточки равен значению GPA-кольца сводки

#### Scenario: Формулировка отражает направление динамики

* WHEN за месяц есть новые работы и средний изменился
* THEN заголовок называет направление и величину («вырос на 6,2 пункта:
      было …, стало …»)
* AND пояснение называет работу, повлиявшую сильнее всего
  (работа, дисциплина, балл)
* WHEN за месяц работ не было
* THEN заголовок честно говорит «новых оценок не было»

#### Scenario: Студенту без оценок карточка не показывается

* WHEN у студента нет ни одной оценки
* THEN карточка «Что изменилось» не рендерится

#### Scenario: Сбой расчёта инсайта не роняет экран (ревью r2)

* WHEN агрегат инсайта упал (временная ошибка хранилища)
* THEN остальной экран — сводка, дисциплины, долги — рендерится как обычно
* AND карточка «Что изменилось» не показывается

### Requirement: Интерактивный график с работами-влияниями

Требование «Интерактивный график с работами-влияниями» — обязательное (MUST): Карточка содержит график накопленного среднего балла по датам работ.
Точки интерактивны: наведение, фокус с клавиатуры или нажатие показывают,
какие работы сформировали средний на эту дату (дисциплина, работа, балл —
новые сверху). По умолчанию раскрыта последняя точка.

#### Scenario: Наведение на точку показывает работы

* WHEN студент наводит указатель на точку графика
* THEN карточка показывает работы, вошедшие в средний на эту дату,
      со своими баллами

#### Scenario: Точки доступны с клавиатуры

* WHEN студент переводит фокус на точку графика табом
* THEN разбор работ этой точки раскрывается так же, как при наведении

### Requirement: Скоупинг и доступ (IDOR недопустим)

Требование «Скоупинг и доступ (IDOR недопустим)» — обязательное (MUST): Агрегат `getGradeInsight(db, ctx)` строится из живой сессии: выборки
скоуплены `ctx.studentId` и `ctx.groupName`, из URL идентификаторы не
приходят. Сотрудник деканата (без studentId) получает null с записью
ROLE_MISMATCH в AuditLog. Наружу уходят только данные владельца ctx.

#### Scenario: Сотруднику инсайта нет

* WHEN сотрудник деканата открывает `/grades`
* THEN агрегат инсайта не строится (null)
* AND попытка записана в AuditLog с причиной ROLE_MISMATCH

#### Scenario: Чужие оценки не попадают в разбор

* WHEN студент открывает `/grades`
* THEN в графике и разборах фигурируют только его собственные работы
