# events Specification

## Purpose
Экран «Мероприятия»: события вуза, запись участника и места по вместимости; данные вымышленные.
## Requirements
### Requirement: Афиша мероприятий — общий каталог с фильтрами

Экран /events ОБЯЗАН (MUST) показывать ленту карточек мероприятий,
доступную любому вошедшему (студент и сотрудник): афиша общая, карточка
не содержит личных данных. Карточка ДОЛЖНА (MUST) показывать
обложку-заглушку (детерминированный градиент по названию + иконка типа),
бейдж типа, дату и время, место или «Онлайн», «Осталось N мест»
(«Мест нет» при нуле) и чип «Записан» для записей владельца сессии.
Лента ДОЛЖНА (MUST) сортироваться по дате старта по возрастанию и
фильтроваться query-параметром ?filter=: `week` (старт в ближайшие 7
дней), `faculty` (тег факультета контекста), `career`, `online`;
неизвестное значение — «Все».

#### Scenario: Лента и фильтр «Онлайн»

- **WHEN** вошедший открывает /events?filter=online
- **THEN** показаны только мероприятия с isOnline, сортировка по дате
  старта сохранена; неизвестный ?filter= выглядит как «Все»

#### Scenario: «Осталось N мест» и «Мест нет»

- **WHEN** на мероприятие capacity 5 записано 5 студентов
- **THEN** карточка показывает «Мест нет», а при capacity 120 и 1 записи —
  «Осталось 119 мест» (плюрализация: 1 место / 2 места / 5 мест)

#### Scenario: Пустой фильтр

- **WHEN** под выбранный фильтр мероприятий нет
- **THEN** экран показывает пустое состояние с подсказкой попробовать
  другой фильтр

### Requirement: Запись на мероприятие — owner-scoped toggle

Запись ОБЯЗАНА (MUST) быть мутацией владельца сессии: скоуп —
ctx.studentId, никогда ввод; форма работает без JS (server action).
Повторное нажатие «Вы записаны ✓» отменяет запись (UNIQUE пара
мероприятие+студент, дубликат строки невозможен). Сотруднику запись
запрещена (отказ с аудитом ROLE_MISMATCH); при заполненной вместимости
строка не создаётся — отказ «Мест нет»; несуществующее мероприятие —
отказ с аудитом NOT_FOUND. Записанное мероприятие в прототипе НЕ
добавляется в /schedule (пометка на экране).

#### Scenario: Запись и отмена

- **WHEN** студент нажимает «Записаться», затем «Вы записаны ✓»
- **THEN** создаётся ровно одна строка записи, повторное нажатие её
  удаляет; счётчик мест возвращается к прежнему значению

#### Scenario: Мест нет

- **WHEN** свободных мест ноль и студент не записан
- **THEN** кнопка disabled «Мест нет», записи не создаётся (в том числе
  при гонке двух вкладок)

#### Scenario: Сотрудник и несуществующее мероприятие

- **WHEN** сотрудник отправляет форму записи / форма указывает
  несуществующий eventId
- **THEN** единый отказ без изменений ленты; причина (ROLE_MISMATCH /
  NOT_FOUND) видна только в AuditLog

### Requirement: Карточка мероприятия по slug — единый 404

Страница /events/[slug] ОБЯЗАНА (MUST) открывать мероприятие по
публичному slug (никогда cuid): описание, дата/время, место или ссылку
онлайн-трансляции, вместимость/занято, кнопку записи и заглушку «Друзья
не пойдут». Несуществующий slug ОБЯЗАН (MUST) отвечать контрактным
notFound() (404) без оракула существования: причина — только в AuditLog
(NOT_FOUND); над сегментом [slug] не должно быть loading-границы.

#### Scenario: Открытие по slug

- **WHEN** вошедший открывает /events/<slug> существующего мероприятия
- **THEN** карточка с описанием, датой/временем, местом (или «Онлайн» +
  ссылкой трансляции), вместимостью и занятостью, кнопкой записи

#### Scenario: Несуществующий slug

- **WHEN** открыт /events/<неизвестный-slug> (или некорректный
  percent-encoding)
- **THEN** 404; попытка записана в аудит с reason NOT_FOUND

### Requirement: Пункт меню и концепт-плашка

Раздел ОБЯЗАН (MUST) быть доступен из меню «Ещё» (MORE_SECTIONS += «
Мероприятия», /events, иконка CalendarHeart) и подсвечивать вкладку
«Ещё» на мобильном. Обе страницы ДОЛЖНЫ (MUST) показывать общую плашку
«Концепт для конкурса» (root layout).

#### Scenario: Навигация

- **WHEN** студент открает «Ещё» → «Мероприятия»
- **THEN** открывается /events, пункт и вкладка «Ещё» подсвечены для
  /events/*, плашка «Концепт для конкурса» видна
