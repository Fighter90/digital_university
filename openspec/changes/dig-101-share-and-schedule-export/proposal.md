# DIG-101 — Фича: «Поделиться в соцсетях» + экспорт расписания

## Зачем

У кабинета нет вирусного контура и офлайн-сценария:

- студент не может быстро скинуть полезную статью базы знаний, новость
  или ссылку на день расписания одногруппнику в мессенджер;
- расписание доступно только в кабинете — на экзамен/print/планирование
  его не вытащить (ICS-подписка DIG-63 решает календарь, но не «распечатать
  список пар на неделю» и не «открыть в Excel»).

## Что делается

### Часть 1 — Поделиться

- **Общий клиентский компонент** `src/components/share/share-buttons.tsx`
  (props `{ url, title, locale?, testId? }`): четыре кнопки-иконки
  (lucide: `Share2` → ВКонтакте, `Send` → Telegram, `MessageCircle` →
  WhatsApp, `Link` → скопировать ссылку) с aria-label; шеры открываются
  в новой вкладке (`target="_blank"` + `rel="noreferrer noopener"`):
  `vk.com/share.php?url=…`, `t.me/share/url?url=…&text=title`,
  `wa.me/?text=url+title`. «Скопировать ссылку» — `navigator.clipboard`
  с фолбэком `execCommand` (паттерн ShareButton DIG-36) и видимым
  подтверждением «Ссылка скопирована» (aria-live `role=status`).
  Корень-относительный `url` превращается в абсолютный на клиенте
  (`window.location.origin`) — страница не зависит от заголовков прокси.
- **Размещение**: статья справки `/help/[slug]`, статья новостей
  `/news/[id]` (вместо одиночной кнопки «Поделиться ссылкой» — блок из
  четырёх кнопок; прежние testid `news-share`/`news-share-status` и текст
  e2e сохранены через props), детали пары в расписании — панель
  «Детали пары» шарит безопасную публичную ссылку
  `/schedule?date=<день>&share=lesson-<id>`: получатель открывает СВОЁ
  расписание на этот день, личных данных в ссылке нет.
- **Подписи** — новые ключи словаря `share.*` парой RU/EN.

### Часть 2 — Экспорт расписания

- **Блок «Экспорт»** на `/schedule` (виды «День» и «Неделя», в «Месяце»
  не показывается): три ссылки-кнопки MD / XLSX / PDF на
  `/api/export/schedule.md|xlsx|pdf?view=day|week&date=YYYY-MM-DD`.
  Ссылки учитывают выбранный вид и дату URL.
- **MD**: `GET /api/export/schedule.md` — markdown-таблица
  (Время/Дисциплина/Тип/Аудитория/Преподаватель), по дням; файл
  `schedule-YYYY-MM-DD-day.md` / `schedule-YYYY-MM-DD-week.md`.
- **XLSX**: `GET /api/export/schedule.xlsx` — настоящий .xlsx (OOXML:
  ZIP + worksheet XML) собирает **собственный минимальный писатель**
  `src/lib/xlsx/xlsx-writer.ts` (STORED-записи без сжатия, CRC32,
  детерминированный вывод). Новых зависимостей нет — по образцу
  собственного PDF-писателя проекта (DIG-27), лицензионных строк в
  THIRD_PARTY_LICENSES.md не добавляется. Заголовки колонок в строке 1.
- **PDF**: переиспользование существующего механизма справок/выписки —
  `src/lib/pdf/pdf-writer.ts` (векторный шрифт с кириллицей, DIG-27);
  заголовок, диапазон, плашка «Концепт для конкурса», таблица по дням.
- **Owner-scope**: все три роута — `requireDataCtx` (живая сессия) →
  `getSchedule` (парсы только своей группы; IDOR невозможен по
  построению). Параметров скоупа в URL нет (только `view`/`date`).
  Сотрудник (нет группы) — единый 404 (`uniformNotFoundResponse`).
  Ответы `Cache-Control: private, no-store`, ASCII-имена файлов
  (Content-Disposition).
- **Локаль**: заголовки колонок и подписи диапазона по cookie
  `du-locale` (RU/EN словари), как у выписки DIG-84.

## Non-goals

- Экспорт вида «Месяц» (в блоке только day/week — по постановке задачи).
- Кастомизация состава колонок/диапазона экспорта.
- Реальные бренд-иконки VK/TG/WA (запрещено AGENTS.md) — нейтральные
  иконки lucide согласно постановке.
- Легаси-ключи `news.share`/`news.share.copied` из словарей не удаляются
  (план чистки неиспользуемых ключей — вне задачи).
