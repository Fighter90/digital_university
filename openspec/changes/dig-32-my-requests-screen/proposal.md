# DIG-32 — Экран «Мои заявки» (список со статусами)

## Зачем

Аудит старого ЛК: 9 строк подряд «Центр сервиса «Студент»», пять слов для одного
и того же («Выполнено», «Завершено», «Оплата завершена», «Поддержана», «Удалено»),
у двух заявок один номер, фильтр «Все / В работе / Завершённые» бесполезен.
DIG-30 уже дал серверный фундамент: канонические заявки «ЗД-…», машина состояний
из единого словаря на 8 статусов, действия студента (отмена, повторная подача),
PDF мгновенных типов. Остался сам экран списка.

## Что делаем

Экран `/requests` (фрейм Figma «06 · Заявки — мои заявки»):

- фильтры пилюлями со счётчиками: **Все · В работе · Нужно действие · Готовы · Архив**;
  поиск по номеру и названию;
- карточка заявки: иконка типа, название с ключевым параметром
  («Справка об обучении · для военкомата»), номер, дата подачи, статус-пилюля
  из единого словаря, горизонтальный степпер «Подана → Принята → В работе →
  Готова → Выдана» с текущим шагом, строка следующего действия
  («Готовность до 14 ноября» / «Нужна доработка: укажите ФИО латиницей»),
  кнопка действия (Скачать PDF / Исправить / Отменить);
- заявки «Нужна доработка» всегда наверху списка и выделены;
- клик по карточке → экран «Карточка заявки» (`/requests/[number]`);
- пустое состояние «Заявок пока нет» + «Заказать справку» (в каталог сервисов).

## Решения

- **Единый словарь статусов.** Словарь канона (8 значений из `lib/request-machine`)
  становится единственным, которым говорит UI. Скалярный тип слоя данных
  `RequestStatus` расширяется до надмножества канона; два легаси-значения
  (`COMPLETED`, `NEEDS_REVISION` — мир prisma-сидов DIG-10) отображаются на канон
  чистой функцией `unifyRequestStatus` на стыке «данные → экран». Экран никогда
  не рендерит ничего, кроме 8 канонических меток.
- **Два хранилища — один список.** В прототипе живут канонические заявки (ЗД-…,
  DIG-30) и legacy-заявки панели кабинета (SR-…, DIG-12; на них завязан
  e2e-контракт изоляции данных). Экран показывает обе, едиными карточками и
  единым словарём статусов.
- **Демо-данные.** В сид добавляются канонические «Справка об обучении ·
  для военкомата» в статусе NEEDS_FIX (причина доработки — «Укажите ФИО
  латиницей», как в задаче) и события к ней; legacy-«Справка об обучении для
  налоговой» переводится из COMPLETED в ISSUED по карте миграции DIG-49.
  Так в демо Анны покрыты все пилюли фильтра.
- **Отмена из списка** — кнопкой «Отменить» (с подтверждением) только для
  статусов, где это разрешает машина состояний (до IN_PROGRESS).

## Non-goals

- Полный редизайн «Карточки заявки» — отдельная задача DIG-33; здесь карточка
  по клику показывает существующий экран детали, дополненный каноническими
  заявками (иначе клик ведёт в 404).
- Мастер заказа справки — DIG-31 (ссылка `/requests?order=…` продолжает вести
  на список, параметр игнорируется).
- Переход prisma-сидов `prisma/seed-data.ts` на 8-значный словарь (контракт
  `tests/seed.test.ts` фиксирует 5 статусов этого мира) — задача reconcile-хвоста.
- Реальные PDF бумажных типов, изменение машины состояний, действия сотрудника.
