# Delta — capability: requests-screen (экран «Мои заявки»)

## ADDED

### Requirement: Фильтры пилюлями со счётчиками

Экран «Мои заявки» показывает пять фильтров-пилюль со счётчиками заявок владельца:
«Все», «В работе», «Нужно действие», «Готовы», «Архив». Корзины не пересекаются
и покрывают все статусы единого словаря:

- «В работе» — SUBMITTED, ACCEPTED, IN_PROGRESS;
- «Нужно действие» — NEEDS_FIX;
- «Готовы» — READY;
- «Архив» — ISSUED, REJECTED, CANCELLED.

#### Scenario: Счётчики пилюль сходятся с «Все»

- WHEN у студента есть заявки SUBMITTED, ACCEPTED, IN_PROGRESS, NEEDS_FIX,
  READY, ISSUED
- THEN счётчики равны: Все = 6, В работе = 3, Нужно действие = 1,
  Готовы = 1, Архив = 1, и сумма корзин равна «Все»

#### Scenario: Пилюля фильтрует список

- WHEN выбрана пилюля «Готовы»
- THEN в списке только заявки READY, остальные скрыты

### Requirement: Поиск по номеру и названию

Поле поиска фильтрует текущий список без перезагрузки: совпадение по номеру
(без учёта регистра, включая фрагмент) или названию. Нормализация — нижний
регистр и схлопнутые пробелы.

#### Scenario: Поиск находит по фрагменту номера

- WHEN в поиске введено «000001» или «зд-2026»
- THEN остаются только заявки с совпадающим номером

#### Scenario: Пустой результат поиска

- WHEN совпадений нет
- THEN показывается «Ничего не найдено» со сбросом, а не пустой список

### Requirement: Карточка заявки

Каждая карточка показывает: иконку типа, название с ключевым параметром
(например «Справка об обучении · для военкомата»), номер заявки, дату подачи,
статус-пилюлю из единого словаря (только 8 канонических меток), горизонтальный
степпер «Подана → Принята → В работе → Готова → Выдана» с текущим шагом,
строку следующего действия и кнопку действия (Скачать PDF / Исправить /
Отменить) — по статусу и без запрещённых машиной состояний действий.

#### Scenario: Строка следующего действия для каждого статуса

- WHEN заявка SUBMITTED/ACCEPTED/IN_PROGRESS со SLA
- THEN строка вида «Готовность до 14 ноября»;
- WHEN NEEDS_FIX с причиной «Укажите ФИО латиницей»
- THEN строка «Нужна доработка: Укажите ФИО латиницей» и кнопка «Исправить»;
- WHEN READY
- THEN строка «Документ готов к скачиванию» и кнопка «Скачать PDF»;
- WHEN REJECTED / CANCELLED / ISSUED
- THEN строка с причиной/итогом и без кнопок действий

#### Scenario: Клик по карточке открывает карточку заявки

- WHEN студент кликает по карточке (номер ЗД-… или SR-…)
- THEN открывается `/requests/{номер}` с этой заявкой (чужой номер — 404)

### Requirement: NEEDS_FIX наверху и выделена

Заявки со статусом NEEDS_FIX сортируются выше всех (в каждой корзине и при
любом поиске) и визуально выделены.

#### Scenario: Доработка старше остальных

- WHEN NEEDS_FIX-заявка создана раньше остальных в выбранной корзине
- THEN она всё равно первая в списке

### Requirement: Компактный степпер на 360 px

На ширине до 360 px степпер карточки — точки шагов и подпись только текущего
шага («Шаг 2 из 5 · Принята»); полный вид с подписями всех шагов — от 640 px.

#### Scenario: Мобильный степпер

- WHEN вьюпорт 360×800 и заявка ACCEPTED
- THEN видны 5 точек и текст «Шаг 2 из 5 · Принята», подписи остальных шагов
  не отображаются

### Requirement: Единый словарь статусов

Экран отображает статусы ТОЛЬКО метками единого словаря канона («Подана»,
«Принята», «В работе», «Готова», «Выдана», «Нужна доработка», «Отклонена»,
«Отменена»). Legacy-значения (`COMPLETED`, `NEEDS_REVISION`) отображаются на
канон чистой функцией на входе в экран и на экран не попадают.

#### Scenario: Ни одного вне-словарного статуса

- WHEN рендерится список с заявками всех значений типа `RequestStatus`
- THEN ни одна карточка не показывает «Выполнена»/«Требует правок»; COMPLETED
  показан как «Выдана», NEEDS_REVISION — «Нужна доработка»

### Requirement: Пустые состояния

Нет заявок вовсе — иллюстрация «Заявок пока нет» и кнопка «Заказать справку»
(ведёт в каталог сервисов). Сотруднику список недоступен (пустое состояние,
доступ аудируется — существующий контракт слоя).

#### Scenario: Студент без заявок

- WHEN у студента нет ни одной заявки
- THEN экран показывает «Заявок пока нет» и «Заказать справку»

### Requirement: Демо-данные покрывают все пилюли

Демо-сид студента Анны содержит заявки во всех корзинах: NEEDS_FIX «Справка
об обучении · для военкомата» с причиной «Укажите ФИО латиницей», READY,
SUBMITTED, IN_PROGRESS и архивную; ни одна заявка не имеет обезличенного
названия (название всегда содержит ключевой параметр или конкретную услугу).

#### Scenario: Обезличенных названий нет

- WHEN список рендерится на демо-данных
- THEN ни одно название не совпадает с голым именем типа словаря
