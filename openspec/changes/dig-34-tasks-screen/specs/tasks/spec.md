# Delta: tasks (DIG-34) — экран «Задачи»

## ADDED Requirements

### Requirement: Единый агрегат задач студента

Слой данных ДОЛЖЕН возвращать все открытые действия студента одним
агрегатом `getTasks(db, ctx, now)` из шести источников: канонические
заявки в статусе NEEDS_FIX («Нужна доработка», машина состояний DIG-30),
дедлайны заданий группы (`StudyDeadlineRow`, скоуп `ctx.groupName`),
недопуск к будущим контрольным (правила допуска DIG-28), будущие
пересдачи группы без созданной заявки на запись, не закрытые обращения
с последним сообщением сотрудника, ручные задачи владельца
(`StudentTaskRow`, скоуп `ctx.studentId`). Строка задачи несёт: источник,
что сделать (глагол), откуда, срок, href — ровно на экран, где действие
выполняется, и флаг ручной задачи. Сотрудник получает пустой агрегат и
запись AuditLog (ROLE_MISMATCH).

#### Scenario: задача из заявки на доработке

- **WHEN** у студента есть каноническая заявка со статусом NEEDS_FIX
- **THEN** появляется задача с глаголом «Доработать заявку», источником
  «Заявка» и href на карточку этой заявки (где доступна форма «Исправить
  и подать повторно»); сама строка не дублирует объект заявки (заявка
  остаётся в «Заявках»).

#### Scenario: недопуск закрывается одной сдачей

- **WHEN** по одной дисциплине запланированы и зачёт, и экзамен, а не
  сдан один и тот же набор элементов плана
- **THEN** в списке ровно одна задача «Сдать: <элементы>» со сроком
  ближайшей контрольной.

#### Scenario: пересдача без заявки

- **WHEN** в группе есть будущая пересдача и заявка «Запись на
  пересдачу — <дисциплина>» ещё не создана
- **THEN** задача «Записаться на пересдачу» ведёт на экран «Сессия»;
  после создания заявки задача исчезает.

#### Scenario: ручные задачи и пустой список

- **WHEN** у студента есть ручная задача без отметки (или все задачи
  закрыты)
- **THEN** ручная задача показывает кнопку «Отметить выполненной», а при
  пустом списке экран показывает «Все дела сделаны 🎉».

#### Scenario: скоуп и роли

- **WHEN** запрашивает студент группы A / сотрудник
- **THEN** студент видит только задачи своей группы и свои ручные
  задачи; сотрудник получает пустой агрегат + AuditLog (ROLE_MISMATCH).

### Requirement: Группировка по срокам

Агрегат ДОЛЖЕН группировать задачи в «Просрочено» (срок раньше сегодня),
«Сегодня» (срок сегодня), «На этой неделе» (1–7 дней) и «Позже» (>7
дней); задача без назначенного срока попадает в «Сегодня». Внутри групп
задачи сортируются по возрастанию срока (в «Просрочено» — самые старые
первыми).

#### Scenario: срок не назначен

- **WHEN** заявка «Нужна доработка» не имеет назначенного срока
- **THEN** задача попадает в группу «Сегодня».

#### Scenario: порядок групп

- **WHEN** на экране есть задачи всех четырёх групп
- **THEN** группы выводятся в порядке: Просрочено, Сегодня, На этой
  неделе, Позже.

### Requirement: Отметка ручной задачи выполненной

`markTaskDone(db, ctx, taskId)` ДОЛЖЕН отмечать ручную задачу владельца
(doneAt), быть идемпотентным и отказывать единообразно (null) для
чужого/несуществующего id — различие причины только в AuditLog
(OWNERSHIP_DENIED / NOT_FOUND). Server action ДОЛЖЕН строить ctx из
живой сессии (requireDataCtx), валидировать формат id по белому списку
и быть доступен только студенту.

#### Scenario: владелец отмечает свою задачу

- **WHEN** владелец отмечает свою ручную задачу
- **THEN** doneAt проставляется, задача исчезает из открытого списка;
  повторный вызов не ошибается.

#### Scenario: IDOR

- **WHEN** студент пытается отметить чужую или несуществующую задачу
- **THEN** ответ единообразно отрицательный, в AuditLog — причина
  (OWNERSHIP_DENIED / NOT_FOUND), чужая строка не изменяется.

### Requirement: Меню и блок на главной

Раздел «Задачи» ДОЛЖЕН появиться в боковом меню (CABINET_SECTIONS) и в
списке «Ещё» (MORE_SECTIONS) с иконкой и счётчиком открытых задач
(счётчик резолвится в каркасе кабинета fail-soft, у сотрудника — 0 без
вызова агрегата). Главная ДОЛЖНА получать счётчик и три самые срочные
задачи секцией агрегата `getDashboard` (тот же контракт изоляции сбоев)
и виджет «Что от меня ждут» реестра DIG-44 со ссылкой «Все задачи» на
`/tasks`.

#### Scenario: счётчик в меню

- **WHEN** у студента открыто N задач
- **THEN** у пункта меню «Задачи» показано число N (N = 0 — пилюля
  скрыта).

#### Scenario: блок на главной

- **WHEN** агрегат главной собирается у студента с открытыми задачами
- **THEN** виджет «Что от меня ждут» показывает счётчик, до трёх самых
  срочных задач и ссылку «Все задачи» на `/tasks`; сбой секции не роняет
  остальные блоки главной.
