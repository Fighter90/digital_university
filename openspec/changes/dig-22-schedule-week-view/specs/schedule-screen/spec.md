# Delta: schedule-screen (DIG-22) — недельный вид расписания

> Макет: Figma «03 · Расписание — неделя». Каноничное соответствие
> «экран ↔ задача» — `docs/figma-screens.md` (03 → DIG-22); в тексте задачи
> фрейм ошибочно назван «04» — это «Детали пары» (DIG-24). Сверено по
> ревью раунда 2.

## ADDED Requirements

### Requirement: URL отражает неделю

Страница `/schedule` ДОЛЖНА канонизировать отображаемую неделю ключом
ISO-недели «2026-W46» (параметр `?week=`). Листание недели ДОЛЖНО менять
URL без перезагрузки страницы (клиентская навигация). Поведение ключа —
ровно одно (ревью раунд 2: внутреннее противоречие «фолбэк vs кламп»
снято):

- мусор, `W00`/`W54`, несуществующие 53-и недели И валидный ключ недели,
  целиком лежащей вне семестра, — фолбэк: рендерится неделя «сейчас»,
  без редиректа и ошибки;
- страница недели «сейчас» и валидная граничная неделя клампятся по
  границам семестра (DIG-21 `pageMoscowWeek`): граничная страница
  рисуется от даты начала (до даты конца) семестра;
- стрелки ‹ › на границах семестра отключаются;
- если «сейчас» целиком вне семестра (июль/август) — заглушка
  «Сейчас вне семестра», недельная сетка не рендерится.

#### Scenario: листание без перезагрузки

- **WHEN** студент нажимает «Следующая неделя» (или клавишу →)
- **THEN** URL становится `/schedule?week=<следующий ключ>`, подпись
  недели и содержимое сетки обновляются, документ не перезагружается.

#### Scenario: мусор в параметре

- **WHEN** студент открывает `/schedule?week=banana` или
  `/schedule?week=2027-W53` (2027-й не 53-недельный)
- **THEN** рендерится текущая неделя, ошибок и редиректа нет.

#### Scenario: первая неделя семестра (кламп)

- **WHEN** студент открывает `/schedule?week=<ключ недели, содержащей дату
  начала семестра>`
- **THEN** страница клампится: сетка начинается с даты начала семестра,
  «Предыдущая неделя» отключена, «Следующая неделя» доступна.

### Requirement: Сетка недели 08:00–20:00

Недельный вид ДОЛЖЕН отображать сетку с 08:00 до 20:00, 64 px на час;
позиционирование блока пары — `top = (startMinutes − 480)/60·64`,
высота — `duration/60·64`. Колонка сегодняшнего дня ДОЛЖНА быть тонирована,
красная линия текущего времени ДОЛЖНА обновляться раз в минуту и не должна
рисоваться на сервере (SSR-мисматч исключён). Пересекающиеся пары ДОЛЖНЫ
делить ширину колонки дня; «встык» (start = end соседа) пересечением не
считается.

Цвета типов занятий — на дизайн-токенах DIG-13: лекция — `lesson-lecture`
(коралловый), семинар — `lesson-seminar` (синий), лабораторная —
`lesson-lab` (зелёный), консультация — `lesson-exam` (янтарный).
Отклонение от текста задачи («экзамен — янтарный»), зафиксировано по
ревью раунда 2: вида занятия EXAM в данных DIG-21 нет
(`ScheduleKind = LECTURE | PRACTICE | LAB | SEMINAR | CONSULTATION`),
янтарные токены закреплены за «Консультацией»; если EXAM появится —
токены переходят ему.

#### Scenario: пересечение

- **WHEN** в одном дне две пары пересекаются по времени
- **THEN** каждая занимает половину ширины колонки; непересекающиеся
  соседние пары — полную ширину.

#### Scenario: перенос и отмена

- **WHEN** в неделе есть перенесённая (`ROOM_CHANGED`/`TIME_CHANGED`) и
  отменённая (`CANCELLED`) пары
- **THEN** перенос отрисован серой штриховкой с пунктирной рамкой, бейджем
  «Перенос» и строкой «было: ауд. 214 / 11:10» (из `previousRoom` /
  `previousStartsAt`); отмена — зачёркнутым заголовком, бледным блоком и
  бейджем «Отменена»; причина изменения доступна в блоке и панели деталей.

### Requirement: Доступность блока пары

Блок пары ДОЛЖЕН быть кнопкой с понятным `aria-label`
«<Тип>, <Дисциплина>, <HH:mm–HH:mm>, ауд. <N>» c суффиксом «, перенос»
для перенесённой и «, отменена» для отменённой пары (онлайн-пара —
«онлайн» вместо «ауд.»). Клик ДОЛЖЕН открывать боковую панель деталей
пары; клавиша Esc ДОЛЖНА её закрывать.

#### Scenario: aria-label перенесённой пары

- **WHEN** скринридер попадает на блок перенесённой пары
- **THEN** подпись — «Лабораторная, Программирование, 12:00–13:30,
  ауд. 305, перенос».

#### Scenario: Esc закрывает панель

- **WHEN** панель деталей открыта и студент нажимает Esc
- **THEN** панель закрыта.

### Requirement: Клавиатурное листание

Стрелки ←/→ ДОЛЖНЫ листать недели (кроме случаев, когда фокус в поле
ввода или в переключателе вида), с отключением на границах семестра.

#### Scenario: стрелки

- **WHEN** студент нажимает ← на теле страницы
- **THEN** отображается предыдущая неделя и URL обновляется.

### Requirement: Фильтры левой колонки

Левая колонка ДОЛЖНА содержать мини-календарь месяца отображаемой недели
(текущая неделя тонирована, сегодня — коралловый круг), фильтры по типу
занятия с цветными чекбоксами и счётчиками и фильтр по преподавателю.
Фильтры ДОЛЖНЫ применяться локально (без сетевого запроса) и скрывать
блоки пар.

#### Scenario: фильтр типа занятия

- **WHEN** студент снимает чекбокс «Лекция»
- **THEN** блоки лекций скрываются, остальные типы остаются; возврат
  чекбокса возвращает блоки.

### Requirement: Тулбар и мобильная замена

Тулбар ДОЛЖЕН содержать кнопку «Сегодня» (переход к текущей неделе),
стрелки ‹ ›, подпись недели («9 – 15 ноября 2026»), переключатель
День / Неделя / Месяц (выбрана «Неделя»; День и Месяц отключены до
реализации соответствующих видов) и кнопку «Синхронизировать»
(перечитывает данные). На ширине < 768 px недельный вид ДОЛЖЕН заменяться
мобильным представлением (в DIG-22 — заглушка; мобильный день — DIG-23).

#### Scenario: неделя вне семестра

- **WHEN** студент открывает `/schedule?week=2027-W30` (июль вне семестра)
- **THEN** рендерится неделя «сейчас» (`data-week-key` = текущий ключ);
  ошибок и редиректа нет, на границах семестра соответствующая стрелка
  отключена.

#### Scenario: «сейчас» вне семестра

- **WHEN** сегодняшний день целиком вне учебного семестра (июль/август)
- **THEN** `/schedule` показывает заглушку «Сейчас вне семестра»,
  недельная сетка не рендерится.

#### Scenario: сотрудник деканата

- **WHEN** сотрудник (без учебной группы) открывает `/schedule`
- **THEN** он видит заглушку «Расписание доступно студентам», недельная
  сетка не рендерится (попытка чтения фиксируется в аудите слоем данных).
