# Delta-spec: certificate-verification — проверка подлинности справок

## ADDED Requirements

### Requirement: Код проверки справки

Каждая выданная справка несёт уникальный код проверки — 32 символа
алфавита base32 (A–Z, 2–7) в группах по 4, разделённых дефисом.

- **WHEN** справка выдаётся (впервые открывается карточка выполненной
  заявки-справки или скачивается её PDF)
  **THEN** создаётся ровно одна запись справки с кодом, полученным из
  криптографического ГСЧ (`crypto.getRandomValues`), энтропия ≥ 128 бит
  (160 бит при 32 символах × 5 бит).
- **WHEN** справка уже существует у заявки
  **THEN** повторное открытие карточки или скачивание PDF возвращает
  ТОТ ЖЕ код (QR остаётся действительным).
- **WHEN** страница проверки получает код в любом из эквивалентных
  начертаний (с дефисами/пробелами, в нижнем регистре)
  **THEN** он нормализуется к каноническому виду перед поиском.

### Requirement: Публичная страница проверки `/verify/<код>`

Страница доступна без входа в кабинет и показывает РОВНО:
тип документа, дату выдачи, ФИО держателя в маскированном виде
(«Смирнова А. В.») и статус.

- **WHEN** код существует, справка не отозвана и не истекла
  **THEN** страница показывает зелёный статус «Документ действителен»,
  тип документа, дату выдачи и маскированное ФИО; полное имя, оценки,
  контакты и прочие данные НЕ отображаются нигде на странице.
- **WHEN** справка отозвана сотрудником
  **THEN** страница показывает красный статус «Отозван» (тип, дата и
  маскированное ФИО остаются видимыми).
- **WHEN** код не найден, истёк, имеет неверный формат или справка
  вышла из реестра
  **THEN** страница показывает нейтральный статус «Документ не найден»
  без каких-либо полей документа; неверный формат НЕ отличим от
  отсутствия кода (нет ответа «неверный формат»).
- **WHEN** страница отрисована
  **THEN** на ней есть плашка «Концепт для конкурса» и подсказка
  «Как проверить документ»; работает на 360 px и 1440 px.

### Requirement: Rate limit перебора кодов

Подбор кодов на публичной странице ограничен.

- **WHEN** с одного IP за окно `VERIFY_RATE_WINDOW_MS` поступает более
  `VERIFY_RATE_MAX_ATTEMPTS` обращений к странице проверки
  **THEN** дальнейшие обращения получают состояние «Слишком много
  попыток» (нейтральный текст без статуса документа) до окончания окна.

### Requirement: PDF-шаблон справки

PDF справки строится собственным писателем DIG-27 (кириллица —
векторными глифами, без вложенных шрифтов) и содержит: шапку
вымышленного вуза, номер, дату выдачи, ФИО, программу, курс, форму
обучения, назначение, отметку «электронный документ», код проверки
текстом и сканируемый QR-код со ссылкой на `/verify/<код>`.
Документ детерминирован при равных входах и несёт плашку
«Концепт для конкурса».

- **WHEN** владелец (STUDENT) открывает выполненную заявку типа
  CERTIFICATE и скачивает PDF
  **THEN** ответ `application/pdf` содержит все обязательные реквизиты
  и QR, кодирующий URL `/verify/<код>` этой справки.
- **WHEN** PDF запрошен анонимом (миддлварь), сотрудником или по чужому
  номеру заявки
  **THEN** ответ — единый 404 без раскрытия причины (попытка пишется
  в аудит).

### Requirement: Отзыв справки сотрудником

- **WHEN** сотрудник (STAFF) отзывает код справки студента СВОЕГО
  факультета через `POST /api/staff/certificates/revoke`
  **THEN** статус на странице проверки меняется на «Отозван» сразу —
  при следующем открытии страницы (без кэша).
- **WHEN** отзыв пытается выполнить студент или сотрудник ЧУЖОГО
  факультета, либо код не существует
  **THEN** ответ — единый 404, попытка пишется в аудит
  (ROLE_MISMATCH / OWNERSHIP_DENIED / NOT_FOUND соответственно);
  повторный отзыв того же кода — идемпотентен (дата отзыва не
  меняется).
