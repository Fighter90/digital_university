# Proposal: экран «Каталог сервисов» (DIG-29)

## Зачем

В аудированном ЛК каталог сервисов — 12 вкладок-зоопарк: студенту 2 курса
магистратуры рекомендуется «Личный кабинет абитуриента», один сервис дублируется
в «Популярном» и «Рекомендуем», названия внешних систем разнородны, в текстах
опечатки («Мои зачетная книжка»). По задаче каталог пересобирается: услуги
деканата и вуза, отфильтрованные под роль и курс студента, единые тексты и
пути внутри кабинета.

## Что

- **Экран `/services`** (Figma «06 · Заявки — каталог»):
  - поиск по каталогу с подсветкой совпадений (`<mark>`);
  - категории пилюлями (6, не 12): Справки, Заявления, Учёба, Финансы и
    стипендии, Общежитие, Помощь — горизонтальный скролл на 360 px;
  - «Избранное и часто используемые» — до 6 закреплённых сервисов,
    звёздочка на карточке, «+ Добавить» (якорь на каталог);
  - «Часто нужно на N курсе» — подборка по курсу студента, без дублей
    с избранным;
  - карточка сервиса: иконка, название, одна строка пользы, срок пилюлей
    («Мгновенно», «2–3 дня», «до 5 дней»), формат (PDF / Бумажная),
    кнопка «Заказать» (→ вход в мастер заказа, `/requests?order=<id>`)
    или «Открыть» (→ страница кабинета: зачётка с мгновенной выпиской,
    расписание, деканат, AI-ассистент).
- **Сервисы не по роли не показываются**: каталог содержит отдельные
  абитуриентские и сотруднические записи, но `servicesForRole('STUDENT')`
  их отфильтровывает — студент не увидит ни одной чужой услуги.
- **Избранное на сервере**: слой данных DIG-12 — `serviceFavorites`
  (owner-scoped по `studentId`), порт и memory-адаптер, лимит 6,
  идемпотентный toggle; сотруднику — отказ с аудитом ROLE_MISMATCH.
- **Точка входа**: CTA «Каталог сервисов» на странице «Заявки и справки»
  (фрейм 06 — шаг потока заявок).

## Правила и допущения (зафиксированы тестами)

- Каталог — вымышленный контент в `src/lib/services-catalog.ts` (чистый
  модуль без серверных импортов): 17 студенческих + 2 отфильтровываемые
  записи (абитуриентская и сотрудническая) для доказательства фильтра.
- Все ссылки каталога — внутренние (`/…`): никакого «зоопарка внешних
  систем»; «Заказать» ведёт в существующий поток заявок, куда мастер
  заказа (DIG-31) встанет как следующий шаг.
- Единообразие текстов — автотест: кавычки только «ёлочки», тире —
  только en-dash в диапазонах («2–3 дня»), без двойных пробелов и
  опечаток-маркеров («зачетная» без ё, «Мои зачетная»), польза — одна
  строка без точки в конце.
- Подборка «Часто нужно» — детерминированная функция курса
  (`picksForCourse`), без дублей с избранным (фильтр в слое данных).
- Мгновенная услуга «Выписка из зачётной книжки» открывает зачётку
  DIG-27, где выписка PDF скачивается сразу (без заявки).
- Сотрудник, открывший `/services` напрямую, видит пустое состояние
  «Доступно студентам» + аудит ROLE_MISMATCH (как у зачётки).

## Отклонения от текста задачи (обоснованные)

- «12 вкладок» аудита → 6 категорий пилюлями — прямо по задаче
  («Категории пилюлями (5–6, не 12)»).
- «Популярное» и «Рекомендуем» аудита объединены в «Часто нужно на
  N курсе» — по задаче подборка одна и без дублей; «Популярное» без
  источника данных (нет статистики заказов в прототипе) не заводим.
- «+ Добавить» — ссылка-якорь на каталог (`#catalog`), а не модальный
  пикер: звёздочка на любой карточке добавляет сервис; пикер без
  макета не изобретаем.

## Вне скоупа

- Мастер заказа услуги (DIG-31, Figma «09») — «Заказать» пока ведёт на
  `/requests?order=<id>` (список заявок читает параметр позже).
- Prisma-модель избранного: прототип работает на memory-адаптере DIG-12,
  Prisma-адаптер порта — общий трек (DIG-10/50); сигнатуры порта уже
  owner-scoped и переносятся 1:1.
- Скриншот-верификация по Figma REST API — токен не задан, вёрстка по
  описанию фрейма и токенам DIG-13, сверка скриншотами Playwright.
