# DIG-63 — Фича: живая ICS-подписка расписания и дедлайнов

## Зачем

Тренд Product Hunt: календарь на Lock Screen и подписки на события
(Calendarly, Stitch.ai). У студента уже был «экспорт сессии в календарь»
(DIG-28) — файл-снимок, который устаревает в момент скачивания: перенос
пары деканатом не попадает в уже добавленный календарь. Подписка (ics-URL)
решает это по-настоящему: календарный клиент сам периодически перечитывает
фид, и любое изменение расписания оказывается в системном календаре
студента без его участия.

## Что сделано

- **Живая подписка вместо скачивания.** Экран «Сессия» отдаёт
  персональную подписанную ссылку `/api/calendar/ics?token=…` (карточка
  с копированием вместо кнопки-файла). Роут `/api/session/ics` удалён —
  `GET /api/calendar/ics` — единственная поверхность ICS.
- **Состав фида**: пары группы студента за текущий семестр (включая
  отменённые — с пометкой «Отменена» и причиной переноса в описании) и
  ВСЕ контрольные точки сессии группы (экзамены, зачёты, пересдачи — это
  и есть «дедлайны» главной). Сборка фида — на каждый запрос: изменения
  деканатом видны при следующем обновлении подписки клиентом.
- **Токен ссылки**: `v1.<tokenId>.<hmac>` — 128-битный случайный nonce +
  HMAC-SHA256 с секретом `ICS_TOKEN_SECRET` (зарезервирован в
  `.env.example` с DIG-7; локально — fallback на `AUTH_SECRET`, оба
  серверные). В URL нет studentId и секрета; подделка отсекается
  парсером (timingSafeEqual) до обращения к хранилищу.
- **Выдача и отзыв.** Одна активная подписка на студента: повторный визит
  возвращает ту же ссылку (календарь подписчика не ломается). Выход из
  кабинета (оба server action'а, «Выйти» и «со всех устройств») удаляет
  строку подписки — прежняя ссылка умирает навсегда, новый вход получает
  новый tokenId. Сотруднику подписка не выдаётся (null + аудит
  ROLE_MISMATCH).
- **Публичный путь** `/api/calendar/ics` в route-guard: календарные
  клиенты не отправляют cookies; доступ держится на bearer-токене.
  Любой отказ — единый 404 (uniform not-found, нет оракула существования),
  ответ `private, no-store`.
- **Изоляция**: строка подписки ищется по tokenId (осознанное исключение
  из owner-scope по образцу `findCertificateByCode` DIG-47), владелец
  строки задаёт скоуп фида — чужая подписка отдаёт только свою группу;
  studentId/email/ФИО через контракт фида не проходят.

## Non-goals

- Веб-календарь внутри кабинета (экраны расписания — DIG-21/22/23).
- Ротация ссылки по кнопке и «отозвать все подписки» в настройках —
  кандидат в отдельную задачу (порт и адаптер уже готовы).
- PostgreSQL-адаптер порта данных (DIG-10): подписка добавлена в порт
  `DataDb` и in-memory адаптер, как остальные данные прототипа.
- Push/письма о дедлайнах (DIG-19 покрывает каналы уведомлений).
