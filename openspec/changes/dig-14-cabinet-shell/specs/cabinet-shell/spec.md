# Delta: cabinet-shell (DIG-14)

## ADDED Requirements

### Requirement: Защищённый каркас кабинета

Приложение ДОЛЖНО предоставлять общий лэйаут маршрутов `(cabinet)`, который
перед отрисовкой проверяет сессию пользователя серверной функцией
`requireUser()` и отдаёт данные только этой сессии.

#### Scenario: сессия проверяется до рендера

- **WHEN** пользователь открывает любой маршрут группы `(cabinet)`
- **THEN** layout вызывает `await requireUser()` до рендера Shell и передаёт
  только безопасные поля (имя, группа, e-mail) в клиентские компоненты.

### Requirement: Верхняя панель

Приложение ДОЛЖНО показывать верхнюю панель 72 px (белая, с blur, нижняя
граница) с вымышленным логотипом «Цифровой деканат», кнопкой поиска
«Найти пару, преподавателя, справку…» (открывается по ⌘K/Ctrl+K), кнопкой
AI, колокольчиком с точкой непрочитанных, аватаром с меню (Профиль,
Настройки, Выйти) и всегда заметной плашкой «Концепт для конкурса».

#### Scenario: панель и её элементы видны

- **WHEN** пользователь открывает кабинет на 1440 px
- **THEN** видны логотип, поиск с подсказкой «⌘K», AI, колокольчик с числом
  непрочитанных, аватар и плашка «Концепт для конкурса».

#### Scenario: поиск открывается с клавиатуры

- **WHEN** пользователь нажимает ⌘K или Ctrl+K (или кнопку поиска)
- **THEN** открывается диалог поиска с полем «Найти пару, преподавателя,
  справку…», Escape закрывает диалог, фокус не покидает его.

#### Scenario: меню пользователя доступно с клавиатуры

- **WHEN** пользователь фокусирует аватар и нажимает Enter, затем Escape
- **THEN** открывается меню с пунктами Профиль, Настройки, Выйти; Escape
  закрывает меню и возвращает фокус на аватар.

### Requirement: Боковое меню

Приложение ДОЛЖНО показывать боковое меню: ≥1024 px — полное, 212 px,
пункты Главная, Расписание, Успеваемость, Заявки и справки, Уведомления
(счётчик), Связь с деканатом, AI-ассистент, разделитель, Профиль; активный
пункт — мягкий коралловый фон; под меню карточка «Ближайший дедлайн».
768–1023 px — то же меню, свёрнутое до иконок.

#### Scenario: активный раздел подсвечен

- **WHEN** пользователь открывает `/notifications`
- **THEN** пункт «Уведомления» имеет `aria-current="page"` и коралловый фон,
  остальные пункты активными не помечены.

#### Scenario: дедлайн виден на десктопе

- **WHEN** пользователь открывает кабинет на ≥1024 px
- **THEN** под меню видна карточка «Ближайший дедлайн» (вымышленные данные).

### Requirement: Мобильная навигация

Приложение ДОЛЖНО на ширине <768 px (минимум 360) скрыть боковое меню и
показать нижний таб-бар «Главная, Расписание, Оценки, Заявки, Ещё» с
отступом `env(safe-area-inset-bottom)`, а также плавающую круглую кнопку
AI над таб-баром. Активная вкладка синхронизирована с активным разделом:
разделы из «Ещё» подсвечивают вкладку «Ещё».

#### Scenario: нет горизонтального скролла на 360 px

- **WHEN** страница кабинета открыта во вьюпорте 360×800
- **THEN** `scrollWidth ≤ clientWidth` (горизонтального скролла нет),
  боковое меню скрыто, видны таб-бар и плавающая AI-кнопка.

#### Scenario: вкладка «Ещё» активна для дочерних разделов

- **WHEN** пользователь открывает `/notifications` или `/more` на мобильном
- **THEN** вкладка «Ещё» помечена `aria-current="page"`.

### Requirement: Доступность каркаса

Каркас ДОЛЖЕН быть доступен с клавиатуры: первый таб-стоп — skip-link
«К содержимому», который переводит фокус в основной регион `#main-content`.

#### Scenario: skip-link работает

- **WHEN** пользователь загружает кабинет и нажимает Tab, затем Enter
- **THEN** skip-link получает фокус, после Enter фокус оказывается в
  `#main-content`.

### Requirement: Счётчик уведомлений обновляется без перезагрузки

Приложение ДОЛЖНО показывать число непрочитанных уведомлений (SSR-значение
из серверного источника, доступного только текущей сессии) и обновлять его
не реже раза в 60 секунд без перезагрузки страницы.

#### Scenario: значение обновляется за интервал

- **WHEN** источник счётчика меняется с 3 на 5 и проходит 60 секунд
- **THEN** бейдж на колокольчике показывает 5 без перезагрузки страницы.
