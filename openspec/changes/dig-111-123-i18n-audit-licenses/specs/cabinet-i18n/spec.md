# cabinet-i18n — delta (DIG-111/DIG-123)

## ADDED Requirements

### Requirement: Словари проходят рантайм-аудит переводов

Требование «Словари проходят рантайм-аудит переводов» — обязательное (MUST):
Словари `src/lib/i18n/{ru,en}.ts` проверяются автоматическими правилами
качества: парность ключей 1:1, паритет плейсхолдеров `{name}` между локалями,
отсутствие незакрытых фигурных скобок, EN-значения без кириллицы (кроме
двуязычных `locale.*`), RU-значения без латинских слов-калек (кроме
закрытого списка разрешённой латыни), без двойных пробелов внутри значений.
Правила живут в юнит-тесте и скрипте-отчёте; глоссарий терминов и список
исключений публикуются в TRANSLATION-AUDIT.md.

#### Scenario: Аудит зелёный на консистентных словарях

- **WHEN** выполняются `npx vitest run tests/i18n-audit.test.ts`
  и `node scripts/i18n-audit.mjs`
- **THEN** все проверки проходят, скрипт завершается с кодом 0 и
  перезаписывает TRANSLATION-AUDIT.md сводкой без расхождений

#### Scenario: Новая калька ломает аудит

- **WHEN** в RU-словарь добавляют значение с латинским словом вне
  разрешённого списка (например «login»)
- **THEN** юнит-тест падает с указанием ключа, скрипт-аудит возвращает код 1

## MODIFIED Requirements

### Requirement: RU — канон без изменений

Требование «RU — канон без изменений» — обязательное (MUST): Прежние
RU-строки интерфейса равны прежним байт-в-байт, КРОМЕ закрытого списка
исправлений DIG-111 (латинские кальки и грамматика: «Отправить на email» →
«Отправить на почту», «ФИО, email или телефон…» → «ФИО, эл. почта или
телефон…», «Проверьте ФИО, email или телефон и попробуйте ещё раз.» →
«…эл. почту…», «Email виден преподавателям» → «Эл. почта видна
преподавателям», канал «Email» → «Почта», «visa-центров — со суммой» →
«визовых центров — с суммой») и двойных пробелов в `transcript.groupCourse`
и `transcript.semesterLine`. EN-словарь и EN-каталоги не содержат кириллицы
(кроме осознанно двуязычных ключей `locale.*`).

#### Scenario: RU-рендер вне списка правок не меняется

- **WHEN** cookie `du-locale` отсутствует или `ru`
- **THEN** рендер всех поверхностей совпадает с прежним, кроме
  перечисленных в списке строк; юнит- и e2e-тесты обновлены синхронно
  со словарём

#### Scenario: EN без кириллицы и без терминологических расхождений

- **WHEN** локаль `en`
- **THEN** словарь не содержит кириллицы вне `locale.*`, термины
  согласованы: МСП → SME (меню и заголовок), ДПО → continuing education
  (меню и заголовок), заявление → application (слово statement в словаре
  не используется)
