# Delta-spec: staff-cabinet — кабинет сотрудника деканата

## ADDED Requirements

### Requirement: Роль и доступ к экранам сотрудника

Экраны `/staff*` доступны только роли STAFF.

- **WHEN** студент (подписанный role-hint STUDENT) или пользователь без
  валидного role-hint открывает любой путь `/staff*`
  **THEN** middleware отвечает HTTP 403 (не redirect), данные не
  рендерятся; серверная гарда страниц повторно проверяет роль по живой
  сессии и уводит не-сотрудника на `/dashboard`.
- **WHEN** аноним открывает `/staff*`
  **THEN** он перенаправляется на `/login?next=…` (как и весь кабинет).
- **WHEN** сотрудник обращается к APIstaff-эндпоинтам с ролью STUDENT
  **THEN** ответ — единый 404 без раскрытия существования объектов,
  попытка пишется в аудит.

### Requirement: Скоуп факультета

Сотрудник видит и меняет только данные студентов своего факультета.

- **WHEN** сотрудник открывает очередь заявок или обращения
  **THEN** в списках только заявки/обращения студентов его факультета
  (факультет берётся из Staff-строки сессии, никогда из ввода).
- **WHEN** сотрудник запрашивает заявку/обращение студента чужого
  факультета или несуществующий номер
  **THEN** он получает одинаковый null/404, попытка пишется в аудит
  (OWNERSHIP_DENIED / NOT_FOUND), интерфейс состояния не различает.

### Requirement: Очередь заявок `/staff/requests`

- **WHEN** сотрудник открывает очередь
  **THEN** видит заявки, сгруппированные по статусам, с типом, номером,
  студентом (ФИО, группа), датой подачи и меткой срока по SLA.
- **WHEN** у открытой заявки статус открытый (SUBMITTED / IN_PROGRESS /
  NEEDS_REVISION) и прошло больше SLA-дней её типа с момента подачи
  **THEN** строка подсвечена как просроченная («Просрочено», N дн.);
  SLA-дни: справка — 3, заявление — 5, практика и общежитие — 7,
  прочее — 5.
- **WHEN** применён фильтр по типу заявки
  **THEN** остаются только заявки этого типа.
- **WHEN** применён фильтр по сроку `overdue` / `today` / `week`
  **THEN** остаются просроченные / с дедлайном сегодня / с дедлайном
  в течение 7 дней (только открытые статусы).
- **WHEN** сотрудник нажимает «Взять в работу» у заявки в статусе
  SUBMITTED
  **THEN** статус становится IN_PROGRESS, исполнителем записывается
  сотрудник, в историю пишется событие, студенту — уведомление.

### Requirement: Карточка заявки сотрудника `/staff/requests/[номер]`

- **WHEN** сотрудник открывает карточку заявки своего факультета
  **THEN** видит данные студента (ФИО, группа, курс, программа, номер
  зачётки; email/телефон только при разрешённой видимости), параметры
  заявки и историю событий.
- **WHEN** сотрудник меняет статус кнопкой
  **THEN** доступны только разрешённые переходы: SUBMITTED →
  IN_PROGRESS / NEEDS_REVISION / REJECTED; IN_PROGRESS → COMPLETED /
  NEEDS_REVISION / REJECTED; NEEDS_REVISION → IN_PROGRESS / REJECTED;
  COMPLETED и REJECTED — терминальные.
- **WHEN** выбраны «Нужна доработка» или «Отклонить»
  **THEN** причина обязательна (непустая, ≥ 5 символов после трима);
  без неё форма возвращает ошибку и ничего не меняет.
- **WHEN** переход выполнен
  **THEN** атомарно: обновлена строка заявки (+ исполнитель, если не
  задан), в историю добавлено событие с актёром-сотрудником и
  комментарием, студенту записано уведомление с ссылкой на карточку.
- **WHEN** заявка — CERTIFICATE в статусе COMPLETED
  **THEN** доступна кнопка «Сформировать PDF»; PDF повторно отдаёт ТОТ ЖЕ
  код проверки (QR остаётся действительным).
- **WHEN** сотрудник открывает несуществующий или чужой (другой
  факультет) номер
  **THEN** единая 404.

### Requirement: Обращения `/staff/appeals`

- **WHEN** сотрудник открывает список обращений
  **THEN** видит обращения студентов факультета с темой, студентом,
  статусом и последней активностью; новые (OPEN) — первыми.
- **WHEN** сотрудник открывает обращение
  **THEN** видит чат (сообщения студента и сотрудников) и поле ответа
  с кнопками шаблонов ответа; шаблон подставляет текст в поле.
- **WHEN** сотрудник отправляет ответ (непустой текст)
  **THEN** сообщение сохраняется от имени сотрудника, обращение
  становится ANSWERED, студент получает уведомление «Ответ деканата».
- **WHEN** сотрудник нажимает «Решено»
  **THEN** обращение закрывается (CLOSED), студент получает уведомление
  «Обращение решено»; закрытое обращение доступно только для чтения.

### Requirement: Объявления `/staff/announcements`

- **WHEN** сотрудник открывает раздел
  **THEN** видит форму создания (аудитория: факультет или группа; группа
  выбирается только из групп своего факультета), живой предпросмотр и
  список своих опубликованных объявлений.
- **WHEN** отправлена форма с непустыми заголовком и текстом и валидной
  аудиторией
  **THEN** объявление сохраняется с факультетом и (для группы) проверенной
  группой; появившееся объявление видно в списке раздела.
- **WHEN** выбрана группа, которой нет у студентов факультета
  **THEN** форма возвращает ошибку, ничего не сохраняется.

### Requirement: Сводка `/staff`

- **WHEN** сотрудник открывает сводку
  **THEN** видит: заявок сегодня (поданных с начала текущих суток),
  среднее время ответа в часах (по событиям сотрудников; без данных —
  прочерк), просрочено по SLA, счётчики открытых статусов со ссылками в
  очередь и число открытых обращений.

### Requirement: Уведомление студенту при действиях сотрудника

- **WHEN** сотрудник меняет статус заявки, отвечает на обращение или
  закрывает его
  **THEN** уведомление студенту записывается тем же вызовом слоя данных,
  что и само действие (доступно студенту в ленте немедленно, < 60 с),
  с типом REQUEST/SYSTEM и ссылкой в кабинет; матрица каналов и тихие
  часы студента на события деканата не влияют.

### Requirement: Навигация по роли

- **WHEN** в кабинете сессия сотрудника
  **THEN** боковое меню и мобильный таб-бар показывают разделы сотрудника
  (Сводка, Заявки, Обращения, Объявления), логотип ведёт на `/staff`;
  на всех экранах сотрудника общий Shell и плашка «Концепт для конкурса».
