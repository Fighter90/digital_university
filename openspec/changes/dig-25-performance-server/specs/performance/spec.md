# Delta: performance (DIG-25) — серверные данные успеваемости

## ADDED Requirements

### Requirement: Накопленная оценка дисциплины

Слой данных ДОЛЖЕН возвращать по каждой дисциплине текущего студента
накопленную оценку (Σ(нормированный вес × доля максимума) по выставленным
элементам), минимально гарантированную (несданные элементы — нули) и
максимально возможную (несданные — на максимум) в процентах 0–100. Веса
нормируются на сумму весов плана контроля дисциплины; при пересдаче
элемента учитывается последняя оценка по дате; элементы с maxScore ≤ 0
исключаются из плана. Оценок нет → накопленная `null`, границы 0 и 100.

#### Scenario: частично сданная дисциплина

- **WHEN** студент сдал проект на 85 из 100 (вес 0.3), тест и экзамен
  впереди (веса 0.2 и 0.5)
- **THEN** накопленная = 25.5, минимально гарантированная = 25.5,
  максимально возможная = 95.5.

#### Scenario: дисциплина без оценок

- **WHEN** по дисциплине оценок нет
- **THEN** накопленная `null`, минимально гарантированная 0, максимально
  возможная 100, семестр не определён.

#### Scenario: завершённая дисциплина

- **WHEN** все элементы плана оценены
- **THEN** итог = арифметическое округление накопленного процента до
  целого (86.5 → 87), минимальная = максимальная = накопленная, кредит
  зачтён при итог ≥ 60.

### Requirement: GPA за семестр и за всё время

Слой данных ДОЛЖЕН считать GPA средневзвешенно кредитами дисциплин:
значение завершённой дисциплины — округлённый итог, идущей — накопленная.
Семестр дисциплины — по московскому учебному календарю (дата последней
оценки). Дополнительно ДОЛЖНЫ быть возвращены GPA за всё время, GPA и
метка текущего семестра, GPA и метка предыдущего семестра и дельта
(текущий − предыдущий; не с чем сравнивать → `null`).

#### Scenario: дельта к прошлому семестру

- **WHEN** у студента есть оценки в текущем и предыдущем семестрах
- **THEN** `semesterDelta` = GPA текущего − GPA предыдущего (до 0.01),
  рядом метки обоих семестров.

#### Scenario: первый семестр

- **WHEN** оценок в предыдущем семестре нет
- **THEN** `previousSemesterLabel` и `semesterDelta` — `null`.

### Requirement: Кредиты

Слой данных ДОЛЖЕН возвращать «набрано» (Σ кредитов завершённых дисциплин
с итогом ≥ 60) и «требуется» (240 на программу).

#### Scenario: прогресс кредитов

- **WHEN** студент завершил дисциплины на 5 и 4 кредита с итогами ≥ 60
- **THEN** `credits = { earned: 9, required: 240 }`.

### Requirement: Рейтинг в группе и перцентиль

Слой данных ДОЛЖЕН возвращать место студента по общему GPA среди
студентов его группы с оценками, размер группы, «топ-X%» =
ceil(место/размер×100) и готовую формулировку «Вы входите в N% лучших в
группе». Равные GPA — одно место (competition ranking). Группа из одного
студента — «Вы — единственный студент в группе». Студент без оценок —
рейтинга нет (`null`). Оценки сокурсников используются только внутри
агрегата: чужие строки наружу не выходят.

#### Scenario: человеческая формулировка

- **WHEN** студент второй из пяти по общему GPA
- **THEN** `rating = { rank: 2, groupSize: 5, bestPercent: 40, label:
  'Вы входите в 40% лучших в группе' }`.

#### Scenario: равные GPA

- **WHEN** два студента имеют одинаковый общий GPA
- **THEN** оба на месте 1; следующий — на месте 3.

### Requirement: Долги (пересдачи)

Слой данных ДОЛЖЕН возвращать по RETAKE-сессиям группы: дисциплину, дату
пересдачи, дней до неё и статус — `CLOSED` (итог/накопленная ≥ 60),
`ASSIGNED` (дата сегодня или позже), `OVERDUE` (дата прошла, долг не
закрыт). Активные раньше закрытых, внутри — по дате.

#### Scenario: три статуса долга

- **WHEN** в группе есть прошедшая пересдача по несданной дисциплине,
  будущая пересдача и прошедшая пересдача по дисциплине с итогом ≥ 60
- **THEN** статусы соответственно OVERDUE, ASSIGNED, CLOSED; закрытая
  последняя.

### Requirement: needForTarget — калькулятор цели

`needForTarget(db, ctx, disciplineCode, target)` ДОЛЖЕН вернуть
минимальный балл на экзамене (в шкале элемента и в процентах), при котором
итог с арифметическим округлением станет ≥ target, считая остальные
незакрытые элементы нулями. Статусы: `OK`, `ALREADY_SECURED`,
`EXAM_ALREADY_GRADED`, `UNREACHABLE` (с `bestPossible`), `NO_EXAM_ELEMENT`.

#### Scenario: граница округления

- **WHEN** накопленная 25.5, вес экзамена 0.5 (max 100), target 70
- **THEN** `OK`, `neededScore = 88` (при 87 итог 25.5 + 0.5·87 = 69.0 → 69 <
  70, при 88 итог 69.5 округляется вверх в 70), `guaranteedFinal = 70`.

#### Scenario: дробная цель

- **WHEN** накопленная 25.5, вес экзамена 0.5 (max 100), target 70.5
- **THEN** `OK`, `neededScore = 90` (итог округлённый — целое, «итог ≥ 70.5»
  равносильно «итог ≥ 71»; при 90 итог 70.5 округляется вверх в 71),
  `guaranteedFinal = 71`.

#### Scenario: нет оценок

- **WHEN** по дисциплине оценок нет, вес экзамена 0.6, target 60
- **THEN** `OK`, `neededScore = 100`.

#### Scenario: экзамен уже сдан

- **WHEN** экзаменационный элемент оценён и итог ≥ target
- **THEN** `ALREADY_SECURED`; иначе — `EXAM_ALREADY_GRADED` с итогом и
  баллом экзамена.

#### Scenario: цель недостижима

- **WHEN** даже 100 на экзамене не дают target
- **THEN** `UNREACHABLE` с `bestPossible` — максимумом достижимого.

### Requirement: Скоуп данных текущего студента (IDOR)

Все функции ДОЛЖНЫ получать ctx из живой сессии и скоупить персональные
выборки по `ctx.studentId`, справочники и сессии — по `ctx.groupName`.
Сотрудник (studentId отсутствует) — пустой агрегат / `null` + запись в
аудите `ROLE_MISMATCH`. Дисциплина в needForTarget вне группы ctx —
единообразный `null` с причиной `OWNERSHIP_DENIED` в аудите; некорректный
target (NaN/∞) — `null` без записи в аудит.

#### Scenario: сотрудник

- **WHEN** сотрудник вызывает getPerformance или needForTarget
- **THEN** пустой агрегат / `null`, в AuditLog — `ROLE_MISMATCH`.

#### Scenario: чужая дисциплина

- **WHEN** студент запрашивает дисциплину другой группы
- **THEN** ответ `null` — такой же, как для несуществующей; причина
  (`OWNERSHIP_DENIED`) только в AuditLog.

#### Scenario: чужие оценки не покидают агрегат рейтинга

- **WHEN** студент получает свой агрегат
- **THEN** в ответе нет ни ФИО, ни оценок сокурсников — только его место
  и перцентиль.
