# Proposal: серверная часть успеваемости — накопленные оценки, GPA, кредиты, рейтинг, долги, needForTarget (DIG-25)

## Зачем

Экраны «Успеваемость» (DIG-26), «Зачётная книжка» (DIG-27), «Сессия»
(DIG-28) и калькулятор «что нужно на экзамене» стоят на расчётах, которых
в слое данных ещё нет: накопленная оценка дисциплины (текущая /
максимально возможная / минимально гарантированная), GPA за семестр и за
всё время с дельтой, кредиты «набрано/требуется», рейтинг в группе с
понятной формулировкой («Вы входите в 27% лучших», а не «перцентиль 32»),
долги с датой пересдачи и статусом, и `needForTarget` — балл, который
нужен на экзамене ради целевой оценки, с учётом правил округления.

## Что

- `src/lib/performance-math.ts` — чистые формулы (без серверных
  импортов, покрыты юнит-тестами напрямую):
  - `accumulatedGrade` — накопленная / минимально гарантированная /
    максимально возможная; веса нормируются на план контроля; дедуп
    оценок элемента по дате (пересдача); элементы с maxScore ≤ 0
    исключаются из плана;
  - `semesterKeyOf` / метки / сортировка / предыдущий семестр —
    московский учебный календарь (как `semesterBounds`: осень 1.09–25.01,
    весна 9.02–30.06, июль/август → будущая осень);
  - `weightedAverage`, `roundGrade` (арифметическое округление, половина
    вверх — правило зафиксировано в docs/grading.md);
  - `needForTargetPure` — решение неравенства с учётом округления;
    статусы OK / ALREADY_SECURED / EXAM_ALREADY_GRADED / UNREACHABLE /
    NO_EXAM_ELEMENT; остальные незакрытые элементы считаются нулями
    (гарантированный, а не оптимистичный ответ);
  - `bestPercentFromRank` / `bestPercentLabel` — «Вы входите в N%
    лучших в группе» (N = ceil(место/размер×100)); группа из одного —
    «Вы — единственный студент в группе».
- Порт данных DIG-12 дополнен скоупленными методами (group-scoped):
  `listDisciplinesByGroup` (кредиты), `listDisciplineElementsByGroup`
  (полный план контроля, включая неоценённые элементы),
  `listGradesByGroup` (оценки группы — ТОЛЬКО вход агрегата рейтинга;
  наружу идут место/перцентиль владельца ctx, не чужие строки).
  In-memory адаптер реализует 1:1 (+ `disciplines`/`elements` в seed).
- `src/server/data/performance.ts`:
  - `getPerformance(db, ctx, now)` — агрегат: дисциплины с накопленными
    оценками и статусом кредита, GPA (семестр/всё время/дельта), кредиты
    «набрано/требуется», рейтинг в группе, долги (RETAKE-сессии группы со
    статусами ASSIGNED/OVERDUE/CLOSED);
  - `needForTarget(db, ctx, disciplineCode, target)` — калькулятор цели;
    дисциплина обязана принадлежать группе из ctx: чужая/несуществующая —
    единообразный null, причина в AuditLog (OWNERSHIP_DENIED); сотрудник —
    ROLE_MISMATCH + пустой агрегат/null (тот же контракт, что grades.ts);
  - robustness: дисциплины без справочника синтезируются из оценок
    (1 кредит, план = сданные элементы).
- Демо-сид дополнен (существующие строки не менялись): справочник
  дисциплин ПИ-21/ЭК-11 с кредитами, планы контроля, 4 вымышленных
  сокурсника Анны с итогами весны 2025/26 (рейтинг: Анна 2 из 5 → «Вы
  входите в 40% лучших в группе») и две пересдачи (просроченная и
  закрытая) — на существующих `exm-pi21-4` (будущая пересдача) экраны
  «Сессия»/дедлайны главной не изменились.
- `docs/grading.md` — правила: шкала процентов, арифметическое округление
  итога до целого, отсутствие блокирующих элементов, семестры, кредиты,
  рейтинг/перцентиль, долги, доступ (IDOR).
- Barrel `@/server/data` экспортирует `getPerformance`, `needForTarget`
  и view-типы; типы строк `DisciplineRow`/`DisciplineElementRow`.

## Допущения (зафиксированы тестами)

- Шкала — проценты 0–100 от максимума элемента (сиды DIG-10 пишут
  score/maxScore 100-балльными); итог — округлённый процент. Отдельная
  10-балльная шкала канона (Grade.value 0..10) — задача будущего
  Prisma-адаптера: там уже есть маппинг, формулы слоя данных в процентах.
- Дисциплина относится к семестру по дате последней оценки; GPA идущего
  семестра считается по накопленным (предварительный), завершённого —
  по итогам.
- Кредит зачтён при итог ≥ 60; требуется 240 на программу.
- Блокирующие элементы отсутствуют (правила — docs/grading.md).

## Отклонения от текста задачи (обоснованные)

- Подпись `needForTarget(ctx, disciplineId, target)` из задачи расширена
  до `needForTarget(db, ctx, disciplineCode, target)` — конвенция слоя
  данных DIG-12 (порт инъецируется, тестируется без Next.js; тот же
  приём, что в DIG-21 для `getSchedule`).
- Идентификатор дисциплины — `disciplineCode` (имeyer строки сидов
  DIG-10, по которым связаны оценки/план/сессии; cuid Discipline — дело
  будущего Prisma-адаптера).
- Для «максимально возможной/минимально гарантированной» и рейтинга
  данные дополняются: без полного плана контроля и оценок группы эти
  величины не выводимы — поэтому порт расширен двумя group-scoped
  справочниками и `listGradesByGroup` (использование только внутри
  агрегата рейтинга, проверено тестом изоляции).
