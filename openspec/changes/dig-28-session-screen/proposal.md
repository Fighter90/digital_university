# Proposal: экран «Сессия» (DIG-28)

## Зачем

В аудированном ЛК отдельного экрана сессии нет: экзамены видны только в общем
расписании, допуск и пересдачи — через внешние сервисы и заявки. Экран
`/grades/session` уже связан с экраном «Успеваемость» (DIG-26: ссылка
«Сессия — расписание консультаций и экзаменов» в футере и действия
«К сессии» светофора), но самой страницы нет — сейчас это 404. Задача
закрывает экран Figma «05 · Успеваемость — сессия»: таймлайн экзаменов
и зачётов со статусами допуска, блок пересдач с записью в один клик,
консультации и экспорт всей сессии в календарь.

## Что

- **Шапка** — «Зимняя сессия · 22 декабря – 25 января»: название сезона
  выводится из месяца первой контрольной, диапазон — из дат сессии
  (без хардкода дат), плюс обратный отсчёт «До первого экзамена N дней»
  и кнопка «Добавить всю сессию в календарь» (ICS-файл).
- **Таймлайн экзаменов и зачётов** — дата, время, аудитория, преподаватель
  (из справочника группы), тип (Экзамен/Зачёт) и статус-пилюля:
  «Допущен» (зелёный), «Не допущен» (красный + причина «Не сдано: …»
  и действие «Что сдать» → карточка дисциплины), «Сдано · N» (зелёный),
  «Пересдача» (янтарный, в блоке пересдач).
- **Блок «Пересдачи»** — дисциплина, дата/время, аудитория, примечание,
  кнопка «Записаться»: server action создаёт заявку (STATEMENT,
  «Запись на пересдачу — <дисциплина>») и уведомление. Повторная запись
  идемпотентна: возвращается существующая заявка.
- **Консультации** — из расписания группы (`kind: CONSULTATION`),
  дата, время, аудитория, преподаватель.
- **Подсказка AI** — «Подготовиться к экзамену по …» по ближайшему
  несданному экзамену: ссылка открывает ассистента с контекстом
  (`/ai-assistant?intent=exam-prep&discipline=…`), экран ассистента — DIG-46.
- **Экспорт ICS** — `GET /api/session/ics`: VCALENDAR с экзаменами,
  зачётами и консультациями группы, скоуп по ctx, сотрудник/аноним —
  единый 404. Сборщик календаря — чистая функция `src/lib/ics.ts`.

## Правила и допущения (зафиксированы тестами)

- Статус допуска выводится из плана контроля и оценок студента (те же
  правила, что бейдж допуска DIG-26, docs/grading.md):
  - целевой элемент сессии — элемент плана вида EXAM; если его нет
    (зачёт без экзамена) — последний элемент вида TEST;
  - целевой элемент оценён → «Сдано · N» (N — последняя оценка элемента);
  - все остальные элементы плана сданы → «Допущен»;
  - есть несданные → «Не допущен», причина — перечень несданных элементов
    («Не сдано: Лабораторная 3»); план контроля отсутствует → «Допущен»
    (нет данных, чтобы отказывать).
- Пересдача (kind RETAKE) — отдельный статус «Пересдача»; запись доступна
  только для несостоявшихся пересдач (дата не раньше сегодня) и создаёт
  заявку и уведомление типа REQUEST со ссылкой на заявку.
- Дедуп записи на пересдачу — по точному заголовку заявки (идемпотентность
  кнопки; прототип не хранит ссылку заявка↔экзамен).
- Сотрудник (без studentId): пустой агрегат + аудит ROLE_MISMATCH,
  страница — заглушка «Экран доступен студентам» (как на «Успеваемости»).
- ICS: локальное (плавающее) время событий, экранирование спецсимволов,
  свёртка длинных строк по RFC 5545, детерминирован при фиксированном
  DTSTAMP.

## Отклонения от текста задачи (обоснованные)

- «Сдано · 9» в макете — шкала 10-балльного сида PostgreSQL; в памяти
  прототипа оценки в процентах, пилюля показывает фактическую оценку
  («Сдано · 74»). Формат один — `Сдано · N`.
- «Комиссия» в блоке пересдач в модели прототипа не представлена
  (ExamSession: аудитория + примечание); показывается аудитория и
  примечание деканата. Поле комиссии добавится без изменения экрана,
  когда появится в модели.
- Даты шапки («22 декабря – 25 января») не хардкодятся: выводятся из дат
  сессии группы, поэтому остаются верными на любой демонстрации.

## Вне скоупа

- Экран AI-ассистента с контекстом (DIG-46) — подсказка даёт ссылку.
- Сотруднический вид сессии/ведомости (DIG-48).
- Prisma-адаптер порта (общий трек); экран работает через порт DIG-12.
