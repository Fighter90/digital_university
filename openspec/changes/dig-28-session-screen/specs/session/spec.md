# Delta: session (DIG-28) — экран «Сессия»

## ADDED Requirements

### Requirement: Таймлайн сессии со статусами допуска

Слой данных ДОЛЖЕН возвращать сессию текущего студента одним агрегатом
`getSession(db, ctx)`: контрольные работы группы (ExamSession, скоуп
`ctx.groupName`), статусы допуска по плану контроля и оценкам владельца
ctx, преподавателей из справочника группы, консультации группы из
расписания (`kind: CONSULTATION`). Статусы контрольных:

- целевой элемент плана оценён → «Сдано · N» (последняя оценка элемента);
- остальные элементы плана сданы (или плана нет) → «Допущен»;
- есть несданные элементы → «Не допущен» с причиной «Не сдано: <элементы>»;
- kind RETAKE → «Пересдача».

#### Scenario: не допущен с причиной и действием

- **WHEN** у студента несдана «Лабораторная 3» (элемент плана), а зачёт
  по дисциплине ещё впереди
- **THEN** контрольная со статусом «Не допущен», причина
  «Не сдано: Лабораторная 3», действие ведёт на карточку дисциплины.

#### Scenario: скоуп и роли

- **WHEN** студент группы A запрашивает сессию
- **THEN** возвращаются только контрольные группы A; сотрудник получает
  пустой агрегат + запись AuditLog (ROLE_MISMATCH).

#### Scenario: шапка экрана

- **WHEN** сессия группы датируется декабрём–январём
- **THEN** заголовок «Зимняя сессия · <d MMMM> – <d MMMM>» (выводится из
  дат, не хардкодится) и обратный отсчёт «До первого экзамена N дней».

### Requirement: Запись на пересдачу

`createRetakeRequest(db, ctx, examId)` ДОЛЖЕН проверять владельца
(экзамен существует, принадлежит группе ctx, kind RETAKE и ещё не
состоялся) и создавать заявку STATEMENT «Запись на пересдачу —
<дисциплина>» (статус SUBMITTED, событие «Заявка подана через личный
кабинет») и уведомление REQUEST со ссылкой на заявку. Чужой/
несуществующий examId, не-пересдача и прошедшая пересдача —
единообразный null + AuditLog (различие причины только в аудите).
Повторный вызов возвращает существующую заявку (created: false).

#### Scenario: запись создаёт заявку и уведомление

- **WHEN** студент записывается на пересдачу по своей группе
- **THEN** в «Моих заявках» появляется SUBMITTED-заявка, в уведомлениях —
  REQUEST со ссылкой `/requests/<номер>`.

#### Scenario: прошедшая пересдача не даёт записаться

- **WHEN** дата пересдачи раньше сегодняшней
- **THEN** экран показывает «Пересдача уже состоялась — запись закрыта»,
  вызов слоя возвращает null (заявки нет).

#### Scenario: IDOR

- **WHEN** студент передаёт examId контрольной чужой группы
- **THEN** null + AuditLog OWNERSHIP_DENIED; страница отвечает ошибкой
  формы без раскрытия существования.

### Requirement: Экспорт сессии в календарь

`GET /api/session/ics` ДОЛЖЕН отдавать VCALENDAR (text/calendar;
charset=utf-8; attachment; Cache-Control private, no-store) с событиями
контрольных и консультаций группы ctx. Сотрудник — единый 404 JSON,
аноним недопускается middleware.

#### Scenario: ICS корректен

- **WHEN** студент скачивает календарь сессии
- **THEN** файл содержит BEGIN:VCALENDAR/VEVENT на каждую контрольную и
  консультацию, спецсимволы экранированы, время — плавающее локальное.

### Requirement: Консультации и подсказка AI

Экран ДОЛЖЕН показывать консультации группы (дата, время, аудитория,
преподаватель) и подсказку AI «Подготовиться к экзамену по <дисциплина>»
по ближайшей несданной контрольной со ссылкой на ассистента с контекстом
(`/ai-assistant?intent=exam-prep&discipline=<код>`).

#### Scenario: подсказка по ближайшему экзамену

- **WHEN** у студента есть будущая не сданная контрольная
- **THEN** подсказка называет дисциплину и открывает ассистента с её кодом.
