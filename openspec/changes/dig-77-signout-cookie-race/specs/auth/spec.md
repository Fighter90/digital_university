# DIG-77 — delta: Аутентификация и доступ

## MODIFIED Requirement: Скользящее продление авторизационных кук

Middleware пере-выставляет `__Host-session` и `__Host-role` (прежние
значения, полный Max-Age) только на документ-навигациях (GET/HEAD,
Fetch-Metadata `Sec-Fetch-Dest: document`) по разрешённым путям вне
экранов входа. Запросы без Fetch-Metadata (легаси-клиенты) трактуются
как документ-навигации (fail-open). RSC-запросы (prefetch и
fetch-навигация, `Sec-Fetch-Dest: empty`) и экраны `/login`,
`/forgot-password` куки не продлевают никогда. Мутации (POST/PUT/
DELETE/PATCH) не продлевают — правило DIG-55 сохранено.

#### Scenario: Prefetch-ответ не воскрешает куки после выхода

- **WHEN** браузер с живой сессией держит в полёте RSC-prefetch-запросы
  (например, prefetch-шторм дашборда) и в этот момент выполняется
  sign-out action, очистивший обе куки (`Max-Age=0`)
- **THEN** завершившиеся ПОСЛЕ очистки prefetch/RSC-ответы не содержат
  Set-Cookie авторизационных кук, и в браузере после обработки всех
  ответов кук `__Host-session`/`__Host-role` нет

#### Scenario: Экран входа не возвращает живые куки

- **WHEN** sign-out action редиректит на `/login?signedOut=1`, и
  RSC-навигация экрана входа уходит от браузера гонкой с применением
  куки-очистки (запрос ещё несёт прежнюю куку)
- **THEN** ответ `/login*` не пере-выдаёт авторизационные куки, и
  последний Set-Cookie для обеих кук остаётся очисткой из ответа action'а

#### Scenario: Активный пользователь продлевает куки документ-навигацией

- **WHEN** браузер с живой сессией выполняет GET-переход документом
  (`Sec-Fetch-Dest: document`) по разрешённой странице вне `/login*`
- **THEN** куки пере-выставляются с прежними значениями и полным
  Max-Age (поведение review round 3 DIG-11 сохранено)

#### Scenario: Клиент без Fetch-Metadata сохраняет продление

- **WHEN** GET-запрос не несёт `Sec-Fetch-Dest` (старый браузер, curl)
- **THEN** запрос трактуется как документ-навигация и куки продлеваются
  (fail-open; детерминированность выхода обеспечена современными
  браузерами, которые Fetch-Metadata отправляют всегда)

## MODIFIED Requirement: Выход удаляет обе куки

Оба sign-out action'а (`signOutAction`, `signOutAllDevicesAction`)
очищают `__Host-session` и `__Host-role` (`Max-Age=0`, name/Path/атрибуты
совпадают с выдачей, Domain отсутствует). Проверка удаления обеих кук —
обязательная часть приёмки (e2e), включая состояние после «Назад».

#### Scenario: «Выйти» из настроек удаляет обе куки

- **WHEN** авторизованный пользователь в «Настройки → Безопасность»
  нажимает «Выйти на всех устройствах»
- **THEN** `signOutAllDevicesAction` отзывает все сессии пользователя и
  очищает обе куки; браузер на `/login?signedOut=1` не имеет ни
  `__Host-session`, ни `__Host-role`

#### Scenario: После «Назад» куки не воскресают

- **WHEN** после успешного выхода пользователь возвращается «Назад» на
  защищённый экран
- **THEN** middleware без сессии отдаёт редирект на `/login?next=…`, и
  в браузере по-прежнему нет ни одной куки `__Host-*`
