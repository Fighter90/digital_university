# DIG-77 — Баг: «Выйти» не удаляет куку __Host-session (гонка prefetch/RSC с очисткой)

## Зачем

Регресс desktop 18.11 (e2e `auth.spec:188`): «Выйти» → `/login?signedOut=1`
с сообщением, но `__Host-session` **остаётся** в браузере («кука не удалена»,
тест ждёт `toBeUndefined`). «Назад» — и куки снова на месте: сессия
«формально жива» в браузере.

**Диагностика (CDP-трейс `Network.responseReceivedExtraInfo` на
ostrovok.store и на локальной прод-сборке):** оба sign-out action'а и
атрибуты куки-очистки корректны (обе куки, `Max-Age=0`, тот же name/Path,
без Domain). Причина — **гонка последнего Set-Cookie**:

1. POST sign-out action'а завершается 303-ответом с куками-очисткой.
2. Параллельно (prefetch-шторм дашборда — десятки RSC-prefetch-запросов,
   ушедших с живыми куками, и RSC-навигация на `/login?signedOut=1`,
   выпущенная роутером до применения очистки) завершаются GET-запросы,
   **уже несшие живые куки**.
3. Sliding re-issue (DIG-11 review round 3) пере-выдаёт живые
   `__Host-session` + `__Host-role` на каждом таком ответе — и **последний
   Set-Cookie побеждает** куку-очистку (порядок применения ответов не
   гарантирован). Обе куки воскресают с тем же (уже осиротевшим в БД)
   токеном; e2e-проверка удаления падает.

Fix DIG-55 (исключение мутаций) закрывал POST-конкуренцию слоёв
middleware/action, но не эти GET-гонки.

## Что сделано

- `shouldSlideAuthCookies` (route-guard.ts) — два новых правила:
  1. **Продление — только документ-навигации** (`Sec-Fetch-Dest: document`).
     Внутренние заголовки роутера (`rsc`, `next-router-prefetch`) Next.js
     зачищает из `request.headers` middleware (задокументировано:
     «RSC requests and rewrites», proxy.mdx), поэтому fetch-запрос
     отличаем по браузерному Fetch-Metadata. У клиентов без
     Fetch-Metadata — fail-open (слайдим, совместимость с DIG-11 renewal).
  2. **Экраны входа не слайдят никогда** (`/login`, `/forgot-password`):
     sign-out сам приводит на `/login` — его ответ не должен уносить
     живые auth-куки ни при каком раскладе.
- Sliding renewal для реальной активности сохранён: документ-навигации
  защищённых и публичных (не auth) экранов продлевают куки как раньше
  (вход, F5, закладка, переходы по внешним ссылкам — любая сессия
  начинается документом).
- e2e `auth.spec` DIG-55-группа: добавлена проверка удаления
  `__Host-role` (раньше проверялась только `__Host-session`) и проверка
  отсутствия всех `__Host-*` после «Назад» (пин гонки DIG-77); добавлен
  сценарий выхода из настроек («Выйти на всех устройствах»,
  `signOutAllDevicesAction` — второй sign-out action, e2e-покрытия не имел).
- Юнит `auth-core`: cleared-спеки обеих кук (`buildClearedSessionCookie`
  и `buildClearedRoleHintCookie`) — имя/Path совпадают с выдачей,
  `Max-Age=0`, HttpOnly/Secure/SameSite=Lax (DoD «cleared-спеки удаляют
  обе куки»; роль-кука ранее не была покрыта).
- `.env.example`: убран мёртвый `SESSION_SECRET` (в коде не читается),
  добавлен реальный `AUTH_SECRET` (HMAC роли-подсказки; без него
  middleware fail-closed, а путь роли-куки в e2e не активен).
- Попутная стабилизация **в том же файле** `e2e/auth.spec.ts` (требование
  DoD «auth.spec green»): три чип-логина DIG-18 переведены на каноничный
  паттерн файла (ждать подстановку значений чипом до сабмита — гонка
  с рендером документирована в самом файле со времён DIG-55); ассерт
  лендинга сотрудника обновлён на продуктовое поведение 63db150
  (сотрудник → `/staff`, «Сводка деканата») — ассерт остался со
  времён, когда сотрудника вело на `/dashboard`, и ломал группу.

## Non-goals

- Не трогаем саму механику sliding renewal для документов и store-side
  sliding (`resolveSession`/`touchSession`) — деградации продления нет.
- Не меняем атрибуты кук (`buildCleared*Cookie` корректны: очистка
  совпадает по name/Path/Domain с выдачей — проверено юнитом).
- Не трогаем IP-лимитер входа (30/15 мин) и пер-аккаунтную блокировку:
  во время отладки они создавали шум локальных прогонов, но к багу
  отношения не имеют.
- Остаточная теоретическая гонка (документ-навигация, отправленная
  ровно в момент клика «Выйти») принята: требует одновременного клика
  пользователем, а воскресшая кука — осиротевший токен (сессия в БД
  удалена, все защищённые роуты отвечают редиректом на /login).

## Риски

- Пользователи, живущие в SPA без единой полной перезагрузки 7 суток,
  потеряют cookie-sliding (store-side sliding остаётся; hard-logout на
  7-й день возможен только при нулевой документ-навигации за неделю).
  Осознанный трейд-офф против детерминированного выхода (безопасность).
