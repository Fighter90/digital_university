# Proposal: экран «Поиск по кабинету» — командная палитра ⌘K (DIG-45)

## Зачем

В аудированном ЛК глобальный поиск в шапке находит 30 смешанных результатов по
«стипендия», фильтры по типу работают наоборот, а FAQ тем же словом не
находится вообще. Каркас кабинета (DIG-14) оставил заглушку-диалог: палитра
открывается по ⌘K, но ничего не ищет.

## Что

- Командная палитра `SearchPalette` по ⌘K / Ctrl+K и кнопке поиска в шапке
  (макет Figma «24 · Поиск ⌘K»): строка ввода, сгруппированные результаты,
  пустое состояние, подвал с «Спросить AI: „<запрос>“».
- Серверный поиск `GET /api/search?q=` — единственный источник результатов.
  Каждая выборка скоупится `requireDataCtx()` (заявки — только свои,
  дисциплины и преподаватели — только своей группы, люди-сотрудники —
  только через данные, которые студент уже видит): IDOR невозможен по
  построению, как в остальном слое данных.
- Группы результатов в фиксированном порядке: **Действия** («Заказать
  справку» — каталог сервисов роли), **Разделы**, **Дисциплины**, **Заявки**
  (по номеру и названию), **Люди** (преподаватели группы, исполнитель заявок,
  свой профиль), **Вопросы и ответы** (вымышленный FAQ-каталог — заготовка
  DIG-38), **Новости** (фид деканата). Не более 6 попаданий на группу.
- Пустое поле: «Недавние запросы» (localStorage, ≤5, с кнопкой «Очистить»)
  и «Популярные действия» (подборка каталога по роли сессии).
- Клавиатура: ↑/↓ — навигация по общему списку результатов с закольцовкой,
  Enter — открыть активное, Tab / Shift+Tab — переход между группами,
  Escape — закрыть (поведение DIG-14 сохранено: фокус возвращается на
  кнопку поиска).
- Мобильный (<768 px): поиск из шапки открывается на весь экран (360 px —
  минимальная ширина проекта), поле ввода закреплено сверху.
- Ответ поиска < 200 мс на сидовых данных (в памяти, без внешних вызовов).

## Non-goals

- Экран FAQ (`/faq`) и экран новостей — DIG-38 / DIG-36: попадания FAQ и
  новостей ведут на существующие страницы (соответственно — место действия,
  общий фид уведомлений).
- FTS/индексы PostgreSQL — пока прототип на memory-адаптере; для Prisma
  достаточно `ILIKE`-поиска по сидовым объёмам.
- Поиск по содержимому заявок/оценок (только номер и название заявки,
  названия дисциплин).
- Полноценный справочник людей — DIG-37/48; «Люди» — только видимые
  студенту имена с честными переходами (расписание, деканат, свой профиль).

## Риски

- Токен Figma не задан — вёрстка по описанию фрейма задачи и токенам
  DIG-13, сверка скриншотами Playwright 1440×900 и 360×800.
- Расширение `ShellUser` ролью — общая поверхность: обновлены контракт
  `resolveShellUser` и его юнит-тест; гейты прогоняются.
