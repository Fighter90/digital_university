# Delta: search (DIG-45) — поиск по кабинету ⌘K

## ADDED Requirements

### Requirement: Скоупированный серверный поиск

Поиск ДОЛЖЕН выполняться только на сервере (`GET /api/search?q=`) в контексте
сессии (`requireDataCtx()`): заявки — только свои (по публичному номеру и
названию), дисциплины и преподаватели — только своей группы, «Люди» — только
имена, уже видимые студенту в кабинете (преподаватели дисциплин группы,
исполнитель его заявок, собственный профиль); аноним — redirect на /login.
Чужие данные недостижимы ни в одной группе; частично введённый или чужой
номер заявки НЕ возвращает чужую заявку.

#### Scenario: чужой номер заявки не находится

- **WHEN** Илья ищет «SR-» + номер заявки Анны (или его префикс)
- **THEN** группа «Заявки» в ответе отсутствует; попытка полного номера
  попадает в AuditLog как OWNERSHIP_DENIED (поведение getRequestByNumber).

#### Scenario: сотрудник не получает студенческих групп

- **WHEN** сотрудник ищет «справка» или «базы данных»
- **THEN** групп «Дисциплины», «Заявки», «Люди» в ответе нет; «Действия»
  содержат только сервисы роли STAFF.

### Requirement: Группы результатов в фиксированном порядке

Результаты ДОЛЖНЫ приходить сгруппированными в порядке: Действия, Разделы,
Дисциплины, Заявки, Люди, Вопросы и ответы, Новости. Пустые группы не
отрисовываются; в группе не более 6 попаданий; внутри группы сначала
совпадения по префиксу названия, затем по вхождению. Матчинг — без учёта
регистра, с фолдингом «ё→е»; запрос короче 2 символов результатов не даёт.
Приёмка: номер заявки находит заявку, ФИО — человека, «справка» — действие
и статью FAQ одновременно.

#### Scenario: «справка» находит действие и статью

- **WHEN** студент ищет «справка»
- **THEN** в «Действиях» есть «Справка об обучении» (href
  `/requests?order=cert-enrollment`), в «Вопросах и ответах» — статья
  про заказ справки; группы разделены заголовками.

#### Scenario: ФИО находит человека

- **WHEN** студент ищет «Иванова»
- **THEN** группа «Люди» содержит преподавателя «Иванова Ирина Игоревна»
  с переходом на расписание; поиск «Анна Ковалёва» находит свой профиль
  (переход /profile, пометка «это вы»).

### Requirement: Пустое поле — недавние и популярные

При пустом запросе палитра ДОЛЖНА показывать «Недавние запросы»
(localStorage, ≤5, дедупликация, кнопка «Очистить») и «Популярные действия»
— сервисы роли сессии; клик по недавнему подставляет запрос и ищет.

#### Scenario: недавний запрос повторно используется

- **WHEN** студент искал «справка», открыл результат и снова открыл палитру
  с пустым полем
- **THEN** чип «справка» есть в «Недавних запросах»; клик по нему
  выполняет поиск без ручного ввода.

### Requirement: Клавиатура и AI-подвал

Навигация ДОЛЖНА работать стрелками ↑/↓ по общему списку результатов с
закольцовкой (aria-activedescendant на списке), Enter открывает активный
результат и закрывает палитру, Tab / Shift+Tab перескакивает на первую
строку следующей/предыдущей группы, Escape закрывает (фокус возвращается
на кнопку поиска — контракт DIG-14). В подале при непустом запросе —
строка «Спросить AI: „<запрос>“» (переход /ai-assistant с параметром q),
достижимая стрелками и Enter.

#### Scenario: Tab переключает группу

- **WHEN** активна первая строка группы «Действия», нажат Tab
- **THEN** активной становится первая строка следующей непустой группы;
  Shift+Tab возвращает назад; Enter открывает активную строку.

#### Scenario: AI-подвал

- **WHEN** введён запрос «стипендия»
- **THEN** в подале видна строка «Спросить AI: «стипендия»», Enter на ней
  ведёт на /ai-assistant?q=стипендия.

### Requirement: Мобильный полноэкранный поиск

На ширине <768 px палитра, открытая из шапки, ДОЛЖНА занимать весь экран
(360 px без горизонтального скролла): поле ввода закреплено сверху,
результаты скроллятся, группы и подвал доступны без потери контекста.

#### Scenario: полноэкранный поиск на 360 px

- **WHEN** на mobile-360 студент открывает поиск кнопкой в шапке
- **THEN** оверлей занимает весь вьюпорт, горизонтального скролла нет,
  ввод «справка» показывает группы и AI-подвал на том же экране.

### Requirement: Производительность и состояния

Ответ поиска на сидовых данных ДОЛЖЕН занимать < 200 мс; во время запроса
палитра не мигает макетом (debounce 120 мс, отмена устаревших запросов);
ошибка сети — сообщение «Поиск временно недоступен», нулевой результат —
«Ничего не найдено» с подсказкой «Спросить AI».

#### Scenario: быстрый ответ на сидовых данных

- **WHEN** searchCabinet выполняется на demo-данных с запросом «справка»
- **THEN** время выполнения меньше 200 мс (фактически — единицы мс).

#### Scenario: нулевой результат

- **WHEN** запрос «вымышленныйзапрос» не даёт попаданий
- **THEN** палитра показывает «Ничего не найдено» и AI-подвал, а не пустоту.
