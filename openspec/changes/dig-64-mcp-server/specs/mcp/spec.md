# mcp — delta (DIG-64)

## ADDED Requirements

### Requirement: Демо-MCP-сервер деканата

Приложение публикует демо-MCP-сервер на `POST /api/mcp` (транспорт
Streamable HTTP, сообщения JSON-RPC 2.0, ответы `application/json`).
Сервер поддерживает `initialize`, `tools/list`, `tools/call` и `ping`;
уведомления (сообщения без id) отвечают `202 Accepted` без тела;
неизвестный метод → `-32601`; неизвестный инструмент → `-32602`;
неразбираемый JSON → `-32700`. Запросы без `POST` отвечают `405`
(метод не поддерживается), CORS открыт для браузерных клиентов.

#### Scenario: Инициализация клиента

* WHEN клиент отправляет `initialize` с `protocolVersion: "2025-06-18"`
* THEN ответ содержит `serverInfo.name = "digital-deanery"` и совместимую
  `protocolVersion`

#### Scenario: Список инструментов

* WHEN клиент отправляет `tools/list`
* THEN ответ содержит ровно три инструмента: `my_schedule_today`,
  `my_grades`, `my_unread` — с описанием и входной JSON-Schema

#### Scenario: Вызов инструмента и обработка ошибок

* WHEN клиент вызывает `tools/call` известного инструмента
* THEN ответ содержит `content: [{ type: "text", text }]` с человекочитаемым
  текстом на русском
* WHEN клиент вызывает неизвестный метод или инструмент / отправляет мусор
* THEN сервер отвечает JSON-RPC-ошибкой (-32601 / -32602 / -32700)

### Requirement: Персональный демо-токен

Доступ к серверу — по персональному токену студента в заголовке
`Authorization: Bearer <токен>`. Токен выпускает владелец сессии
(`demo-mcp-…`, 192 бита энтропии); в хранилище остаётся только SHA-256-хэш,
превью и владелец. Перевыпуск отзывает прежний токен. Запрос без токена, с
неверным токеном или чужим токеном отвечает `401` с `WWW-Authenticate:
Bearer`; обращения с одного IP ограничены скользящим окном (`429` +
`Retry-After`). Вызванные под токеном инструменты читают данные ТОЛЬКО
владельца токена через скоупленный data-слой.

#### Scenario: Подключение со своим токеном

* WHEN владелец токена вызывает инструмент с `Authorization: Bearer <токен>`
* THEN сервер отдаёт данные владельца токена (IDOR исключён)

#### Scenario: Отказ без/с неверным токеном

* WHEN запрос приходит без заголовка Authorization или с неверным токеном
* THEN ответ `401`, данных в ответе нет

#### Scenario: Перевыпуск отзывает прежний токен

* WHEN владелец выпускает новый токен на вкладке «Настройка MCP»
* THEN прежний токен перестаёт проходить (`401`), новый работает

#### Scenario: Перебор токенов ограничен

* WHEN с одного IP поступает больше лимита обращений за окно
* THEN сервер отвечает `429` с заголовком `Retry-After`

### Requirement: Инструменты отдают только свои данные

Инструменты возвращают человекочитаемый текст на русском:

- `my_schedule_today` — пары владельца на сегодняшний день по Москве
  (время, дисциплина, тип, аудитория, преподаватель; переносы и отмены
  помечены; пустой день — честное «пар нет»);
- `my_grades` — последние оценки владельца (дисциплина, элемент контроля,
  балл из максимума, дата; не более 20, с общим счётчиком);
- `my_unread` — непрочитанные уведомления владельца (тип, заголовок, текст,
  время; не более 10, с общим счётчиком).

Данные вымышленные (демо-набор прототипа); реальных вузов и ключей нет.

#### Scenario: Расписание на сегодня

* WHEN владелец вызывает `my_schedule_today`
* THEN текст начинается с «Расписание на сегодня» и содержит только пары
  его группы

#### Scenario: Оценки и непрочитанные

* WHEN владелец вызывает `my_grades` / `my_unread`
* THEN текст содержит его оценки / его непрочитанные уведомления и не
  содержит данные других студентов
