# Proposal: экран «Успеваемость: сводка» (DIG-26)

## Зачем

DIG-25 дала слой данных успеваемости (накопленные оценки, GPA, кредиты,
рейтинг, долги), но в кабинете до сих пор стоит заглушка `/grades`.
Студент не видит «как у меня дела»: средний балл семестра и дельту к
прошлому, прогресс кредитов до 240, место в группе, оценки по дисциплинам
с допуском к экзамену и долги с пересдачами. Это экран 05 Figma-макета
«Цифровой деканат» (1440 + 360 px) и центральная часть концепта
«всё в одном месте».

## Что

- `src/lib/performance-format.ts` — presentation-слой (чистые функции
  без серверных импортов, контракт зафиксирован red-тестами
  `tests/performance-format.test.ts`):
  - параметр семестра `?semester=YYYY-FALL|YYYY-SPRING`:
    `semesterParam` / `parseSemesterParam` (мусор → null);
  - пилюли семестров `buildSemesterPills`: семестры с оценками + текущий
    (даже пустой), по убыванию; короткие подписи «Осень 26/27»;
  - `disciplinesForSemester`: безоценочные дисциплины остаются в текущем
    семестре (семестр дисциплины выводится из дат оценок);
  - семестровый GPA `semesterGpaOf` (итог ?? накопленная, вес — кредиты)
    и дельта `semesterDelta` к предыдущему семестру (пустой предыдущий →
    null — «не с чем сравнивать»);
  - карточки дисциплин `toDisciplineCards`: крупная оценка («87» / «48,9»
    / прочерк), словесный уровень («Отлично» / «Порог ещё не гарантирован»
    / «Не дотянуть до порога» — цвет не единственный носитель смысла),
    «из возможных 88,9», бейдж допуска к экзамену (Экзамен сдан / Допуск
    есть / Допуска нет / без бейджа), ссылка в зачётку;
  - светофор `trafficLight`: активные долги > риски > всё хорошо >
    «Оценок пока нет» — с фразой и действием;
  - пустой семестр: `nextAssessment` (ближайшая будущая не-пересдача) +
    `emptySemesterNote` («Первая контрольная — зачёт по … 14 ноября»);
  - долги: `activeDebts`, `debtBadge`, `debtDatePhrase`
    («Пересдача назначена на 19 ноября (осталось 7 дней)»);
  - тултипы сокращений простыми словами: `GPA_HINT`, `CREDITS_HINT`,
    `CREDITS_SHORT_HINT`, `PERCENTILE_HINT`.
- View-поля агрегата (DIG-25 → дополнены): `DisciplinePerformance` несёт
  `teacherName` (из справочника группы), `hasExamElement` /
  `examGraded` (экзаменационный элемент плана и оценён ли он) — источник
  бейджа допуска и строки преподавателя на карточке.
- Экран `src/app/(cabinet)/grades/page.tsx` (метка `screen`, Figma «05»):
  - сводка «как у меня дела»: кольцо GPA семестра с дельтой к прошлому
    («−54,1 к Весна 25/26»), GPA за всё время, кредиты полосой
    «9 из 240», место в группе «2 из 5» с формулировкой «Вы входите в
    40% лучших» и тултипом «Как считается»;
  - пилюли семестров (?semester=, aria-current на активной);
  - светофор состояния с действием (к долгам / к сессии);
  - список дисциплин выбранного семестра карточками (преподаватель,
    кредиты, накопленная крупно, «из возможных», уровень словами, бейдж
    допуска; клик → `/grades/gradebook?discipline=CODE`);
  - блок «Долги» (#debts): статус, дата пересдачи, «Записаться на
    пересдачу» → `/deanery`;
  - нижние ссылки: «Сессия» и «Нашли ошибку в оценке? Написать в деканат»;
  - дефолтный семестр: текущий, а если в нём нет оценок — ближайший
    семестр с оценками; мусорный ?semester= откатывается к дефолту;
  - пустые состояния, ошибка агрегата (ErrorState + «Повторить»),
    заглушка сотруднику («Экран доступен студентам»).
- `loading.tsx` + `GradesSkeleton` — скелетон на время загрузки RSC.

## Данные и доступ (IDOR)

Данные читает только сервер: `getPerformance(dataDb, ctx)` и
`listExams(dataDb, ctx)`, ctx из живой сессии (`requireDataCtx`);
`ctx.studentId` — единственный ключ персональной выборки, из URL не
приходит. Параметр `?semester=` влияет только на то, какой срез уже
своих данных показан. Сотрудник (studentId = null) получает заглушку до
обращения к данным. Чужих строк в ответе нет (контракт DIG-25: оценки
сокурсников — только вход агрегата рейтинга, наружу место/перцентиль
владельца).
