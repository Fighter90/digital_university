# Delta: gradebook (DIG-27) — зачётная книжка и карточка дисциплины

## ADDED Requirements

### Requirement: Список зачётки по семестрам

Слой данных ДОЛЖЕН возвращать дисциплины текущего студента, сгруппированные
в семестры (московский учебный календарь DIG-25, семестр — по дате последней
оценки; безоценочные дисциплины — в текущем семестре), отсортированные по
убыванию (свежие сверху). Для каждой дисциплины: название, тип контроля
(«Экзамен» / «Диф. зачёт» / «Зачёт», выведенный из плана контроля),
кредиты, итоговая оценка (завершённая дисциплина — арифметическое
округление, иначе — накопленная), дата выставления итога (последняя
оценка). Для семестра: средний балл (средневзвешенное кредитами) и кредиты
«набрано / всего».

#### Scenario: завершённый и текущий семестры

- **WHEN** у студента итоги весны (ALG 87, 5 кр.; DISC 74, 4 кр.) и
  накопленные осени (INFO 88, PROG 92, DB 85)
- **THEN** семестры идут «Осень 2026/27» → «Весна 2025/26»; средний балл
  весны = (87·5 + 74·4) / 9 = 81.22, кредиты весны 9 из 9; в осени
  средний = 88.6, кредиты набрано 0 из 15.

#### Scenario: тип контроля из плана

- **WHEN** в плане есть элемент EXAM → «Экзамен»; единственный элемент
  TEST → «Зачёт»; прочие планы без EXAM → «Диф. зачёт»; ни плана, ни
  оценок → «—»
- **THEN** метка типа контроля детерминирована и покрыта тестами.

#### Scenario: скоуп и роли

- **WHEN** сотрудник запрашивает зачётку
- **THEN** пустой агрегат + запись в AuditLog (ROLE_MISMATCH); студент
  видит только дисциплины своей группы.

### Requirement: Мгновенная выписка PDF

`GET /api/grades/transcript` ДОЛЖЕН отдавать выписку из зачётки мгновенно
(без заявки и очереди): PDF с шапкой вымышленного вуза, данными студента,
таблицами семестров (дисциплина, тип контроля, кредиты, итог, дата),
итогами семестров и сводкой, кодом проверки (160 бит) и рамкой под QR
(сканируемый QR и публичная проверка — DIG-47). Ответ —
`application/pdf`, `Content-Disposition: attachment`; сотруднику —
единый 404 + аудит; PDF детерминирован при фиксированных входах.
На 360 px таблица семестра на экране превращается в карточки (таблица —
только от `md`).

#### Scenario: скачивание студентом

- **WHEN** студент нажимает «Скачать выписку PDF»
- **THEN** ответ 200, `application/pdf`, тело начинается с `%PDF-`,
  файл открывается без вложенных шрифтов (векторные глифы).

#### Scenario: выписка недоступна без роли

- **WHEN** сотрудник или аноним обращается к `/api/grades/transcript`
- **THEN** сотрудник — 404 + аудит (ROLE_MISMATCH), аноним — редирект на
  вход.

### Requirement: Карточка дисциплины

`/grades/<disciplineId>` (id = disciplineCode) ДОЛЖЕН показывать: шапку
(название, преподаватель, кредиты, накопленная оценка крупно с границами),
формулу оценки полосами (группы видов контроля с процентом части и текущим
баллом части), список отдельных оценок (элемент, дата, балл; все попытки,
сверхдаты помечены «пересдача»), слот калькулятора «Что нужно на экзамене»
(встраивается отдельной задачей) и «Ошибка в оценке?» — обращение в
деканат с предзаполненной дисциплиной. Чужая или несуществующая
дисциплина — единый 404 (причина — только в AuditLog).

#### Scenario: формула полосами

- **WHEN** план «Контрольные 30% (сдано 88 из 100) · Экзамен 70% (не
  сдан)»
- **THEN** части показывают проценты веса и текущий балл части (для части
  с несданными элементами — заработанная доля от максимума части: 44 из
  100), экзамен помечен «не оценено».

#### Scenario: чужая дисциплина

- **WHEN** Анна открывает `/grades/EK11-MATH` (дисциплина группы ЭК-11)
- **THEN** страница отвечает 404 (единый not-found), попытка записана в
  AuditLog (OWNERSHIP_DENIED); несуществующий код — тот же 404
  (NOT_FOUND).

#### Scenario: обращение по ошибке в оценке

- **WHEN** студент нажимает «Ошибка в оценке?» на карточке своей
  дисциплины
- **THEN** создаётся обращение в деканат, предмет и сообщение содержат
  название дисциплины и текущую накопленную оценку; чужая дисциплина
  обращение не создаёт (null + аудит).
