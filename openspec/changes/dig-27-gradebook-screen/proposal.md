# Proposal: экран «Зачётная книжка» и карточка дисциплины (DIG-27)

## Зачем

В аудированном ЛК зачётка — отдельный внешний сервис, а выписку из неё
студент заказывает заявкой (до 5 раз за год). По задаче зачётка должна жить
внутри кабинета: список дисциплин по семестрам с итогами и мгновенная
выписка PDF (механизм справок с QR — DIG-47 добавит публичную проверку),
плюс карточка дисциплины с формулой оценки, отдельными оценками,
калькулятором «что нужно на экзамене» (отдельная задача, встраивается
слотом) и обращением в деканат по ошибке в оценке.

## Что

- **Список (аккордеон по семестрам)** — `/grades/gradebook`:
  дисциплина: название, тип контроля (экзамен / зачёт / диф. зачёт),
  кредиты, итоговая оценка, дата выставления; итог семестра: средний балл
  (взвешенный кредитами), кредиты семестра. Кнопка «Скачать выписку PDF».
  На 360 px таблица семестра превращается в карточки (таблица — только
  от `md`, карточки — только ниже).
- **Карточка дисциплины** — `/grades/<disciplineId>` (id = disciplineCode):
  шапка (название, преподаватель, кредиты, накопленная оценка крупно),
  формула оценки полосами («Контрольные 30% · ДЗ 20% · Экзамен 50%» с
  текущими баллами частей), список отдельных оценок (элемент, дата, балл;
  пересдачи помечены), слот калькулятора «Что нужно на экзамене»
  (id="calculator", отдельная задача), «Ошибка в оценке?» → server action
  создаёт обращение в деканат с предзаполненной дисциплиной.
- **Выписка PDF** — `GET /api/grades/transcript`: мгновенно (без заявки и
  очереди), скоуп по ctx (сотрудник — единый 404 + аудит). PDF собирается
  собственным минимальным писателем (`src/lib/pdf/*`) с векторным шрифтом
  (глифы 5×8 как прямоугольники): кириллица не требует вложенных шрифтов и
  открывается в любом просмотрщике; QR-блок — рамка-заготовка + код проверки
  текстом (сканируемый QR и страница `/verify/<код>` — DIG-47).
- **Слой данных** — `src/server/data/gradebook.ts`: `getGradebook`
  (семестры → дисциплины → итог семестра), `getDisciplineCard` (чужая /
  несуществующая дисциплина — единообразный `null` + AuditLog, страница
  отвечает `notFound()`), `createGradeAppeal` (обращение с предзаполненной
  дисциплиной, та же проверка владельца). Расчёты — переиспользование
  `computeDisciplines` из DIG-25 (экспортирована из `performance.ts`) и
  чистых функций `src/lib/performance-math.ts`; новые чистые функции
  (тип контроля, части формулы) — `src/lib/gradebook.ts`.

## Правила и допущения (зафиксированы тестами)

- Тип контроля дисциплины выводится из плана контроля: есть элемент EXAM →
  «Экзамен»; единственный элемент вида TEST → «Зачёт»; иначе —
  «Диф. зачёт»; нет ни плана, ни оценок → «—». В модели прототипа нет
  отдельного поля «тип контроля», вывод из плана детерминирован и покрыт
  тестами.
- Семестр дисциплины — по дате последней оценки (московский календарь
  DIG-25); дисциплины без оценок попадают в текущий семестр (как в
  `getPerformance`).
- «Итог семестра»: средний балл = средневзвешенное кредитами по значениям
  дисциплин семестра (завершённая — округлённый итог, идущая — накопленная,
  та же логика GPA DIG-25); кредиты семестра: набрано / всего по плану
  семестра.
- Формула карточки: элементы группируются по виду контроля (TEST →
  «Контрольные», HOMEWORK → «ДЗ», LAB → «Лабораторные», PROJECT →
  «Проект», EXAM → «Экзамен»), процент части = сумма весов группы;
  «текущий балл части» = заработанные проценты от максимума части
  (Σ вес×доля по сданным элементам группы / вес части × 100).
- Дата итога дисциплины = дата последней оценки по её элементам.
- Пересдача не удваивает счёт: в списке оценок видны все попытки, в
  формуле и накопленной учитывается последняя по дате (правила
  docs/grading.md).

## Отклонения от текста задачи (обоснованные)

- «Преподаватель (ссылка на справочник)»: экрана справочника ещё нет
  (DIG-37), ссылка вела бы на 404 — преподаватель показывается текстом с
  пометкой, что профиль появится в справочнике. Карточка готова принять
  ссылку, когда экран появится.
- «Механизм справок с QR»: выписка скачивается мгновенно уже сейчас, но
  сканируемый QR и публичная страница проверки — задача DIG-47
  (публичная `/verify/<код>` + PDF-шаблон справки). В PDF печатается код
  проверки (128 бит) и рамка под QR, чтобы формат документа не менялся
  при запуске проверки.
- Калькулятор «Что нужно на экзамене» — отдельная задача; карточка
  предоставляет слот `id="calculator"` и данные плана (экзамен: вес,
  максимум, сдан ли), калькулятор встраивается сюда без изменений
  страницы.

## Вне скоупа

- Экран «Успеваемость» (DIG-26, Figma «05») — карточка дисциплины
  (/grades/<id>) и зачётка (/grades/gradebook) сознательно отделены от
  страницы-заглушки /grades: в неё добавлена только точка входа
  «Перейти в зачётную книжку» (кнопка из аналога), вёрстку «05» делает
  DIG-26.
- Сессия и пересдачи как мутации (DIG-28).
- Сканируемый QR и `/verify/<код>` (DIG-47).
- Prisma-адаптер порта: слой работает через существующий порт DIG-12
  (in-memory адаптер прототипа), Prisma-реализация — общий трек.
