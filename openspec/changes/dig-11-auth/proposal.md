# DIG-11 — Аутентификация: вход по логину и паролю, сессии, защита от перебора

## Зачем

Прототип обязан показывать жюри безопасный вход без внешних сервисов (работа из
РФ, без зависимости от зарубежных auth-провайдеров). Это фундамент правила
IDOR: все последующие экраны получают пользователя через `requireUser()`.

## Что сделано

- Пароли: **argon2id** через `@node-rs/argon2`, параметры OWASP
  (memory 19 MiB, iterations 2, parallelism 1). Открытые пароли не хранятся
  и не логируются.
- Сессии: случайный токен 256 бит (`base64url`, 43 символа); в БД/хранилище —
  только SHA-256 токена. Cookie `__Host-session`: HttpOnly, Secure,
  SameSite=Lax, Path=/, 7 дней.
- Скользящее продление: когда остаётся меньше половины срока, сессия
  продлевается на полные 7 дней (`session-policy.ts`, значение cookie не
  меняется).
- «Выйти» (текущее устройство) и «Выйти со всех устройств» (отзыв всех сессий
  пользователя) — server actions из `src/server/actions/auth.ts`.
- Защита от перебора: 5 неудачных входов подряд → блокировка аккаунта на
  15 минут; скользящий лимит 30 попыток за 15 минут на IP; одинаковое
  сообщение об ошибке для неверного логина и неверного пароля; для
  несуществующего логина выполняется такая же по стоимости проверка argon2id
  (защита от timing-оракула).
- CSRF: Server Actions (встроенная проверка Origin/Host в Next.js) +
  проверка Origin для мутационных API-роутов в middleware (`decideAccess`).
- Роли STUDENT и STAFF; `src/middleware.ts` не пускает неавторизованных в
  кабинет (`/login?next=…` со защите от open redirect) и студентов в `/staff`.
  Роль для быстрого гейта едет в подписанной HMAC (AUTH_SECRET) cookie
  `__Host-role`; каждый staff-экран обязан перепроверять роль на сервере через
  `requireStaff()`.
- «Войти через Госуслуги» — только неактивная кнопка с меткой «демо».
- Тесты (red-first): 46 unit-тестов — пароли, токены, вход, блокировка,
  IP-лимит, истечение сессии, скользящее продление, выход, выход со всех
  устройств, форма cookie, Prisma-адаптер (в БД нет открытых паролей/токенов),
  маршруты и Origin-проверка.

## Non-goals

- **Экран входа (визуал)** — задача DIG-18 (Figma «02 · Вход»): здесь форма
  только работает (labels, ошибки, pending, демо-кнопка Госуслуг).
- **Схема БД и сиды** — задачи DIG-9/DIG-10 (свои ветки). На этой ветке
  приложение работает на in-memory хранилище (`src/server/auth/store.ts`);
  переход на PostgreSQL — заменить фабрику на `createPrismaAuthStore(...)`
  (адаптер готов и протестирован, отображение на схему DIG-9: `User`,
  `Session.tokenHash`, `User.failedLogins/lockedUntil`).
- **Сиды с bcrypt**: если DIG-10 засеивает `passwordHash` через bcryptjs,
  при смерже нужен перевод сидов на `argon2id` (иначе тестовые аккаунты
  не смогут войти) — координация на оркестраторе.
- Реальная интеграция с Госуслугами и восстановление пароля — вне концепта.
