# Delta: login-screen (DIG-18)

## ADDED Requirements

### Requirement: Экран входа соответствует макету «02 · Вход»

Экран `/login` ДОЛЖЕН быть разделённым на десктопе (≥768 px): слева —
декоративная панель на мягком коралловом градиенте с «парящими» карточками
(пара, оценка, статус справки), справа — форма входа. На 360 px панель
ДОЛЖНА быть скрыта, форма — на весь экран, поля ввода — высотой 48 px.
Панель ДОЛЖНА быть `aria-hidden` и не анимироваться при
`prefers-reduced-motion: reduce`.

#### Scenario: десктоп 1440

- **WHEN** пользователь открывает /login на 1440 px
- **THEN** виден коралловый герой (~половина ширины) и форма справа.

#### Scenario: мобильный 360

- **WHEN** пользователь открывает /login на 360 px
- **THEN** герой скрыт, форма занимает весь экран, высота полей 48 px.

### Requirement: Тестовые аккаунты одним кликом

Экран входа ДОЛЖЕН показывать блок «Тестовые аккаунты» с тремя чипами —
канонические вымышленные персоны DIG-12: «Анна Ковалёва · ПИ-21» (anna),
«Илья Смирнов · ЭК-11» (ilya), «Сотрудник деканата» (maria). Клик по чипу
ДОЛЖЕН заполнить поля логина и пароля соответствующими демо-данными.

#### Scenario: клик по чипу

- **WHEN** пользователь нажимает чип «Анна Ковалёва · ПИ-21»
- **THEN** поле «Логин» = `anna`, поле «Пароль» = `demo-anna-2026`.

#### Scenario: вход по чипу

- **WHEN** пользователь нажимает чип и отправляет форму (Enter или «Войти»)
- **THEN** серверная сессия создаётся, пользователь попадает в кабинет
  (`/dashboard`) или на безопасный `?next=`-цель.

### Requirement: Видимость пароля

Поле пароля ДОЛЖНО иметь кнопку «показать/скрыть» с `aria-pressed` и
понятной подписью (`Показать пароль` / `Скрыть пароль`), переключающую
`type` между `password` и `text`.

#### Scenario: переключение

- **WHEN** пользователь нажимает кнопку «Показать пароль»
- **THEN** `type` ввода становится `text`, `aria-pressed="true"`, повторное
  нажатие возвращает `password`.

### Requirement: Заглушка «Забыли пароль?»

Маршрут `/forgot-password` ДОЛЖЕН быть публичным (без сессии) и объяснять,
что в концепте восстановление пароля выполняет деканат; со страницы ведёт
возврат на `/login`.

#### Scenario: переход

- **WHEN** пользователь нажимает «Забыли пароль?» на /login
- **THEN** открывается `/forgot-password` с заголовком «Восстановление
  пароля», текстом про деканат и ссылкой «Вернуться ко входу».

### Requirement: Демо-данные готовы к первому экрану

Рендер экрана входа ДОЛЖЕН гарантировать наличие демо-пользователей в
хранилище аутентификации (вызов `ensureAppData()`), чтобы первый вход после
старта сервера работал без предварительного открытия других экранов.

#### Scenario: свежий старт сервера

- **WHEN** сервер запущен и пользователь сразу открывает /login и входит по
  чипу
- **THEN** вход успешен (не «Неверный логин или пароль»).

## MODIFIED Requirements

### Requirement: Сохранение контракта DIG-11

Форма ДОЛЖНА сохранить: `autocomplete="username"` / `current-password`,
Enter отправляет форму, состояние загрузки («Входим…», кнопка неактивна),
единые ошибки через `role="alert"` («Неверный логин или пароль», «Слишком
много попыток, попробуйте через 15 минут»), неактивную кнопку «Войти через
Госуслуги (демо)», скрытое поле `next` с безопасным значением
(`safeNextPath`: один `/`, без `//` и `/\`), плашку «Концепт для конкурса».

#### Scenario: неверный пароль

- **WHEN** пользователь входит с верным логином и неверным паролем
- **THEN** видна единая ошибка «Неверный логин или пароль» без раскрытия
  причины.

#### Scenario: блокировка

- **WHEN** совершено 5 неудачных попыток входа в один аккаунт
- **THEN** следующая попытка (даже с верным паролем) показывает «Слишком
  много попыток, попробуйте через 15 минут».
