# Delta: notifications-center (DIG-35) — центр уведомлений и панель колокольчика

## ADDED Requirements

### Requirement: Конкретные строки уведомлений

Каждое уведомление ДОЛЖНО (MUST) называть объект и что изменилось
(«Справка для военкомата готова», «Пара «Базы данных» перенесена в
ауд. 305») — строки вида «Сменился статус по …» без конкретики
запрещены. Строка ленты: иконка категории, заголовок, одна строка
деталей, время, точка «не прочитано» для непрочитанных, опциональные
метка «Важно» и действие («Скачать», «Открыть расписание»).

#### Scenario: ни одного уведомления без конкретики

- **WHEN** сид демо-набора создаёт уведомления
- **THEN** каждая строка имеет заголовок с объектом и деталь с изменением;
  тест сида проверяет отсутствие шаблонов без конкретики.

#### Scenario: «Важно» только для срочного

- **WHEN** источник уведомления — перенос/отмена пары сегодня, недопуск,
  доработка заявки или дедлайн оплаты
- **THEN** строка помечается «Важно» (поле `important`, ставит источник,
  не эвристика по тексту); прочие уведомления метки не имеют.

### Requirement: Фильтры и группировка центра уведомлений

Экран `/notifications` ДОЛЖЕН (MUST) показывать фильтры Все / Непрочитанные /
Учёба / Заявки / Деканат / Финансы (категории: Учёба = SCHEDULE+GRADE,
Заявки = REQUEST, Деканат = NEWS+SYSTEM, Финансы = DEADLINE) и
группировать строки по локальному календарному дню: «Сегодня» / «Вчера» /
«Ранее». Время строки: сегодня и вчера — HH:MM, ранее — DD.MM.

#### Scenario: фильтр сужает список

- **WHEN** студент выбирает «Финансы»
- **THEN** остаются только DEADLINE-строки; если под фильтр ничего не
  подошло — виден отдельный пустой результат («Здесь пока пусто»),
  а не пустое состояние всей ленты.

#### Scenario: группировка по дням

- **WHEN** уведомления созданы сегодня, вчера и неделю назад
- **THEN** они попадают в группы «Сегодня», «Вчера» и «Ранее»
  соответственно; пустые группы не показываются.

### Requirement: Панель колокольчика в шапке

Шапка кабинета ДОЛЖНА (MUST) показывать колокольчик с числом непрочитанных и по
клику/клавиатуре открывать панель последних 5 уведомлений (самых свежих).
Панель управляется с клавиатуры: открытие с Enter/Space, фокус уходит в
панель, Tab циклит внутри панели, Esc закрывает и возвращает фокус на
колокольчик, клик мимо панели закрывает её. Из панели ведут ссылки
«Все уведомления» → /notifications и «Настроить уведомления» → /settings.

#### Scenario: максимум 5 свежих

- **WHEN** у студента больше 5 уведомлений
- **THEN** панель показывает ровно 5 самых свежих (по `createdAt`,
  новые сверху).

#### Scenario: клавиатура

- **WHEN** студент открывает панель с клавиатуры и нажимает Esc
- **THEN** панель закрывается, фокус возвращается на колокольчик;
  Tab не выводит фокус за пределы панели.

### Requirement: Прочтение и переход к объекту

Клик по строке (или её действию) ДОЛЖЕН (MUST) отмечать уведомление прочитанным
и вести к объекту (soft-nav). «Отметить все прочитанными» ДОЛЖНО отмечать
разом все свои строки и блокироваться, когда непрочитанных нет.
Мутации — server actions со скоупом владельца сессии: чужой id
возвращает отказ и попадает в аудит, «отметить все» затрагивает только
свои строки; сотруднику student-мутации недоступны (ROLE_MISMATCH + аудит).

#### Scenario: клик по строке

- **WHEN** студент кликает непрочитанную строку с действием «Скачать»
- **THEN** точка «не прочитано» исчезает, выполняется переход по ссылке
  строки, отметка уходит через server action владельца.

#### Scenario: чужой id

- **WHEN** action вызван с id уведомления другого студента
- **THEN** отметка не применяется (false), попытка фиксируется в AuditLog;
  HTTP-ответ не раскрывает существование чужой строки.

### Requirement: Живость счётчика и ленты без перезагрузки

Счётчик непрочитанных в шапке ДОЛЖЕН (MUST) обновляться без перезагрузки
страницы (polling `/api/notifications/count` раз в 60 секунд), лента
панели и экрана — polling `/api/notifications/recent` раз в 60 секунд;
после server actions клиент вызывает `router.refresh()` для обновления
серверных частей. Оба эндпоинта отвечают только данными владельца
сессии (аноним недопускается middleware, сотрудник — пустой агрегат
без аудита), ответы `Cache-Control: no-store`.

#### Scenario: счётчик обновляется без перезагрузки

- **WHEN** проходит 60 секунд с момента загрузки страницы
- **THEN** шапка опрашивает count-эндпоинт и обновляет бейдж без
  перезагрузки страницы.

#### Scenario: лента пополняется

- **WHEN** во время открытой панели/экрана появляется новое уведомление
- **THEN** оно появляется в ленте на следующем опросе без перезагрузки.

### Requirement: Пустые состояния

Центр уведомлений ДОЛЖЕН (MUST) показывать пустое состояние с иллюстрацией
колокольчика и текстом «Новых уведомлений нет», когда лента пуста
(в том числе сотруднику, у которого персональной ленты нет), и отдельный
пустой результат под фильтр.

#### Scenario: сотрудник

- **WHEN** сотрудник открывает /notifications
- **THEN** он видит пустое состояние без данных; попытки чтения/мутаций
  студенческой ленты фиксируются в аудите.
