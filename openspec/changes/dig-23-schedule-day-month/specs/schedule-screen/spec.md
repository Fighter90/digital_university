# Delta: schedule-screen (DIG-23) — виды «День», «Месяц», мобильная лента дат

## ADDED Requirements

### Requirement: Вид «День» — карточки пар

Вид «День» ДОЛЖЕН показывать пары дня карточками: время слева (начало
жирным, «до конец» мелкой строкой), цветная полоса типа занятия, название,
аудитория («ауд. N») или «онлайн», преподаватель; перенос (ROOM_CHANGED /
TIME_CHANGED) — заметно: штриховка, пунктирная warning-рамка, бейдж
«Перенос» и строки «было: ауд. N» / «было: HH:MM»; отмена (CANCELLED) —
бейдж «Отмена», зачёркнутое название, бледная карточка и причина. Карточка
ДОЛЖНА нести понятный aria-label («Лекция, Информатика, 10:00–11:30,
ауд. 301, перенос»).

#### Scenario: перенос и отмена в одном дне

- **WHEN** студент открывает день с перенесённой и отменённой парами
- **THEN** перенесённая карточка показывает «Перенос», «было: ауд. 214» и
  причину; отменённая — «Отмена», зачёркнутое название и причину.

#### Scenario: пустой день

- **WHEN** у выбранного дня пар нет и впереди есть учебный день с парами
- **THEN** показывается пустое состояние с иллюстрацией и текстом
  «Ближайшие пары: чт, 12 ноября»; если пар до конца семестра нет —
  «В семестре пар больше нет».

### Requirement: Вид «Месяц» — сетка 7×N

Вид «Месяц» ДОЛЖЕН рендерить сетку 7 колонок (пн..вс) целыми неделями; в
ячейке — число дня и цветные точки пар по типам занятий (до 4, сверх —
«+N»); сегодняшний день ДОЛЖЕН быть выделен. Клик по дню ДОЛЖЕН открывать
вид «День» этого дня (`/schedule?view=day&date=YYYY-MM-DD`). Навигация по
месяцам — ссылки, у месяцев вне семестра стрелки отключаются; месяц целиком
вне семестра — пустое состояние «Сейчас вне семестра».

#### Scenario: клик по дню месяца

- **WHEN** студент нажимает ячейку «13» ноября
- **THEN** URL становится `/schedule?view=day&date=2026-11-13` и рендерится
  вид «День» этого дня.

#### Scenario: точки пар

- **WHEN** в дне 6 пар
- **THEN** ячейка показывает 4 цветные точки (по типам первых пар) и «+2».

### Requirement: Мобильный вид (< 768 px) — лента дат и свайп

На ширине меньше 768 px вид «День» ДОЛЖЕН показывать сверху горизонтальную
ленту дат недели (7 дней, выбранный отмечен, дни с парами — точка-маркер),
под ней — карточки выбранного дня; по умолчанию выбран сегодня. Лента
ДОЛЖНА скроллиться в собственном контейнере, не вызывая горизонтальный
скролл страницы; при выборе дня лента ДОЛЖНА автоскроллиться к нему.
Горизонтальный свайп по списку пар ДОЛЖЕН листать дни (влево — следующий,
вправо — предыдущий); вертикальные и короткие (< 48 px) жесты листать не
ДОЛЖНЫ. Переключатель «Неделя» на мобильном ДОЛЖЕН показывать компактный
список по дням (заголовок дня, счётчик пар, плотные карточки) — перенос и
отмена видны теми же бейджами, что и на десктопе.

#### Scenario: страница без горизонтального скролла

- **WHEN** кабинет открыт на 360 px
- **THEN** у документа нет горизонтальной прокрутки
  (`scrollWidth ≤ clientWidth`), лента дат прокручивается независимо
  (`scrollWidth > clientWidth` у контейнера ленты).

#### Scenario: свайп листает день

- **WHEN** студент свайпит список пар влево
- **THEN** заголовок дня и список сменяются на следующий день без
  перезагрузки страницы (данные окна ±2 недели уже на клиенте); свайп
  вправо возвращает предыдущий день.

### Requirement: Переключатель видов и параметры URL

Страница `/schedule` ДОЛЖНА поддерживать параметры `?view=day|week|month`
(`?date=YYYY-MM-DD` для дня, `?week=YYYY-Wnn` для недели, `?month=YYYY-MM`
для месяца). Мусорные значения ДОЛЖНЫ откатываться к дефолту без ошибки.
Дефолт без `?view=` ДОЛЖЕН быть платформозависимым: десктоп открывает
недельную сетку DIG-22, мобильный — «сегодня» с лентой дат (вид «Неделя» на
мобильном — компактный список по дням). Все три опции переключателя ДОЛЖНЫ
быть доступны на обоих брейкпоинтах; переключение ДОЛЖНО переносить контекст
даты (день → ключ ISO-недели → месяц) и работать ссылкой (вид переживает
перезагрузку). Недельная сетка при листании ДОЛЖНА сохранять явный
`?view=week`.

#### Scenario: дефолт без параметров

- **WHEN** студент открывает `/schedule` без параметров
- **THEN** на десктопе рендерится недельная сетка DIG-22 с отмеченной
  «Неделей», на мобильном — лента дат и пары «сегодня» с отмеченным «Днём».

#### Scenario: мусор в параметрах

- **WHEN** студент открывает `/schedule?view=year&date=junk`
- **THEN** рендерится дефолт (десктоп — неделя, мобильный — «сегодня»)
  без ошибки.

#### Scenario: переключение с переносом контекста

- **WHEN** студент на виде дня `?view=day&date=2026-11-11` нажимает
  «Неделя»
- **THEN** URL становится `/schedule?view=week&week=2026-W46` и рендерится
  неделя, содержащая выбранный день.

### Requirement: Изоляция данных и границы ролей

Данные расписания ДОЛЖНЫ читаться только серверными скоуп-функциями
(`getSchedule` / `getMonth` / `getNextStudyDay`) с контекстом живой сессии
(`requireDataCtx`) — id из URL не влияет на скоуп (студент видит только
пары своей группы). Сотрудник ДОЛЖЕН получать явную заглушку «Расписание
доступно студентам». Ошибка слоя данных — ErrorState, а не падение страницы.

#### Scenario: студент видит только свою группу

- **WHEN** студент ПИ-21 открывает `/schedule`
- **THEN** карточки и точки месяца строятся из пар группы ПИ-21; пары чужих
  групп в ответе отсутствуют по построению запроса.
