# Delta Spec: docs — PDF «Описание процесса создания» (submission)

## ADDED Requirements

### Requirement: PDF-описание процесса соответствует чек-листу задания

`docs/submission/digital-deanery-process.pdf` ДОЛЖЕН (MUST) содержать
восемь секций: (1) проблема студента и почему такие разделы — с честной
пометкой, что опрос однокурсников не проводился (DIG-17 отменена), и
описанием альтернативной проработки (сценарии, справка/база знаний,
доступность); (2) полный перечень ИИ-инструментов/IDE/сервисов с ролью
каждого — включая Higgsfield для дизайна/иллюстраций; (3) ключевые промпты
и диалоги с привязкой к этапам и функциям; (4) скриншоты ключевых шагов от
первой идеи до кабинета; (5) неудачные варианты и работа с ошибками ИИ
(ревью-RETURN, красные гейты, squash-регрессия PR #82, OOM-kill) — дословные
выдержки из `docs/ai-log/` и git-истории; (6) вход, хранение данных и защита
простыми словами (argon2id, `__Host-`cookie, owner-scope/IDOR, .env,
rate-limit); (7) этапы, проделанные вручную; (8) проверяемые цифры проекта
со ссылками на источники. В документе НЕ ДОЛЖНО (MUST NOT) быть утверждения,
что опрос студентов проводился, если он не проводился.

#### Scenario: Жюри проверяет пункт «опрос однокурсников»

* WHEN жюри читает секцию 1 PDF
* THEN видно явное заявление, что опрос НЕ проводился и задача DIG-17 отменена
* AND перечислена альтернативная проработка: сценарии дня, справка/база
  знаний, доступность, и зафиксировано ограничение (гипотезы не
  валидированы анкетой)

#### Scenario: Жюри проверяет пункт «работа с ошибками ИИ»

* WHEN жюри читает секцию 5 PDF
* THEN видны минимум четыре неудачных случая из журналов проекта
  (ревью RETURN×3 DIG-20; нестабильный e2e и гонка кук DIG-77;
  squash-регрессия PR #82 с коммитом bcffd8a; OOM-kill DIG-50)
* AND для каждого случая указан урок/механика, которой система это ловит

#### Scenario: Жюри проверяет salvage-коммиты из секции 5.1

* WHEN жюри выполняет `git cat-file -p ecfe95e` в публичном репозитории
* THEN команда возвращает коммит (объекты ecfe95e и 39253ac существуют)
* AND документ явно квалифицирует их как висячие объекты после
  reflog-restore: в `git log` веток их нет, способ проверки указан в PDF

#### Scenario: Жюри пересчитывает цифру «77 циклов»

* WHEN жюри выполняет `ls docs/ai-log/`
* THEN документ объясняет формулу подсчёта: общее число записей каталога
  (81) = файлов циклов (77) + README, _TEMPLATE.md, assets.md и
  assets-src/ — служебные записи не являются циклами
* AND статистика на странице «Цифры проекта» называет то же число, что
  даёт формула, и тест `tests/submission-pdf-facts.test.ts` это прибивает

#### Scenario: Заявленное число страниц совпадает с реальным

* WHEN жюри проверяет заявление «11 стр.» (COMMENT.md, SUBMISSION.md)
  по числу объектов `/Type /Page` в PDF
* THEN реальное число страниц равно 11
* AND проверки через `mdls`/Spotlight не используются как источник правды
  (устаревающий индекс — это и споткнуло ревью)

### Requirement: Цитаты дословны, счётчики с датой среза

Поскольку титул PDF обещает «все цитаты промптов и вердиктов — дословные»,
каждая цитата в документе ДОЛЖНА (MUST) воспроизводить свой источник в
репозитории дословно, а место сокращения в выдержке ДОЛЖНО (MUST) быть
помечено «…» — молчаливые сокращения запрещены. Счётчики, которые меняются
самостоятельно (задачи Linear, merged PR), ДОЛЖНЫ (MUST) нести явную дату
среза («на 20.11») и быть согласованы между таблицей инструментов и
страницей «Цифры проекта». Подписи с размерами файлов ДОЛЖНЫ (MUST)
совпадать с реальным размером файла в репозитории. Проверки прибиты тестом
`tests/submission-pdf-facts.test.ts`.

#### Scenario: Жюри сверяет цитату чек-листа с исходником агента

* WHEN жюри открывает `.opencode/agent/reviewer.md` (или `security.md`)
  и сравнивает с панелью секции 3 PDF
* THEN текст пунктов совпадает дословно, а сокращения помечены «…»
* AND тест `tests/submission-pdf-facts.test.ts` проверяет те же подстроки

#### Scenario: Жюри проверяет актуальность счётчиков

* WHEN жюри выполняет `gh pr list --state merged` или открывает Linear
* THEN цифры в PDF помечены датой среза «на 20.11» и понимаются как срез,
  а не как вечно-актуальное значение
* AND формулировки в таблице инструментов и на странице «Цифры проекта»
  называют одно и то же число (внутренняя согласованность)

#### Scenario: Жюри проверяет цитату git-лога из секции 5.3

* WHEN жюри выполняет `git log --format=%s -1 f010348`
* THEN вывод совпадает со строкой панели в PDF дословно
* AND длинный subject `c2a331a` обрезан только с явным «…»

### Requirement: PDF собирается воспроизводимо из репозитория

PDF `docs/submission/digital-deanery-process.pdf` ДОЛЖЕН (MUST) иметь
исходник `docs/submission/process.html` и сборщик
`docs/submission/build-pdf.mjs` (Playwright Chromium, A4, print-background),
запускаемый командой `node docs/submission/build-pdf.mjs` из корня
репозитория. Шрифт Inter (OFL) ДОЛЖЕН (MUST) лежать в
`docs/submission/fonts/`. Скриншоты ДОЛЖНЫ (MUST) браться из
`docs/design/screenshots/` и `docs/shots/` — бинарные ассеты не
дублируются. Описания PDF в `docs/SUBMISSION.md` и
`docs/submission/COMMENT.md` ДОЛЖНЫ (MUST) соответствовать фактическому
содержимому.

#### Scenario: Пересборка PDF из исходника

* WHEN выполняется `node docs/submission/build-pdf.mjs` из корня репозитория
* THEN файл `docs/submission/digital-deanery-process.pdf` создаётся заново
  (A4, фон печатается, Inter подключён локально)
* AND исходные скриншоты не копируются в docs/submission (ссылки относительные)

#### Scenario: Описания PDF не расходятся с содержимым

* WHEN читатель открывает `docs/SUBMISSION.md` или `docs/submission/COMMENT.md`
* THEN описание PDF упоминает: честный блок об опросе, полный перечень
  инструментов (включая Higgsfield), неудачные варианты, защиту простыми
  словами и ручные этапы
