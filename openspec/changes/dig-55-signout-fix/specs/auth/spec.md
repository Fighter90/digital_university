# Аутентификация и доступ — delta (DIG-55)

## MODIFIED Requirement: Выход

Кнопка «Выйти» (меню аватара и экран настроек) обязана ЗАВЕРШАТЬ сессию:
submit-форма server action, удаление строки сессии в БД и сброс обеих кук.
Ссылка-редирект на `/login` без завершения сессии запрещена.

#### Scenario: Выход на текущем устройстве

- **WHEN** пользователь нажимает «Выйти» в меню аватара
- **THEN** server action удаляет строку сессии из хранилища, сбрасывает
  куки `__Host-session` и `__Host-role` (Max-Age=0) и редиректит на
  `/login?signedOut=1`

#### Scenario: Подтверждение выхода на экране входа

- **WHEN** открыт `/login?signedOut=1`
- **THEN** над формой входа виден статус «Вы вышли из кабинета»
  (`role="status"`); без параметра статус не показывается

#### Scenario: Сброшенные куки не перезаписываются

- **WHEN** мутящий запрос (server action выхода) возвращает сброшенные куки
- **THEN** middleware не пере-выдаёт `__Host-session`/`__Host-role` на этом
  ответе (sliding renewal только для GET/HEAD) — в браузере кук не остаётся

## ADDED Requirement: Запрет кэширования защищённых экранов

#### Scenario: Back после выхода не возвращает кабинет

- **WHEN** пользователь возвращается «Назад» на защищённый экран после выхода
- **THEN** документ запрошен заново (`Cache-Control: no-store, max-age=0,
  must-revalidate`), middleware без сессии уводит на `/login?next=…`;
  кэшированная копия кабинета не показывается никогда

#### Scenario: Публичные пути не меняют кэширование

- **WHEN** запрошен публичный путь (`/`, `/login`, `/_next/*`, …)
- **THEN** middleware не добавляет свой `Cache-Control` (умолчания фреймворка
  и immutable-кэш статики сохранены)
