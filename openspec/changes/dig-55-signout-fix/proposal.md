# DIG-55 — «Выйти» не работает на проде: завершение сессии и запрет кэша

## Зачем

На проде (ostrov.store) нажатие «Выйти» в меню аватара не завершало сессию:
пункт меню был ссылкой-заглушкой на `/login` — она не вызывала server action,
строка сессии в БД и куки `__Host-session` / `__Host-role` оставались живыми.
Дополнительно «Назад» после выхода возвращал кабинет из back/forward кэша:
защищённые экраны не имели `Cache-Control: no-store`.

## Что меняется

1. **«Выйти» — submit-форма server action** `signOutAction` в `UserMenu`
   (было: `<Link href="/login">`). Важно: кнопка не закрывает меню в
   `onClick` — размонтирование формы до завершения клика отменяло отправку.
2. **Оба действия выхода** (`signOutAction`, `signOutAllDevicesAction`)
   удаляют строку сессии в БД, сбрасывают обе куки и редиректят на
   `/login?signedOut=1`.
3. **Экран входа** показывает сообщение «Вы вышли из кабинета»
   (`role="status"`) по параметру `?signedOut=1`.
4. **Middleware ставит `Cache-Control: no-store`** на все защищённые экраны
   (публичные пути не трогаются), и не пере-выдаёт куки на мутящих запросах
   (POST), чтобы сброшенные куки действия выхода не перезаписывались.

## Non-goals

- Переработка экрана входа (это DIG-18), смена параметров cookie (DIG-11).
- Чистка накопленных сессий в демо-БД (операционная задача, не код).
- Прунинг истёкших сессий в хранилище (отдельная задача).
