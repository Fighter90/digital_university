# Delta: docs — README актуален, устаревания wiki/docx помечены

## MODIFIED Requirements

### Requirement: Индекс документации в README

Требование «Индекс документации в README» — обязательное (MUST): README
(RU и EN) содержит раздел быстрых ссылок на документацию (help, assistant,
architecture, security, deploy, figma-screens, user-guide, admin-guide,
accompanying-docs, mcp, sdd, wiki), плашку «Концепт для конкурса» и отражает
текущий набор функций продукта: версия для слабовидящих (DIG-100), «Поделиться»
и экспорт расписания MD/XLSX/PDF (DIG-101), МСП, новости, задачи, кабинет
сотрудника.

#### Scenario: README ведёт на новые разделы

- **WHEN** читатель открывает README.md или README.en.md
- **THEN** в таблице быстрых ссылок есть docs/wiki/ со ссылкой на отчёт
  устареваний docs/REPORT-112.md; функции DIG-100 и DIG-101 упомянуты;
  в EN README заполнен раздел «Mandatory core»

#### Scenario: README не противоречит коду

- **WHEN** проверяются факты README против репозитория
- **THEN** нет утверждений вида «вход/БД будут подключены в следующих
  задачах» — вход и БД работают; тест docs-facts остаётся зелёным

## ADDED Requirements

### Requirement: Отчёт устареваний REPORT-112

Требование «Отчёт устареваний» — обязательное (MUST): расхождения docs/wiki/
и docs/docx-описание/ с кодом фиксируются списком в `docs/REPORT-112.md`
(пофайлово: что устарело, что актуально, рекомендация), без переписывания
самих документов в этой задаче.

#### Scenario: wiki и docx не переписываются, но честно помечены

- **WHEN** читатель открывает docs/REPORT-112.md
- **THEN** для каждого файла docs/wiki/ указан статус (устарело/актуально)
  с конкретными пунктами (DIG-99…103, DIG-120, DIG-124, DIG-112), а для
  docx-описания перечислены отсутствующие в нём функции
