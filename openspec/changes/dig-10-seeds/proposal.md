# DIG-10 — Сиды: вымышленные студенты, расписание, оценки, заявки

## Зачем

Демо для жюри и данные для e2e: БД должна наполняться правдоподобными,
полностью вымышленными данными одной командой `pnpm db:seed`. Даты расписания
должны «жить» относительно текущей недели, чтобы демо не протухало до 28 ноября
и после.

## Что входит

- `prisma/schema.prisma` — минимальная схема под состав сида (студенты, сотрудник,
  дисциплины с элементами контроля и оценками по 10-балльной шкале, расписание
  семестра с переносами, сессия, заявки с историей, уведомления, новости, FAQ,
  обращения с перепиской). Дальнейшие задачи (DIG-18+) расширяют схему.
- `prisma/seed-data.ts` — чистые (без Prisma) билдеры данных: детерминированный
  PRNG, скользящий семестр, недельная сетка, исключения текущей недели.
- `prisma/seed.ts` — идемпотентный сид: транзакция «стереть и пересоздать»,
  повторный запуск не дублирует данные.
- Скрипты `db:seed` / `db:migrate`, bcrypt-хэши паролей в сидах, открытые
  пароли — только в README для жюри.

## Non-goals

- Экраны, NextAuth, server actions, rate-limit входа (DIG-18+).
- Реальные ПДн и интеграции с системами вуза — запрещены AGENTS.md.
- Данные для кабинета сотрудника (списки чужих заявок) — ролями займётся DIG-48.
