# Delta: экран «Финансы» (DIG-41)

## ADDED Requirements

### Requirement: Сводка финансов студента

На `/finance` показывается сводка: форма обучения (бюджет или договор),
стипендия (вид, сумма в месяц, дата ближайшей выплаты) и задолженность
(сумма и срок) или «Задолженности нет».

#### Scenario: У бюджетника экран не пустой

- **WHEN** студент с формой финансирования «бюджет» открывает `/finance`
- **THEN** видна сводка с формой «Бюджетная основа», стипендией (вид,
  сумма, ближайшая выплата) и «Задолженности нет»
- **THEN** история выплат содержит стипендии и материальную помощь

#### Scenario: Задолженность платника

- **WHEN** у студента-платника есть платёж в статусе «К оплате»
- **THEN** в сводке показывается сумма к оплате и срок, бейдж ошибки

### Requirement: Договор на обучение (только платное)

Для платного обучения показывается блок договора: номер, подпись,
стоимость семестра, прогресс «оплачено из», график платежей таймлайном
со статусом каждого платежа; у оплаченных платежей — «Скачать квитанцию».

#### Scenario: График платежей таймлайном

- **WHEN** студент-платник открывает `/finance`
- **THEN** виден блок договора с номером, стоимостью семестра и таймлайном
  платежей, у каждого платежа статус («Оплачен» / «К оплате до …» /
  «Ожидается»)
- **THEN** у оплаченного платежа есть ссылка «Скачать квитанцию»

#### Scenario: Бюджетнику блок договора не показывается

- **WHEN** студент-бюджетник открывает `/finance`
- **THEN** блока договора нет (секция отсутствует в разметке)

### Requirement: Документы с фильтром и скачиванием

Список финансовых документов (договоры, допсоглашения, акты, квитанции,
счета) с пилюлями-фильтром по виду и скачиванием демо-PDF через
GET `/api/finance/documents/<id>`.

#### Scenario: Фильтр по виду документа

- **WHEN** студент нажимает пилюлю «Квитанции»
- **THEN** в списке остаются только квитанции; «Все» возвращает полный список

#### Scenario: Скачивание доступно только владельцу

- **WHEN** студент запрашивает `/api/finance/documents/<id>` документа из
  СВОЕГО набора
- **THEN** сервер отдаёт PDF (Content-Disposition: attachment)
- **WHEN** сотрудник или чужой/неизвестный id
- **THEN** единый ответ 404, попытка чужого — в AuditLog

### Requirement: История выплат

История стипендий и материальной помощи: вид, сумма, дата, свежие сверху.

#### Scenario: Выплаты упорядочены

- **WHEN** студент открывает `/finance`
- **THEN** список выплат отсортирован по дате по убыванию, суммы
  положительные, формат «48 000 ₽»

### Requirement: Действия → мастер заявки

Кнопки «Заявление на материальную помощь» и «Справка о размере стипендии»
ведут в мастер заявки с предвыбором типа (`/requests?order=…`).

#### Scenario: Предвыбор типа из каталога финансов

- **WHEN** студент нажимает «Справка о размере стипендии»
- **THEN** мастер открывается с типом `SCHOLARSHIP_CERT`
- **WHEN** студент нажимает «Заявление на материальную помощь»
- **THEN** мастер открывается с типом `MATERIAL_AID`

### Requirement: Нет реальных реквизитов и платёжных форм

Ни экран, ни демо-PDF не содержат банковских реквизитов (БИК, ИНН, КПП,
расчётный счёт, р/с), платёжных форм и кнопок оплаты; демо-PDF помечен
«Концепт для конкурса» и «не является платёжным документом».

#### Scenario: Запрет реквизитов

- **WHEN** рендерится `/finance` (любая форма финансирования) или строится
  демо-PDF финансового документа
- **THEN** в разметке/строках документа нет подстрок БИК, ИНН, КПП,
  «Расчётный счёт», «р/с», «IBAN»

### Requirement: Доступ по роли

Экран и PDF-роут доступны только студенту: контекст строится из живой
сессии, сотрудник получает пустое состояние (экран) или единый 404
(PDF), отказ пишется в AuditLog (ROLE_MISMATCH).

#### Scenario: Сотруднику студенческих финансов нет

- **WHEN** сотрудник деканата открывает `/finance`
- **THEN** видит «Экран доступен студентам» без финансовых данных,
  попытка зафиксирована в AuditLog
