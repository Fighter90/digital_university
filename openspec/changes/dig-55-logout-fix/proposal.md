# DIG-55 — Баг: кнопка «Выйти» не работает на проде

## Зачем

На проде (ostrovok.store) нажатие «Выйти» не разлогинивает. Диагностика
нашла **три** независимых дефекта, дающих вместе наблюдаемый симптом:

1. **Кнопка-заглушка** (главная причина): пункт «Выйти» меню аватара
   (DIG-14) был обычной ссылкой `<Link href="/login">` — server action
   не вызывался, сессия и куки не удалялись, а `/login` мгновенно
   возвращал залогиненного на `/dashboard` (`redirect('/dashboard')`
   в `LoginPage`).
2. **Гонка cookie-очистки со скользящим продлением**: middleware
   пере-выставлял `__Host-session` на **любом** разрешённом запросе,
   включая POST server actions. На ответе logout кука-очистка
   (`Max-Age=0`) конкурировала с пере-выставленной куки-продлением
   (последний `Set-Cookie` побеждает, порядок слоёв не гарантирован) —
   выход через «Настройки» тоже мог не разлогинить.
3. **Кэш**: защищённые страницы не имели явного `Cache-Control: no-store`,
   поэтому «Назад» после выхода мог показать кабинет из back/forward
   кэша браузера.

## Что сделано

- «Выйти» в меню аватара — submit-кнопка внутри `<form action={signOutAction}>`;
  action удаляет сессию в БД и обе куки (`__Host-session`, `__Host-role`).
- **Важно**: кнопка НЕ закрывает меню в `onClick` — размонтирование формы
  до завершения клика отменяет submit, и сессия не завершается. Меню
  закрывает сама навигация action'а на `/login`.
- Оба выхода (`signOutAction`, `signOutAllDevicesAction`) редиректят на
  `/login?signedOut=1`; страница входа показывает `role="status"`-сообщение
  «Вы вышли из кабинета…».
- `shouldSlideAuthCookies` не продлевает куки на мутациях (POST/PUT/DELETE/
  PATCH): навигации — GET/HEAD и куки никогда не очищают, а action'ы
  единолично владеют cookie-судьбой своего ответа.
- `cacheControlFor()` — чистая функция в `route-guard.ts`: защищённые
  страницы получают `Cache-Control: no-store, max-age=0, must-revalidate`
  из middleware; публичные пути сохраняют дефолты фреймворка (статика
  не затронута).

## Non-goals

- Восстановление пароля, «Госуслуги» — вне концепта (DIG-11/DIG-18).
- Слепое продление мёртвой куки на публичных GET (middleware не может
  проверить БД на edge) — не влияет на безопасность: серверная резолюция
  сессии всегда идёт по хранилищу; отдельная задача не требуется.
- Предсуществующие флаки других спек (grades-page demo-данные, DIG-18
  heading) — вне этой задачи.
