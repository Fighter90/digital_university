# DIG-63 — delta: Календарная подписка (ICS)

## ADDED Requirements

### Requirement: Живая подписка на календарь по персональной ссылке

Экран «Сессия» ОБЯЗАН (MUST) отдавать студенту персональную подписанную
ссылку на живой ICS-фид; скачивание файла-снимка (`GET /api/session/ics`)
заменено подпиской `GET /api/calendar/ics?token=…`. Фид ДОЛЖЕН (MUST)
собираться на каждый запрос: изменения расписания и контрольных точек
деканатом попадают в календарь подписчика при следующем обновлении
клиентом.

#### Scenario: Студент получает персональную подписанную ссылку

- **WHEN** студент открывает экран «Сессия»
- **THEN** на странице карточка «Подписка на календарь» с абсолютной
  ссылкой `https://<host>/api/calendar/ics?token=v1.…` и кнопкой
  «Скопировать»; ссылка персональная и подписана HMAC-секретом сервера

#### Scenario: Ссылка стабильна между визитами

- **WHEN** студент повторно открывает экран «Сессия» в период той же
  подписки
- **THEN** ссылка идентична прежней (одна активная подписка на студента —
  календарь подписчика не ломается)

#### Scenario: Состав фида — расписание и дедлайны

- **WHEN** календарный клиент запрашивает валидную ссылку подписки
- **THEN** ответ `text/calendar` (VCALENDAR) содержит пары группы
  студента за текущий семестр (отменённые — с пометкой «Отменена», то
  есть после переноса аудитории/времени событие обновляется) и все
  контрольные точки сессии группы (экзамены, зачёты, пересдачи),
  отсортированные по времени начала

#### Scenario: Изоляция фида по группе

- **WHEN** студент группы A запрашивает свою ссылку
- **THEN** фид содержит только события группы A; события группы B и
  персональные данные владельца (studentId/email/ФИО) через фид не
  передаются

### Requirement: Токен подписки — подписанный bearer, доступ только владельца

Ссылка ОБЯЗАНА (MUST) иметь вид `v1.<tokenId>.<hmac>`: tokenId —
128-битный случайный nonce, hmac — HMAC-SHA256(tokenId) с секретом
`ICS_TOKEN_SECRET` (.env.example; локально fallback на AUTH_SECRET — оба
серверные). Путь `/api/calendar/ics` ДОЛЖЕН (MUST) быть публичным
(календарные клиенты не отправляют cookies), доступ держится на
bearer-токене; любой отказ — единый 404 без причины (нет оракула
существования).

#### Scenario: Подделка ссылки отсекается до хранилища

- **WHEN** запрошен фид с токеном с повреждённой подписью, чужим секретом
  или в неверном формате
- **THEN** ответ — единый 404; запрос не доходит до поиска строки

#### Scenario: Без токена ответ не отличается от отозванного

- **WHEN** запрошен `/api/calendar/ics` без параметра token
- **THEN** ответ — тот же единый 404 (контракт uniform not-found), ответ
  несёт `Cache-Control: private, no-store`

#### Scenario: Сотруднику подписка не выдаётся

- **WHEN** сотрудник деканата открывает экран «Сессия»
- **THEN** карточка подписки не рендерится, попытка выдачи фиксируется в
  аудите (ROLE_MISMATCH)

### Requirement: Выход отзывает подписку навсегда

Оба выхода из кабинета («Выйти» и «Выйти со всех устройств») ОБЯЗАНЫ (MUST)
удалять строку подписки владельца; прежняя ссылка умирает навсегда —
повторный вход выдаёт новый tokenId и новую ссылку. Логин для отзыва
ДОЛЖЕН (MUST) читаться из живой сессии (никогда из ввода); сбой отзыва
не блокирует сам выход.

#### Scenario: Выход убивает ссылку

- **WHEN** студент вышел из кабинета и запрошена прежняя ссылка фида
- **THEN** ответ 404 — и остаётся 404 после повторного входа

#### Scenario: Повторный вход — новая ссылка

- **WHEN** студент после выхода снова входит в кабинет и открывает
  «Сессию»
- **THEN** выдана новая подписанная ссылка, прежняя не оживает

## Историческая заметка (не дельта)

**Удалено из предложения**: требование «Скачивание ICS-снимка сессии»

**Reason**: переработано в живую подписку — снимок устаревает в момент
скачивания и не отражает изменения расписания.
**Migration**: прежняя кнопка «Добавить всю сессию в календарь» заменена
карточкой подписки; события сессии входят в состав фида подписки.

#### Scenario: Старый роут не существует

- **WHEN** клиент запрашивает `GET /api/session/ics`
- **THEN** приложение отвечает страницей 404 (роут удалён); единственная
  ICS-поверхность — `/api/calendar/ics`
