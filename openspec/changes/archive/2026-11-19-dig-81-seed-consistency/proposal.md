# DIG-81 — Сид-согласованность: логины↔ФИО на чипах, уведомления из расписания/сессии, группа ЭК-11 непустая (BUG-07, BUG-08, BUG-11)

## Зачем

QA-регресс 18.11 (BUG-07, BUG-08 средние; BUG-11 средний) — расхождения
демо-данных между модулями, заметные жюри:

1. **BUG-07.** Чип «Анна Ковалёва · ПИ-21» подставляет логин `anna.smirnova`,
   «Илья Смирнов · ЭК-11» → `ilya.petrov`, сотрудник `dean.kovaleva` —
   фамилии чипа, логина и профиля рассказывают три разные истории. Жюри
   вводит данные вручную и видит «ошибку». Коммит 67b8bac выровнял ФИО сида
   под чипы, но сам разрыв «логин ↔ ФИО» не закрыл (это не один из двух
   вариантов, предложенных задачей).
2. **BUG-08.** Демо-уведомления описывают события, которых нет в
   расписании/сессии: «Базы данных … Б-204 вместо А-312» (переноса нет,
   аудиторий А-312/Б-204 не существует), «пересдача 21 декабря, ауд. А-401» /
   «25 ноября» против записи сессии (пересдача «Информатика» — через 7 дней,
   каб. 305), «семинар по матану сегодня отменён» при отсутствии отмены у
   ЭК-11, фиксированные даты («20 ноября», «18 декабря») вместо скользящих
   записей сида.
3. **BUG-11.** Группа ЭК-11 была из одного студента — рейтинг «1 из 1».
   67b8bac добавил трёх вымышленных сокурсников, но инвариант не закреплён
   юнит-тестом (регресс может вернуться).

## Что делаем

- **Канон идентичности (вариант 1 из задачи): ФИО ↔ логины.**
  Анна **Смирнова** (`anna.smirnova`), Илья **Петров** (`ilya.petrov`),
  Мария **Ковалёва** (`dean.kovaleva`). Чипы входа, demo-сид (memory),
  README и docs говорят одно и то же; prisma-сид уже использует эти ФИО —
  логины не меняются (меняются только отображаемые имена/emails).
- **Уведомления генерируются из тех же записей, что расписание/сессия**
  (`schedule`/`exams` demo-сида): перенос «Программирование» 214→305,
  перенос времени «Математический анализ» 9:00 вместо 10:40, отмена
  лаборатории «Физика» (текст «Что делать» — из записи пары), пересдача
  «Информатика» с датой/временем/кабинетом из записи `exm-pi21-4`. Дата в
  тексте вычисляется из записи, а не захардкожена («25 ноября» при запуске
  сида в другой день больше не врёт).
- **Юнит-тест `tests/demo-seed-consistency.test.ts`** (red-first):
  чипы ↔ ФИО/группа/пароль сида; ФИО едины между demo-сидом и prisma-сидом;
  каждое расписание/сессионное уведомление находит свою запись (дата,
  время, аудитория); фантомные аудитории (Б-204/А-312/А-401) запрещены;
  в ЭК-11 ≥ 3 студентов.

## Non-goals

- Не меняем логины/пароли демо-аккаунтов (вариант «student1/student2» не
  выбран) и группы prisma-сида (ИВТ-21/ЭК-23) — prisma-хранилище используется
  только для аутентификации, ФИО из него в UI не показываются.
- Не трогаем финансовые дедлайны-уведомления («оплата до …») — они не
  ссылаются на расписание/сессию.
- Не меняем статусы Linear и инфраструктуру роя.
