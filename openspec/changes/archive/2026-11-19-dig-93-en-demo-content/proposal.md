# DIG-93 — EN: убрать кириллицу из демо-контента кабинета

## Зачем

DIG-87/88/89 перевели интерфейс кабинета, но ДЕМО-КОНТЕНТ (сид: дисциплины,
преподаватели, имена, тексты уведомлений, названия заявок, события, новости,
задачи, обращения, МСП, ДПО, сессия) на `locale=en` частично оставался
кириллицей, а инициалы топбара считались из RU-ФИО («АС»). Аудит видимого
рендера: /dashboard — 1042 кириллических символа, /tasks — 462,
/grades/session — 458, /requests — 414, /feedback — 870, /people — 326,
/deanery — 292, /grades — 294, /msp — 118, /dpo — 57, /profile — 43,
/more — 36; на каждой странице ≥15 — инициалы «АС».

Цель: при `locale=en` в кабинете НОЛЬ кириллицы в видимом рендере.
RU-рендер не меняется ни на байт.

## Что делаем

- Имена демо-персон (студенты, преподаватели, сотрудники, авторы МСП) —
  таблица `PEOPLE_NAME_EN` (транслит, западный порядок) в `ru-translit.ts`;
  хелперы `enPersonName / localizePersonName / localizeInitials`.
- Инициалы топбара (`UserMenu`) и аватаров: EN — латиница из EN-имени
  («Анна Смирнова» → «AS»), фолбэк — из префикса email/логина; RU — как было.
- Дисциплины, преподаватели, заметки пар, элементы контроля: локализация
  в view-билдерах (dashboard/session/gradebook/event-details/grade-insight)
  с guard `locale === 'en'` — канонические данные не меняются.
- Заявки: названия с параметром (`Справка об обучении · для военкомата` →
  `Enrollment certificate · for the military office`), причины доработки и
  номера «ЗД-…» (транслит «ZD-…», как в карточке) — `localizeRequestCardTitle`,
  `localizeRequestReason`.
- Задачи (/tasks): агрегат `getTasks` получает locale; глаголы и источники
  шести типов локализует `localizeTasksData` (глагол, уже собранный словарём
  с RU-титулом внутри, разбирается двуязычно).
- Сессия: `getSession` получает locale; шапка (сезон/диапазон/отсчёт),
  статусы допуска, причины недопуска, заметки пересдач — `localizeSessionData`.
- Успеваемость/зачётка: имена дисциплин/преподавателей/долгов/работ инсайта
  в EN-словаре элементов контроля (`ELEMENT_NAME_EN`).
- Обращения: превью последнего сообщения — по id (`TICKET_MESSAGES_EN`),
  композер — EN-названия заявок/дисциплин (значения `<option>` — канон).
- Обратная связь: страница передаёт locale в список/ленту, тексты сида —
  `FEEDBACK_TEXTS_EN`, обещание срока — `feedbackResponsePromise(locale)`.
- Справочник: имена — транслит, «Ваши дисциплины» — EN-имена.
- МСП: авторы — транслит, логотип-буква — из локализованного названия.
- ДПО: тег факультета («ИТ» → «IT») в `localizeProgram`.
- Профиль: имя владельца — транслит, срок семестра — `profile.term.*`.
- Меню: ключи `menu.finance / menu.msp / menu.events` (раньше — RU-фолбэк
  nav-items в боковом рельсе и на «Ещё»).
- AI-гид: локаль в компоненте (`aiguide.*`), EN-шаги экскурсии и сценарии
  (`guideTourSteps/guideScenarios` по тем же id), голосовой ввод — подписи
  и язык распознавания по локали; aria-подпись AiFab — из словаря.
- Расписание: карточки (`EventCard`), панель деталей (`toEventDetailsView`),
  фильтр преподавателя (value — канон, подпись — локаль).

## Non-goals

- RU-значения словарей и сид-данных не меняются ни на байт.
- Схема БД, prisma/seed.ts, `scripts/swarm/` не трогаются.
- Логин/лендинг/verify/ PDF-маршруты — вне скоупа (как в DIG-89).
- Поиск и фильтрация — по каноническим RU-значениям (меняются только
  видимые подписи); это осознанный контракт прототипа.

## Риски

- Закрытый набор строк сида: неизвестная RU-строка (новая демо-запись без
  маппинга) — RU-фолбэк, фиксируется расширенным no-Cyrillic тестом.
- Обратные ссылки (преподаватель → /people/<id>) строятся по каноническому
  ФИО — локализация только подписи, сшивка не зависит от локали.
