# Proposal: детальная документация (wiki) + README — DIG-59

## Зачем

Код и экраны растут быстрее, чем документация для людей: у жюри и нового
разработчика нет одного места «как этим пользоваться» и «как это устроено».
README рассказывает про запуск и рой, но не про студенческие сценарии
(вход → расписание → оценки → заявка → справка с QR) и не показывает,
как выглядит продукт. Часть docs (architecture, security, deploy) уже есть,
но не собрана в индекс быстрых ссылок, а из кабинета в документацию не ведёт
ни одной ссылки.

## Что

- **docs/help.md** — справка студента: вход и сеансы, главная с виджетами,
  расписание (день/неделя/месяц, переносы), успеваемость («как у меня дела»,
  зачётка, сессия, пересдачи, апелляция), заявки и справки (каталог, заказ,
  статусы, номер SR-…), справка с QR (код проверки, PDF, публичная проверка
  /verify/<код>, отзыв), уведомления (концепт + что уже работает: счётчик,
  каналы, тихие часы), поиск ⌘K, настройки. Честные пометки «в разработке»
  для разделов-заглушек (экран уведомлений, деканат, AI-ассистент).
- **docs/assistant.md** — цифровой ассистент: роль в продукте, где живёт
  (пункт меню, FAB, хэндоффы из поиска/FAQ/сессии), возможности и примеры
  запросов, ограничения (демо-режим), MCP-интеграции (Product Hunt,
  Календарь, Деканат-API) с шагами подключения и правилами токенов.
- **docs/architecture.md** — дополнен коротким разделом «Безопасность»
  (сводка + ссылка на docs/security.md) и перекрёстными ссылками на
  help/assistant.
- **README.md** — раздел «Скриншоты» (готовые снимки 1440/360 из
  docs/design/screenshots) и «Быстрые ссылки» на всю документацию
  (help, assistant, architecture, security, deploy, figma-screens, SDD,
  CHANGELOG, ai-log). Плашка «Концепт для конкурса» — уже есть, сохраняется.
- **Перекрёстные ссылки из кабинета**: один источник ссылок
  `src/lib/docs-links.ts` (GitHub blob, ветка main); карточка
  «Справка и документация» на вкладке «Главная» настроек; ссылка на
  docs/assistant.md из справки MCP и со страницы AI-ассистента.

## Non-goals

- Не рендерим markdown-документы внутри приложения (отдельный роут/вьюер) —
  документация живёт в репозитории, ссылки ведут на GitHub (репозиторий
  публичный, ветка main).
- Не меняем поведение существующих экранов, кроме добавления ссылок.
- Не трогаем заглушки уведомлений/деканата/AI (свои задачи: DIG-34…36,
  DIG-38, DIG-39, DIG-46).

## Риски

- Ссылки на GitHub ломаются при переименовании репозитория/ветки — база
  собрана в одну константу `DOCS_BASE_URL` с тестом на существование файлов.
