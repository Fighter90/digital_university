# Proposal: рейтинг группы по среднему баллу (DIG-103)

## Зачем

Сводка /grades показывает только личное место студента («2 из 5», DIG-80),
но не сам рейтинг: студент не видит, кто в группе впереди и насколько.
Задача добавляет «Рейтинг группы» — таблицу студентов СВОЕЙ группы по
среднему баллу. Агрегат среднего балла единый (DIG-80): средний каждого
студента считает тот же `gpaOfStudent` модуля performance — SQL/формулы
не дублируются, средний и место на странице рейтинга совпадают с кольцом
GPA и «N из M» сводки.

## Что

- `src/lib/group-rating.ts` — чистая логика (red-тесты
  `tests/group-rating.test.ts`): сортировка по среднему desc, при
  равенстве — по алфавиту (ru); равные средние — ОДНО место
  (competition ranking, как «Рейтинг в группе» сводки); студенты без
  оценок — после ранжированных по алфавиту, без места;
  `formatAverageScore` — средний всегда двумя знаками («87,00»).
- `getGroupRating(db, ctx)` в `src/server/data/performance.ts` (фасад,
  owner-scope): группа ТОЛЬКО из `ctx.groupName` (сессия, не URL);
  сотрудник — null + аудит ROLE_MISMATCH; в строках только ФИО и средний
  балл — чужие оценки по дисциплинам не раскрываются (приватность
  рейтинга). Возвращает `GroupRatingView { groupName, rows, hasAnyGrades }`.
- Страница `/grades/rating` (`page.tsx` + `loading.tsx`): таблица «место
  №, ФИО, средний балл (2 знака)» с тонким прогресс-баром к шкале проекта
  0–100; строка владельца подсвечена + метка «вы» (словарь); группа без
  единой оценки — honest empty-state; группа из одного студента — таблица
  из одной строки; обратная ссылка «← К успеваемости»; сотруднику —
  заглушка. Скелетон загрузки переиспользует GradesSkeleton.
- Сводка `/grades`: в блоке «Рейтинг в группе» появилась ссылка
  «Весь рейтинг группы» → `/grades/rating` (компактная страница выбрана
  вместо блока-таблицы: сводка остаётся компактной, таблица группы может
  быть длинной).
- Словарь: ключи `grades.rating.*` + `title/meta/loading.gradesRating`
  RU/EN парами, паритет ключей сохраняется.

## Данные и доступ (IDOR)

`getGroupRating` строится ТОЛЬКО из ctx живой сессии: groupName — из
сессии, параметром не передаётся (чужую группу получить невозможно по
построению; юнит-тест закрепляет: студент ЭК-11 не попадает в рейтинг
ПИ-21 и наоборот). Сотрудник (studentId = null) — null + запись в
AuditLog (ROLE_MISMATCH). Наружу уходят только ФИО, средний балл, место
и флаг «строка владельца» — чужие персональные оценки не раскрываются.

## Не делаем (вне скоупа)

- Раскрытие оценок сокурсников по дисциплинам (приватность — только
  средний).
- Закрепление «моей строки» при прокрутке (опционально по задаче — не
  требуется для таблицы группы).
- Исторические рейтинги по семестрам (только накопленный за всё время,
  как GPA «за всё время» агрегата).
