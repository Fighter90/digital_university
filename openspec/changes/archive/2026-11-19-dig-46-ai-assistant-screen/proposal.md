# Proposal: экран «AI-ассистент» с карточками действий (DIG-46)

## Зачем

В аудированном ЛК аналога нет: вопросы студента тонут в FAQ, который не находит
ответ, и в почте деканата. AI-ассистент — главная фишка концепта «Цифровой
деканат»: он отвечает на вопросы по учёбе и превращает ответы в **карточки
действий** (мини-расписание, калькулятор цели, предзаполненная заявка, статья
FAQ). Серверная часть (прокси к модели, инструменты, защита от prompt
injection) — отдельная задача agent:backend/agent:security; этот раунд —
экран и клиентский детерминированный «движок» на реальных данных студента.

## Что

- **Полный экран `/assistant`** (Figma «09 · AI-ассистент», референс — блок
  «Оценка резюме · AI» в ResumeCraft): приветствие с именем, 4 подсказки
  по контексту («Что у меня завтра?», «Сколько нужно на экзамене по БД,
  чтобы получить 8?», «Закажи справку для военкомата», «Как оформить
  академический отпуск?»), лента сообщений со стримингом ответа.
  Канонический путь раздела — существующий `/ai-assistant` (глубокие ссылки
  DIG-28 `?intent=exam-prep&discipline=…`, меню, топбар и каталог сервисов
  уже ссылаются туда); `/assistant` отвечает 307-редиректом.
- **Плавающая кнопка на всех экранах** открывает выезжающую панель с тем же
  чатом (правый drawer на десктопе, весь экран на 360 px; фокус-ловушка и
  Esc на базе Base UI). Поле ввода не перекрывается клавиатурой:
  `interactive-widget=resizes-content` в viewport-мете.
- **Карточки действий в ответах**:
  - мини-расписание на день (завтра или ближайший учебный день, переносы и
    отмены как на основном экране расписания);
  - карточка дисциплины с калькулятором «что нужно на экзамене» — чистая
    функция `needForTargetPure` из DIG-25 (шестнадцатерично та же арифметика,
    что у успеваемости), цели-чипы 60/70/80/90 + свой ввод;
  - предзаполненная заявка («Справка для отсрочки от армии») с кнопкой
    «Подтвердить и отправить» — **ассистент сам ничего не отправляет**:
    заявка создаётся только явным подтверждением пользователя, server
    action с проверкой владельца (IDOR-контракт DIG-12);
  - ссылка на статью FAQ («Академический отпуск»).
- **Источник под ответом**: «По данным: расписание» / «По данным: зачётка,
  план контроля» и т.п.
- **Отказы**: на вопросы не про учёбу и на просьбы показать чужие данные —
  вежливый отказ с примером, что можно спросить.
- **«Новый диалог», история диалогов, «Сообщить о неверном ответе»**:
  история — в памяти панели/вкладки (персистентность — задача бэкенда,
  модели AiChat/AiMessage уже в каноне DIG-9); «Сообщить о неверном ответе» —
  двухшаговое подтверждение, создаёт обращение в деканат через слой данных
  (видно в «Связи с деканатом»).

## Правила и допущения (зафиксированы тестами)

- Движок ассистента — чистый модуль `src/lib/assistant-engine.ts` (без React
  и серверных импортов): намерение вопроса → ответ + карточки + источники.
  Работает на данных агрегата `getAssistantContext` (скоуп по ctx — чужие
  данные недостижимы по построению).
- Распознавание вопросов детерминированное (регэкспы + словарь): 4 подсказки
  задачи распознаются точно; «БД» — сокращение по инициалам названия
  дисциплины («Базы данных»); цель «получить 8» трактуется как 80 из 100
  (десятибалльная × 10), «получить 85» — как 85.
- У Анны по «Базам данных» накоплено 25,5 из 100 (Проект 85, вес 0,3), Тест 2
  (0,2) и Экзамен (0,5) не сданы → честный ответ на подсказку про «8»:
  109 из 100 — недостижимо, максимум возможного итога 76; для 70 достаточно
  88. Ответ ассистента объясняет это и предлагает цель пониже (чипы в
  карточке) — расхождений с экраном «Успеваемость» нет.
- Заявка ассистента: whitelist каталога (`cert-defer`, ORDER + STUDENT),
  идемпотентность по заголовку (как запись на пересдачу DIG-28), номер
  `SR-…`, уведомление студенту. Сотруднику — отказ ROLE_MISMATCH + аудит.
- FAQ-каталог — `src/lib/faq-catalog.ts` с одной статьёй и страницей
  `/faq/<slug>` (сортировка ссылок единообразная, вымышленный контент);
  полный экран «Вопросы и ответы» — DIG-38, расширит этот каталог.
- Стриминг — клиентский (посимвольное появление текста, уважает
  `prefers-reduced-motion`); когда придёт серверный прокси (agent:backend),
  движок подменяется на fetch-стрим без изменения UI-контракта сообщений.

## Отклонения от текста задачи (обоснованные)

- «Полный экран `/assistant`» → канонический путь остаётся `/ai-assistant`,
  `/assistant` редиректит: 7 поверхностей (меню, «Ещё», топбар, «Спросить AI»
  на главной, каталог сервисов, глубокие ссылки сессии DIG-28 и их тесты)
  уже ссылаются на `/ai-assistant`; миграция путей — отдельная уборка.
- «Сколько нужно… получить 8?» → в прототипе 100-балльная шкала
  (docs/grading.md), «8» = 80 из 100; трактовка зафиксирована тестом.
- История диалогов — в памяти вкладки, не в БД: серверная часть ассистента —
  отдельная задача (agent:backend), модели канона уже есть.

## Вне скоупа

- Реальная LLM/прокси, инструменты ассистента, защита от prompt injection
  (agent:backend + agent:security — следующие задачи).
- Персистентность диалогов (AiChat/AiMessage) и серверный стриминг SSE.
- Экран «Вопросы и ответы» с поиском и категориями (DIG-38).
- Скриншот-верификация по Figma REST API — токен не задан, вёрстка по
  описанию фрейма и токенам DIG-13, сверка скриншотами Playwright.
