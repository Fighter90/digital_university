# Delta-спека: deanery — обращения в деканат (DIG-39)

## ADDED Requirements

### Requirement: Список обращений студента

Требование «Список обращений студента» — обязательное (MUST): Экран «Обращения в деканат» показывает владельцу сессии ТОЛЬКО его обращения:
тема, публичный номер, статус («Открыто» / «Ждём вас» / «Решено»), последний
ответ и время последней активности. Сотруднику кабинета список недоступен
(пустое состояние + запись в AuditLog с причиной ROLE_MISMATCH).

#### Scenario: Студент видит только свои обращения

- **WHEN** студент Анна открывает `/deanery`
- **THEN** в списке только тикеты с `studentId = Анна`, отсортированные по
  времени последней активности (свежие сверху)
- **AND** ни один тикет другого студента не присутствует в ответе

#### Scenario: Попытка открыть чужое обращение неотличима от несуществующего

- **WHEN** студент запрашивает `/deanery/<номер чужого обращения>`
- **THEN** приложение отвечает тем же 404, что и для несуществующего номера
- **AND** попытка записана в AuditLog с причиной OWNERSHIP_DENIED (или
  NOT_FOUND для отсутствующего номера); тело ответа различий не содержит

### Requirement: Чат обращения

Требование «Чат обращения» — обязательное (MUST): Чат показывает сообщения студента и менеджера: аватар (инициалы), ФИО,
подпись роли «Менеджер программы» у сотрудника, вложения (имена файлов),
время; сообщения студента несут статус «Прочитано», когда менеджер их видел.
Открытие чата студентом помечает сообщения менеджера прочитанными.

#### Scenario: Переписка с менеджером программы

- **WHEN** студент открает чат своего обращения со статусом «Ждём вас»
- **THEN** видит свою реплику, ответ менеджера (аватар, ФИО, «Менеджер
  программы»), вложения и время каждого сообщения
- **AND** сообщение менеджера помечено прочитанным после открытия

### Requirement: Создание обращения

Требование «Создание обращения» — обязательное (MUST): Студент создаёт обращение: тема из фиксированного списка (Учебный план,
Оценки, Перевод, Академический отпуск, Другое), текст, до 3 вложений
(имена, каждое ≤ 5 МБ), опциональная привязка к СВОЕЙ заявке и дисциплине
СВОЕЙ группы. Обращение получает публичный номер `TS-ГГГГ-XXXXX` и статус
«Открыто».

#### Scenario: Привязка только к своим сущностям

- **WHEN** студент отправляет форму с номером чужой заявки или кодом
  дисциплины другой группы
- **THEN** создание отклоняется с ошибкой формы, обращение не создаётся

#### Scenario: Ответ студента возвращает обращение в работу

- **WHEN** студент отправляет сообщение в обращении со статусом «Ждём вас»
- **THEN** статус становится «Открыто» (менеджер должен ответить)

### Requirement: Подсказки FAQ перед отправкой

Требование «Подсказки FAQ перед отправкой» — обязательное (MUST): При наборе текста обращения студенту показываются до трёх подходящих статей
FAQ с заголовком «Возможно, это ответ на ваш вопрос»; совпадение — по ключевым
словам текста, статьи той же темы приоритетны.

#### Scenario: Подсказка по тексту вопроса

- **WHEN** студент набирает «как взять академический отпуск»
- **THEN** в блоке подсказок появляется статья про академический отпуск
- **AND** при вводе менее трёх символов подсказок нет

### Requirement: Уведомление о новом сообщении менеджера

Требование «Уведомление о новом сообщении менеджера» — обязательное (MUST): Новое сообщение менеджера в обращении студента создаёт уведомление (тип
TICKET, ссылка на чат) и переводит обращение в статус «Ждём вас»; если тип
«Обращения» выключен в матрице уведомлений студента, запись не создаётся.

#### Scenario: Менеджер отвечает — студент получает уведомление

- **WHEN** сотрудник отправляет сообщение в обращение студента своего
  факультета
- **THEN** статус обращения становится «Ждём вас», исполнителем записывается
  сотрудник
- **AND** в фиде студента появляется уведомление «Ответ по обращению» со
  ссылкой `/deanery/<номер>`
- **WHEN** тип «Обращения» выключен в настройках уведомлений студента
- **THEN** уведомление не создаётся (статус обращения меняется)

### Requirement: Обещание срока ответа

Требование «Обещание срока ответа» — обязательное (MUST): На экране списка и в чате видно «Обычно отвечаем в течение 1 рабочего дня».

#### Scenario: Обещание срока на экране

- **WHEN** студент открывает `/deanery`
- **THEN** под заголовком видна строка «Обычно отвечаем в течение 1 рабочего
  дня»
