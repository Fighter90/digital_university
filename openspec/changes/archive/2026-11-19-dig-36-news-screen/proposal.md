# Proposal: экран «Новости и объявления» (DIG-36)

## Зачем

В аудированном ЛК блок «Новости» — общий поток новостей вуза без привязки к
студенту, а баннер-карусель на главной вообще не связан с учёбой. Студент
видит чужие для себя сообщения (другого факультета, другого набора) и не
может быстро понять, что касается именно его группы. По задаче лента
пересобирается: вкладки «Моя группа / Мой факультет / Весь вуз» (по умолчанию
— личный скоуп), объявления деканата отдельной полосой «Важно» с пометкой
«Прочитано», фильтр по темам и полноценная страница новости.

## Что

- **Лента `/news`** (Figma «09 · Новости», блок на главной — «03 · Главная»):
  - вкладки скоупа: «Моя группа» (по умолчанию), «Мой факультет», «Весь вуз» —
    ссылки с сохранением темы фильтра (работают без JS, radiogroup со
    стрелками — как ViewSwitcher расписания);
  - полоса объявлений деканата сверху («Важно: изменился порядок пересдач»)
    с пометкой «Прочитано» после открытия;
  - фильтр по темам пилюлями: Все, Учёба, Мероприятия, Стипендии, Общежитие
    (горизонтальный скролл на 360 px);
  - карточка новости: обложка-иллюстрация (SVG с alt и `loading="lazy"`),
    дата, источник, заголовок, 2 строки текста.
- **Страница новости `/news/<id>`**: заголовок, дата, источник, автор, текст
  абзацами, вложения (статичные вымышленные файлы), «Поделиться ссылкой»
  (clipboard + fallback), возврат в ленту. Неизвестный id — честный 404.
- **Блок на главной**: карточки «Новости деканата» ведут на `/news/<id>`
  (было — общий фид уведомлений).
- **Данные**: контент — вымышленный каталог `src/lib/news-catalog.ts` (чистый
  модуль: темы, скоупы, обложки, вложения); отметки «Прочитано» — данные
  студента в слое DIG-12: порт (`listNewsReadIdsByStudent`,
  `markNewsReadByStudent`), memory-адаптер, owner-scoped по `studentId`.
- **Скоупинг**: `getNewsPage(db, ctx, {scope, topic})` фильтрует каталог по
  группе/факультету контекста; сотруднику (без группы) вкладка «Моя группа»
  заменяется на «Мой факультет». Дефолт ленты — личный скоуп студента,
  «Весь вуз» — только по явному выбору.

## Правила и допущения (зафиксированы тестами)

- Контент публичный внутри кабинета (как FAQ): статья доступна любому
  авторизованному пользователю — персональных данных в новостях нет;
  владелец проверяется только для отметки «Прочитано» (owner-scoped).
- Даты новостей фиксированные (ноябрь 2026, вымышленные) — карточки не
  «прыгают» между перезапусками прототипа (конвенция DIG-20).
- Обложки — статичные SVG (`public/news/covers/`), по одной на тему, с
  человеческим alt; ленивая загрузка (`loading="lazy"`, `decoding="async"`).
- Вложения — реальные статичные TXT-файлы (`public/news/files/`) с
  вымышленным содержимым: ссылки честно скачиваются, а не ведут в никуда.
- «Поделиться ссылкой» копирует текущий URL через clipboard API с
  execCommand-фолбэком; состояние «Ссылка скопирована» — aria-live.
- Открытие новости помечает её прочитанной (идемпотентно, в слое данных) —
  полоса объявлений показывает «Прочитано» после посещения.
- Единообразие текстов — автотест: «ёлочки», без двойных пробелов,
  заголовки без точки в конце.

## Отклонения от текста задачи (обоснованные)

- «Баннер-карусель на главной» аудита не воспроизводим: вместо карусели —
  горизонтальная лента карточек новостей с прокруткой (та же механика
  «Новости деканата» DIG-20), карусель без макета не изобретаем.
- Вложения — TXT, а не PDF: честные скачиваемые файлы с вымышленным
  содержимым; PDF-генерация вне скоупа задачи.

## Вне скоупа

- Кабинет сотрудника (DIG-48): сотрудник видит ленту в своём факультетском
  скоупе, но без студенческих пометок «Прочитано».
- Prisma-адаптер отметок «Прочитано»: прототип живёт на memory-адаптере
  DIG-12; сигнатуры порта owner-scoped и переносятся 1:1.
- Скриншот-верификация по Figma REST API — токен не задан, вёрстка по
  описанию фрейма и токенам DIG-13, сверка скриншотами Playwright.
