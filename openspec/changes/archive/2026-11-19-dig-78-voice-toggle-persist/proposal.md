# DIG-78 — Тумблер «Озвучка и голосовой ввод» не сохраняется (регресс)

## Зачем

E2E `e2e/voice-assistant.spec.ts` (второй сценарий, строка 58) падает: после
включения тумблера `voiceAssistant` на вкладке «Вид» (/settings) и перезагрузки
страницы переключатель снова показывает выключенное состояние. Пользователь
включает озвучку, значение не переживает перезагрузку — голосовые функции
(«Прослушать день», микрофон AI-гида) не возвращаются.

## Диагноз

Компонент `VoiceSettings` переключает `aria-checked` **оптимистично**: локальный
`setEnabled(next)` выполняется сразу по клику, а server action
`saveVoiceAssistantAction` уходит в `startTransition` параллельно. E2E ждёт
`aria-checked="true"` (появляется мгновенно, до записи в БД) и сразу делает
`page.reload()` — навигация может прервать in-flight POST server action'а,
значение в строке настроек не записывается, после перезагрузки читается старое.

В фазе «выключение» тест проходит: перед reload он ждёт статус
«Сохранено — …», который появляется только после завершения action'а. В фазе
«включение» такого ожидания нет — гонка воспроизводится.

## Что делаем

- `VoiceSettings` больше не отражает желаемое состояние до подтверждения от
  сервера: `aria-checked` меняется только после успешного завершения
  `saveVoiceAssistantAction` (включение → action → перечитанное значение).
  Статусная строка показывает «Сохранение…», пока action в полёте.
- Расширяем юнит-контракт: компонент вызывает action с новым значением и
  переводит переключатель в него только после `true`; при отказе — откат к
  исходному значению и сообщение об ошибке.
- Красный-первым юнит-тест: мок настроек → toggle → save → перечитать —
  значение сохранено; до фикса тест падает.

## Non-goals

- Не трогаем схему БД, data-слой (`updateOwnVoiceAssistant`) и сам action —
  запись в `StudentSettings` работает корректно.
- Не меняем остальные тумблеры настроек (reduceMotion и т.п. — отдельные
  компоненты с тем же паттерном, но их e2e ждут подтверждение и не страдают).
- Не трогаем `e2e/voice-assistant.spec.ts` — он фиксирует приёмочный контракт
  (aria-checked=true после включения и перезагрузки) и остаётся как есть.

## Риски

- Минимальные: меняется только клиентский компонент вкладки «Вид».
- IDOR не затрагивается: action по-прежнему скоуплен сессией
  (requireStudentCtx → ctx.studentId).
