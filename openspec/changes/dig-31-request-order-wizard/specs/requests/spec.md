# Delta: requests — мастер заказа справки или заявления (DIG-31)

## ADDED Requirements

### Requirement: Мастер заказа открывается внутри кабинета

Заказ справки ДОЛЖЕН (MUST) открываться внутри кабинета: точка входа
`/requests?order=<serviceId>` (каталог DIG-29) и CTA «Заказать
справку или заявление» на «Моих заявках». На десктопе — модальное окно,
на мобильном (360 px) — полноэкранный лист. Сотруднику вход недоступен.

#### Scenario: студент открывает заказ из каталога

- WHEN студент открывает `/requests?order=cert-defer`
- THEN мастер открыт на шаге 1 с выбранным документом «Справка для отсрочки
  от армии», сроком «1 день», форматом PDF и одной строкой пользы

#### Scenario: сотруднику мастера нет

- WHEN сотрудник открывает `/requests`
- THEN CTA не показывается и мастер не открывается даже с `?order=`

### Requirement: Шаги мастера и их поля

Мастер ДОЛЖЕН (MUST) состоять из трёх шагов.
Шаг 1 «Что нужно»: тип (можно сменить), срок, формат, одна строка пользы.
Шаг 2 «Параметры»: поля зависят от типа — куда предоставляется (для
справок с внешним адресатом обязательна), язык RU/EN, экземпляры (1–5),
способ получения (PDF в кабинете / забрать в деканате / почтой), комментарий,
вложения (только заявления: до 5 файлов, до 10 МБ). Данные студента
подставлены из профиля и не вводятся повторно.
Шаг 3 «Проверка»: сводка блоками с «Изменить», согласие «Данные верны»,
«Отправить».

#### Scenario: у мгновенной справки только электронная доставка

- WHEN студент выбрал «Справка об обучении» (мгновенная)
- THEN срок «Мгновенно», а в способах получения только «PDF в кабинете»

#### Scenario: обязательный адресат у справки для военкомата

- WHEN студент на шаге 2 у «Справки для отсрочки от армии» оставил
  «Куда предоставляется» пустым и нажал «Далее»
- THEN перехода на шаг 3 нет, под полем ошибка «Укажите, куда предоставляется документ»

#### Scenario: у заявления есть вложения и нет языка

- WHEN студент выбрал «Академический отпуск»
- THEN в шаге 2 есть блок вложений (до 5 файлов, до 10 МБ) и нет поля языка

### Requirement: Валидация на клиенте и на сервере

Одна чистая функция валидации ДОЛЖНА (MUST) вызываться в форме и в server
action; ошибки — у конкретных полей; сервер перепроверяет всё, включая файлы.

#### Scenario: сервер отвергает невалидную отправку

- WHEN server action получает заявку без согласия или с 6 вложениями
- THEN заявка не создаётся, ответ содержит ошибки полей (без записи в данные)

### Requirement: Черновик не теряется при закрытии

Мастер ДОЛЖЕН (MUST) перехватывать закрытие с черновиком (Esc, крестик, фон)
подтверждением «Выйти без сохранения?» с «Продолжить заполнение» и «Выйти».
Черновик дублируется в sessionStorage и восстанавливается при перезагрузке.

#### Scenario: подтверждение при закрытии с черновиком

- WHEN студент на шаге 2 заполнил поля и нажал Esc
- THEN виден диалог «Выйти без сохранения?»; «Продолжить заполнение» возвращает
  к шагу 2 с данными, «Выйти» закрывает мастер и стирает черновик

#### Scenario: пустой мастер закрывается без вопросов

- WHEN студент открывает мастер и сразу нажимает Esc
- THEN мастер закрывается сразу, без подтверждения

### Requirement: Прогресс и клавиатура

Мастер ДОЛЖЕН (MUST) показывать индикатор «Шаг N из 3» и Stepper с
aria-current="step"; все элементы управления — нативные (радио, чекбокс,
кнопки), мастер работает с клавиатуры.

#### Scenario: индикатор шага

- WHEN студент перешёл на шаг «Параметры»
- THEN виден текст «Шаг 2 из 3», у шага «Параметры» aria-current="step"

### Requirement: Успех заказа

После отправки мастер ДОЛЖЕН (MUST) показывать иллюстрацию «Справка готова»,
номер заявки, ожидаемую дату и «Следить за статусом». Для мгновенных — сразу
кнопка «Скачать PDF» (owner-scoped `/api/requests/<номер>/pdf`).

#### Scenario: мгновенная справка скачивается сразу

- WHEN студент отправил заказ «Справки об обучении»
- THEN экран успеха с «Справка готова», кнопкой «Скачать PDF» (загружается
  PDF), номером заявки и «Следить за статусом»; заявка создана со статусом
  «Выполнена»

#### Scenario: PDF недоступен чужому и не-готовой заявке

- WHEN другой студент (или гость) запрашивает PDF по чужому номеру, либо
  заявка ещё не выполнена
- THEN ответ — единый 404, попытка записана в AuditLog

### Requirement: Заявка из мастера читаема в потоке заявок

Заявка ДОЛЖНА (MUST) создаваться с названием документа и сводкой параметров
в первом событии; у мгновенной — статус COMPLETED и результат-заметка.

#### Scenario: сводка параметров в истории заявки

- WHEN студент открыл карточку заявки, созданной мастером
- THEN в истории есть событие подачи с параметрами (куда, язык, экземпляры,
  получение, комментарий, вложения)
