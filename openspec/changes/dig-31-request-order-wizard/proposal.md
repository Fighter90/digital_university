# Proposal: экран «Заказ справки или заявления» — мастер в 3 шага (DIG-31)

## Зачем

В аудированном ЛК заказ документа уводит во внешний «Центр сервиса» с отдельной
формой, а заявка после отправки появляется в списке под обезличенным названием.
По задаче мастер встраивается в кабинет: модальное окно на десктопе, полноэкранный
лист на мобильном (Figma «09 Мастер заказа»). Заявка создаётся прямо в потоке
заявок DIG-12 с понятным названием документа и человекочитаемой сводкой параметров
в истории заявки.

## Что

- **Точка входа**: `/requests?order=<serviceId>` — все «Заказать» каталога DIG-29
  уже ведут сюда; плюс CTA «Заказать справку или заявление» на странице «Мои
  заявки». Сотруднику CTA и мастер недоступны (раздел студенческий).
- **Шаг 1 «Что нужно»**: выбранный тип (можно сменить — радиосписок документов
  каталога), срок пилюлей, формат, одна строка «что это за документ» (польза).
- **Шаг 2 «Параметры»** (поля зависят от типа документа):
  - «Куда предоставляется» — для справок с внешним адресатом обязательна
    (военкомат, налоговая), для остальных скрыта или опциональна;
  - язык (RU/EN) — для справок;
  - количество экземпляров (1–5, потолок зависит от документа);
  - способ получения: PDF в кабинете / забрать в деканате / почтой —
    набор зависит от формата документа (мгновенные — только PDF);
  - комментарий (до 500 символов);
  - вложения — для заявлений: до 5 файлов, до 10 МБ каждый.
  - Данные студента подставлены из профиля (ФИО, группа, курс, зачётка) и
    повторно не вводятся — карточка «Данные студента» в шаге 2.
- **Шаг 3 «Проверка»**: сводка по блокам («Документ», «Параметры», «Данные
  студента»), «Изменить» у каждого блока, согласие «Данные верны»,
  кнопка «Отправить» (активна только с согласием).
- **Успех**: иллюстрация «Справка готова»; для мгновенных — сразу кнопка
  «Скачать PDF» (`/api/requests/<номер>/pdf`), номер заявки, ожидаемая дата,
  «Следить за статусом» (→ карточка заявки).
- **Валидация на клиенте и на сервере** — одна чистая функция
  `validateWizardInput` (`src/lib/request-wizard.ts`) вызывается и в форме, и
  в server action; понятные ошибки у полей (`role="alert"`, testid на поле).
- **Черновик**: попытка закрыть мастер с заполненными данными показывает
  подтверждение «Выйти без сохранения?» («Продолжить заполнение» / «Выйти»);
  черновик дублируется в sessionStorage и восстанавливается после
  случайной перезагрузки.
- **Прогресс**: «Шаг N из 3» + Stepper («Что нужно / Параметры / Проверка»),
  `aria-current="step"`; все элементы нативные — работа с клавиатуры.

## Правила и допущения (зафиксированы тестами)

- Реестр документов мастера — чистый модуль `src/lib/request-wizard.ts`,
  собранный из каталога DIG-29 (единый источник правды: `wizardDocs()` = все
  сервисы с `action: 'ORDER'`, ничего лишнего).
- «Мгновенная справка об обучении» по приёмке задачи: `cert-enrollment`
  «Справка об обучении» переводится в `eta: INSTANT` (электронная справка
  формируется сразу — это же основа «Справка PDF + QR» DIG-47). Тексты
  карточек каталога и e2e DIG-29 обновлены на «Мгновенно».
- Мгновенные документы: доставка только «PDF в кабинете», заявка создаётся
  сразу со статусом COMPLETED + результат-заметка (PDF доступен).
  Не-мгновенные: SUBMITTED, ожидаемая дата = сегодня + срок (1/3/5 дней).
- Вложения: валидируются на клиенте и сервере (количество, размер, имена),
  в прототипе сохраняются только имена файлов — они попадают в сводку
  первого события заявки; содержимое файлов нигде не хранится.
- PDF мгновенной справки: собственный писатель DIG-27 (`PdfWriter` +
  векторный шрифт), код проверки как у выписки; сканируемый QR — DIG-47.
  Скачивание owner-scoped: чужой номер и несуществующий отвечают одинаково
  (единый 404, попытка — в AuditLog).
- Порт данных `appendRequestByStudent` расширен опциональными
  `status`/`resultNote` (по умолчанию SUBMITTED/null) — безbreaking для
  существующих вызовов (DIG-28).
- bodySizeLimit server actions поднят до 12 МБ (вложения ≤ 10 МБ + накладные
  multipart), с комментарием; лимиты всё равно проверяет валидатор.

## Отклонения от текста задачи (обоснованные)

- «Полноэкранный лист на мобильном» реализован одним адаптивным диалогом
  (base-ui): `< 640 px` — fullscreen-лист, `≥ 640 px` — модальное окно.
- «Вложения» — только для документов-заявлений (сканы документов) и скрыты
  для справок: поля зависят от типа, вложения справке не нужны.
- «Изменить» у блока «Данные студента» ведёт в «Профиль» — поля профиля
  ведёт деканат (DIG-19), переопределять их в мастере нельзя.
- Удаление вложений в прототипе — «убрать все» (поштучное удаление из
  FileList требует DataTransfer-хаков без пользы для приёмки).

## Вне скоупа

- Сканируемый QR и страница проверки справок — DIG-47.
- Сортировка и дизайн списка «Мои заявки» — DIG-32 (фрейм 10).
- Хранение содержимого вложений (blob-хранилище) — прототип хранит имена.
- Prisma-адаптер: прототип на memory-адаптере DIG-12, сигнатуры порта
  переносятся 1:1 (общий трек DIG-10/50).
